What a Christmas QR code actually does

A QR code is not the gift, the ticket, or the donation. It is the doorway to it: the person scans, their phone opens a page, and the page does the work — plays a video greeting, sells a gift card, takes a donation. The code is printed once and cannot be un-printed; the page behind it can be fixed, updated, or replaced. So the most important decision in this guide is which kind of code you print.

Static vs. dynamic: the decision everything else depends on

A static code carries its content inside the pattern itself. What you print is what it will always do. A dynamic code carries a short redirect: the printed pattern stays the same, but the destination is stored by FreeQrly, so you can change where it points after printing — and see how many times it was scanned.

The rule of thumb: if reprinting it would be costly or troublesome, make it dynamic. A poster run of 500 copies or a church noticeboard sign is expensive to reprint. A greeting card for one person is not.

One caution about tracking: scan statistics only exist for dynamic codes. If you want to know which poster, stall, or card actually got scanned, that placement needs its own dynamic code. A single shared code across five posters tells you the total, not which poster worked.

How the customer journey works

Journey A — Gift-card purchase

Figure 1 shows the five steps: the shopper sees the code on a gift-card display, poster, or shelf edge → scans it with their phone camera, no app needed → chooses an amount and a message and pays on the page → receives the gift card by email or as a printable card → the recipient redeems it in store or online.

The lesson is in step two: the page the code opens must be the gift-card page, not your homepage. Every extra tap loses shoppers standing in your shop, phone in hand, ready to buy.

Journey B — Event ticket and donation

Figure 2 shows the five steps: the guest sees the code on a poster, church noticeboard, market stall, or social post → scans it to open the event page or donation form → books a ticket, RSVPs, or donates → gets a ticket or receipt by email, and a calendar invite is added → the organizer follows up with a thank-you, and for dynamic codes the scan counts show which posters worked.

The lesson is in step four: a donation or booking that ends in silence feels broken, even when the payment went through. Confirm the action on screen and by email. For events, the Event code type adds the date, time, and place straight to the guest's calendar app in one scan.

Gift cards: the highest-value Christmas code

Gift cards are where a QR code most directly turns into money — and where a wrong choice costs the most.

  1. Use a dynamic code on the display. Gift-card amounts sell out and designs change; a dynamic code lets you change the destination without reprinting the display stand. The free tier allows 20 dynamic codes, which covers a display, a poster, and a social post with room to spare; Pro ($9/month or $90/year) only removes that 20-code limit. During the current limited-time offer, free dynamic codes are unlimited; after the offer ends, the free plan includes 20 dynamic codes.
  2. Print the amount range on the display, not just the code. "Gift cards from $10" next to the code sets the expectation before the scan. A bare code with no context gets fewer scans, because shoppers do not know what they are scanning for.
  3. Test the whole purchase on a real phone. Scan the printed display, buy the cheapest card yourself, and check the email the recipient gets. If any step asks for an app download or a login the buyer does not have, fix the page.

Donations and fundraisers: trust is the product

A donation code asks a stranger to send money to a page they have never seen. Everything about the setup should reduce doubt:

  • Link to a page that names the cause, the organization, and where the money goes — not to a bare payment form. It should look like the organization that printed it: same name, same logo, same cause.
  • Use a dynamic code. Fundraisers change through December: a matched-giving window opens, a target is reached, a new total is posted. A dynamic code lets the same printed poster follow the campaign instead of freezing it at the November wording.
  • Put the code where people stand still. A donation code on a poster people walk past gets glanced at; the same code on a collection table, a programme, or a stall counter — where people are already stopped and holding their phones — gets scanned. Add a short line next to it: "Scan to donate" beats a bare code, because it says what happens next. And if the campaign page shows a running total or thank-you message, donors who scan twice see their gift mattered.

Greeting cards, gift tags, and advent calendars

These are the personal uses, and they are where static codes shine — the content is fixed, personal, and meant to last.

  • Video greeting cards. Upload the greeting somewhere with a shareable link — an unlisted YouTube video works well — make a QR code from the link, and print it inside the card. One scan and it plays. Because the code is static, it works next Christmas too, as long as the video stays online.
  • Photo albums, playlists, and invitations. Link the code to a shared album or the evening's playlist — guests open it in one tap, no app to install. The Event code type carries the title, time, and place, so one scan drops the party into your guests' calendar apps.
  • A different code on every gift tag. Make them all at once with Batch mode: one link per line, one code per tag, downloaded as a ZIP. Batch is static-only, with a maximum of 50 codes per batch — paste one per line, or upload a CSV or XLSX file.
  • An advent calendar with 24 doors. Print a code behind each door — a photo, a clue, a tiny video. Twenty-four codes fit comfortably inside one Batch run of up to 50. Keep each door's destination short and fixed: a clue that changes after printing is a door that disappoints a child.
  • A thank-you note that outlives the tree. Print the thank-you code with the gifts. A static code keeps working as long as the page behind it stays online; a dynamic code lets you repoint it after the holidays — to a January sale or next year's event — without reprinting the note.

Planning timeline: when to print

Figure 4 shows the four-stage timeline. The order matters more than the dates: decide, test, print, then monitor.

  • Early November — decide the codes and destinations. List every place a code will appear and what each one should open, and decide static or dynamic for each one using Table 2. This is the cheapest moment to change your mind.
  • Mid-November — test prints and first scan checks. Print one copy of each code at real size and scan it with two different phones, in the lighting where it will actually be used. Check the page it opens, not just that it scans.
  • Late November — print and place everything. Print at 1024 px export or higher for anything larger than a gift tag, and 2048 px for posters. Place codes where people stand still and where the light is good — not behind glass that glares, and not at ankle height.
  • December — monitor, repoint, thank. Check dynamic-code scan counts weekly: a poster with no scans may be badly placed, not unpopular. Repoint dynamic codes when details change instead of reprinting.

When details change mid-season

Christmas plans change: an event moves, a product sells out, a donation target is reached, a market stall moves pitches. What to do depends on the code type:

  • Dynamic code: change the destination in your FreeQrly dashboard. The printed code does not change, and every poster, card, and stall sign follows immediately.
  • Static code, and the page behind it is yours: update the page. A static code pointing at your event page still works if you edit the page itself — new time, new details, same code.
  • Static code, and the page behind it is not yours: you cannot fix it. A static code pointing at a deleted video or a sold-out third-party ticket page is a dead code — which is why anything outside your control should be dynamic.

Good to know

How do I put a video inside a Christmas card?

Upload the video somewhere with a shareable link — an unlisted YouTube video works well — make a QR code from the link, and print it inside the card. One scan and it plays. Use a static code: the greeting is fixed, and it will still work next Christmas as long as the video stays online.

Can a code add the party to my guests’ calendars?

Yes. The Event type carries the title, time, and place; one scan adds the party to their calendar app. Put it on the invitation itself, not just in the email — the paper invitation is the one people keep on the fridge.

I need a different code on every gift tag. How?

Use Batch mode in the generator: one link per line, one code per tag, all downloaded as a ZIP. Batch is static-only, with a maximum of 50 codes per batch, and you can also upload a CSV or XLSX file instead of pasting links.

Can I see how many people scanned my Christmas poster?

Yes, with a dynamic code: scan statistics appear in your FreeQrly dashboard. Static codes are made entirely in your browser with nothing uploaded, so there is nothing to count. If tracking matters, give each poster its own dynamic code — a shared code only shows the total.
