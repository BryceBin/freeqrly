Pourquoi mon QR code est-il flou ?

Un QR code flou est presque toujours un problème de résolution : trop peu de pixels étirés sur trop d'espace. La solution : exporter plus grand — ou en SVG.

17 octobre 2026 · Dernière mise à jour : 3 novembre 2026 · 15 min de lecture

Un QR code flou est presque toujours un problème de résolution : trop peu de pixels étirés sur trop d'espace. Le correctif est d'exporter plus grand — ou en SVG. Si le code semblait net à l'écran et s'est transformé en bouillie sur papier, l'image n'avait pas assez de pixels pour la taille à laquelle elle a été imprimée. Un QR code est une grille de petits carrés appelés modules ; quand il n'y a pas assez de pixels, leurs bords se brouillent les uns dans les autres, les téléphones ne trouvent plus la grille, et les scans échouent. Commencez par l'export, pas par un nouveau design : régénérez en plus haute résolution ou en fichier vectoriel, réimprimez un exemplaire à la vraie taille, et scannez-le à la vraie distance de lecture avant d'imprimer le lot.

Cette réponse couvre la plupart des cas, mais le flou a plus d'une cause, chacune avec un correctif différent : un petit export, la compression JPEG, l'étirement, l'imprimante ou le papier, ou une copie d'une copie. Les sections ci-dessous séparent ces causes, donnent un tableau de chiffres pour l'imprimeur, parcourent le correctif dans l'ordre, et traitent les codes qui semblent nets mais ne scannent toujours pas — ceux-là relèvent de pourquoi votre QR code ne scanne pas.

Ce que le flou fait réellement à un code

Un appareil photo de téléphone ne lit pas un QR code comme une personne lit une image. Il cherche les trois grands motifs carrés de repérage dans les coins, en déduit la grille, puis décide, module par module, si chaque petit carré est foncé ou clair. Le flou attaque exactement cette décision : quand des modules voisins bavent les uns dans les autres, l'appareil photo voit du gris là où il lui faut du noir ou du blanc, et il commence à deviner. Un peu de devinette est survivable, parce que les QR codes portent une correction d'erreur intégrée — des données supplémentaires qui permettent à un lecteur de reconstruire les mots de code revenus faux ou illisibles. Cette protection se mesure en mots de code, pas en surface visible : les quatre niveaux d'ISO/IEC 18004 restaurent environ 7 % des mots de code au niveau L, 15 % en M, 25 % en Q, et 30 % en H. Une tache sur un motif de repérage, ou un flou étalé sur tout le symbole, peut vaincre un lecteur bien avant que n'importe quel pourcentage net suggère qu'il devrait survivre. Traitez la correction d'erreur comme un filet de sécurité, jamais comme une permission d'imprimer un code flou.

La densité aggrave le flou. Un lien court produit une grille aérée avec de grands modules ; un lien long, une carte de contact complète, ou un code Wi-Fi avec un long mot de passe produit une grille plus dense avec des modules plus petits, et les modules plus petits se brouillent plus tôt. C'est pourquoi le même export peut sembler correct pour une URL courte et échouer pour un code chargé en données à la même taille d'impression. Si un code est à la fois dense et imprimé petit, raccourcissez la destination quand vous pouvez, imprimez plus grand, ou les deux. Un code dynamique aide différemment : le motif imprimé encode un lien court que vous pouvez rediriger plus tard, donc la grille reste aérée même si la destination finale est longue. Pour une destination qui ne changera jamais, un code statique est plus simple : gratuit, pas de compte, pas de filigrane, et il n'expire pas.

Les chiffres : taille d'impression, pixels et format

Les imprimeurs parlent de résolution en points ou pixels par pouce. Pour l'impression vue de près, 300 pixels par pouce à la taille finale d'impression est la base professionnelle largement utilisée pour un rendu net. Le tableau ci-dessous transforme cette base en nombres de pixels : largeur d'impression en pouces multipliée par 300. Un code de 2 cm fait environ 0,8 pouce de large, il lui faut donc environ 240 pixels à 300 pixels par pouce — et c'est le strict minimum, pas une marge confortable. Exportez toujours plus grand que le minimum et laissez le graphiste réduire, parce que réduire préserve la netteté alors qu'agrandir ne fait qu'élargir le flou.

Deux règles empiriques se cachent derrière ce tableau. D'abord, la taille d'impression en centimètres, multipliée par environ 100, donne une cible rapide en pixels — un code de 5 cm veut environ 500 pixels au minimum, un code de 10 cm environ 1 000. Ensuite, la règle empirique du 1:10 pour la distance du guide des tailles d'impression : la largeur du code doit faire au moins un dixième de la distance de scan, donc un code scanné depuis 50 cm doit faire au moins 5 cm de large, et une affiche scannée depuis 5 mètres exige un code de 50 cm. Un code d'affiche vu à des mètres de distance peut tolérer une résolution effective plus faible qu'une carte tenue en main, mais il lui faut quand même assez de pixels pour sa taille — et seul un fichier vectoriel vous donne cela sans plafond.

Les 5 causes habituelles, en détail

1. Export basse résolution

C'est la cause la plus fréquente, et la plus indulgente à corriger. Un PNG de 512 px semble correct à 2 cm de large ; soufflé en affiche de 20 cm, chaque module devient une tache, parce que les mêmes 512 pixels couvrent maintenant dix fois la surface. L'écran cache le problème — un affichage montre le code petit, donc les pixels semblent serrés — tandis que le papier le montre à vraie taille. Le correctif est à la source : réexportez à 1024 px pour les cartes et dépliants, 2048 px pour les affiches, ou SVG dès que l'imprimeur l'accepte. Agrandir le petit fichier dans un éditeur n'ajoute pas de détail ; cela ne fait qu'agrandir le flou existant. Si l'export d'origine a disparu, régénérez depuis la même destination plutôt que d'étirer le fichier que vous avez.

2. Compression JPEG

Le JPEG est fait pour les photographies, et il fonctionne en écartant le détail que l'œil risque le moins de remarquer dans une photo. Ce compromis est mauvais pour un QR code, qui n'est que bords nets et zones plates — exactement les traits que le JPEG brouille. Un code enregistré en JPEG basse qualité peut échouer même à petite taille, et les dégâts empirent chaque fois que le fichier est réenregistré en JPEG. Le PNG utilise une compression sans perte, préservant chaque pixel exactement, et le SVG n'a pas de pixels à perdre. La règle est simple : PNG ou SVG seulement. Si un graphiste, une application de conversation ou une plateforme sociale vous rend une version JPEG, traitez-la comme un aperçu, pas comme un original d'impression, et remplacez-la par le PNG ou le SVG d'origine avant d'imprimer.

3. Étirement

Tirer un coin déforme la grille : les carrés deviennent des rectangles, l'espacement des modules change de façon inégale, et les lecteurs abandonnent. Cela arrive le plus souvent dans les diaporamas, les traitements de texte et les outils de mise en page, où une image est tirée pour combler un vide. Redimensionnez toujours proportionnellement — maintenez Maj, ou utilisez l'icône de cadenas, pour que largeur et hauteur changent ensemble et que les carrés restent carrés. Un code étiré puis ramené n'est pas automatiquement carré à nouveau, parce que l'arrondi dans l'outil de mise en page peut le laisser légèrement décalé. Dans le doute, supprimez l'image placée et placez un nouvel export à la taille prévue.

4. Mauvaise impression : imprimante, encre et papier

Les imprimantes basse résolution, le débordement d'encre sur papier rugueux ou absorbant, et les reflets du brillant adoucissent tous les bords. Un jet d'encre sur papier non couché et absorbant laisse l'encre se répandre dans les fibres, donc les fins écarts blancs entre modules se remplissent et le code semble gras et boueux. Une imprimante laser sur papier lisse ou couché tient les bords bien mieux, c'est pourquoi le papier mat et une imprimante laser battent un jet d'encre sur une serviette. Le pelliculage brillant est différent : le papier peut rester net tout en renvoyant des reflets vers l'appareil photo — inclinez le tirage sous la lumière pour distinguer les reflets du flou.

5. Copie d'une copie

Capturer un code depuis un message, puis capturer cette capture, perd de la résolution à chaque fois. Les applications de messagerie recompressent et réduisent aussi les images, donc un code transféré par conversation peut arriver bien plus petit et plus flou que l'export d'origine. Photographier un code imprimé pour le réutiliser ajoute une distorsion de perspective, une lumière inégale, et le flou de l'objectif par-dessus le tirage d'origine. Revenez toujours à l'export d'origine, ou régénérez depuis la même destination. Si la destination est un code dynamique, générez un code tout neuf pour le même lien court — pas besoin d'ancien fichier.

Comment corriger, pas à pas

  1. Retrouvez le fichier d'origine. Si vous n'avez qu'un JPEG, une capture d'écran, ou une image transférée par conversation, arrêtez-vous et régénérez — aucune retouche ne restaure un détail que la compression a déjà jeté.
  2. Exportez à la bonne taille. PNG à 1024 px pour les cartes et dépliants, 2048 px pour les affiches, SVG dès que l'imprimeur ou le graphiste l'accepte. Au-delà d'environ 20 cm, le SVG est le seul format qui garde les bords exacts sans un fichier énorme.
  3. Utilisez PNG ou SVG, jamais JPEG. PNG pour les écrans et l'impression de bureau, SVG pour l'impression professionnelle. Si un outil exige le JPEG, utilisez son réglage de qualité la plus haute pour un aperçu écran seulement, jamais comme original d'impression.
  4. Gardez les proportions en redimensionnant. Maintenez Maj ou l'icône de cadenas pour que les carrés restent carrés. Placez l'image à la taille finale, plutôt que de la placer petite et de l'étirer ensuite.
  5. Gardez le code foncé sur clair, avec une marge nette. Flou et faible contraste se cumulent : un code gris sur fond pâle qui est aussi flou échoue plus tôt que l'une ou l'autre faute seule. Gardez une marge blanche d'au moins 4 modules de large de chaque côté, comme spécifié dans ISO/IEC 18004, et gardez texte, logos et bordures décoratives hors de cette marge.
  6. Adaptez papier et imprimante au travail. Papier lisse ou couché et imprimante laser pour les petits codes ; fini mat là où les reflets sont un risque ; taille plus grande et correction d'erreur plus élevée pour les surfaces rugueuses ou texturées.
  7. Testez le vrai tirage au scan. Imprimez un exemplaire à la taille finale, reculez à la vraie distance de lecture, et scannez-le dans la vraie lumière. Un scan du premier coup veut dire que le lot est sûr. S'il hésite, corrigez l'export ou la taille maintenant — un tirage de codes flous ne peut pas être sauvé après coup.

Scénarios : là où le flou mord le plus fort

Dépliants, menus et chevalets de table

Ceux-ci sont scannés à bout de bras, souvent dans des pièces sombres, ils exigent donc à la fois netteté et taille : au moins 3 cm sur un dépliant ou un menu, 4–5 cm sur un chevalet de table en règle générale. Les menus ajoutent le risque du pelliculage : le brillant sous les plafonniers peut éblouir, tandis que le pelliculage mat garde le code lisible et s'essuie proprement. Pour un menu qui change, liez vers une page que vous contrôlez plutôt qu'une capture d'écran, pour que le tirage ne devienne jamais périmé — et un code dynamique permet de changer cette destination après impression, avec des statistiques de scan pour montrer quelles tables scannent réellement.

Affiches et signalétique

Les affiches échouent différemment : l'export est généralement le problème, pas l'imprimante. Un fichier de 512 px qui semblait correct à l'écran devient visiblement flou à 20 cm ou 50 cm, et aucune imprimante ne peut inventer les pixels manquants. Utilisez le SVG, appliquez la règle empirique du 1:10 pour la distance, et vérifiez le panneau de code en taille réelle avant le tirage.

Emballages et étiquettes

Les petites étiquettes combinent petite taille, données denses, et surfaces courbes ou texturées. Gardez le code à 2 cm ou plus en règle générale, évitez de l'enrouler autour d'une courbe serrée où les modules de bord s'étirent, et testez sur le contenant réel — un code qui scanne à plat peut échouer sur une bouteille. Si le matériau est rugueux ou l'impression grossière, imprimez plus grand et plus simple : un lien court garde la grille aérée, y compris un lien court derrière un code dynamique.

Comparaison honnête : ce qui corrige le flou, et ce qui ne le corrige pas

Toutes les astuces d'accentuation ne fonctionnent pas, et certains conseils populaires gaspillent un tirage. Agrandir un petit fichier — dans un éditeur, avec un outil d'agrandissement, ou en exportant la même petite image plus grande — n'ajoute pas de détail ; cela interpole entre les pixels que vous avez déjà, donc les bords restent flous, seulement plus grands. Un filtre d'accentuation peut rendre les bords plus nets à l'œil tout en ajoutant des halos qui perturbent un appareil photo, donc un code filtré peut scanner plus mal. Convertir un JPEG en PNG n'annule pas non plus les dégâts du JPEG : le format change, mais les pixels brouillés restent brouillés. La seule réparation fiable est un nouvel export depuis les données d'origine en plus haute résolution, ou en SVG.

Le choix de format a ses propres compromis. Le SVG est le meilleur choix pour l'impression, mais certains outils de bureau, applications anciennes et plateformes sociales ne l'acceptent pas — dans ces cas un PNG haute résolution est le bon repli, pas une raison de retomber sur le JPEG. Le PDF peut être un bon support pour l'impression parce qu'il peut contenir le code vectoriel, mais seulement si le code dans le PDF est réellement vectoriel ; un PDF avec un petit JPEG collé dedans n'est qu'un JPEG avec un emballage plus chic, vérifiez donc ce qu'il y a dedans avant de faire confiance à l'extension du fichier.

Enfin, la netteté est nécessaire mais pas suffisante. Un code parfaitement net peut encore échouer s'il est trop petit pour sa distance, si le contraste est faible, si la zone de silence est encombrée, si un logo recouvre trop le centre, ou si la destination elle-même est morte. Ce sont des questions de diagnostic, traitées dans l'ordre dans le guide complet de dépannage. Si votre réimpression est nette et ne scanne toujours pas, parcourez le guide de dépannage avant de réimprimer à nouveau — une deuxième réimpression n'aide que si elle change la chose qui est réellement fausse.

Bon à savoir

Pourquoi mon QR code semble flou mais se scanne quand même ?

Les téléphones pardonnent — la correction d'erreur reconstruit les mots de code revenus faux ou illisibles. Mais un code qui scanne dans un bureau lumineux peut échouer dans une lumière faible ou à bout de bras. Net, c'est sûr ; à peine scannable, non.

Quelle résolution pour une affiche ?

Le SVG est le meilleur choix, parce qu'il s'étend sans limite. Si l'imprimeur a besoin d'un fichier tramé, utilisez le PNG à 2048 px ; une affiche à 20 cm exige environ 2 360 px à 300 pixels par pouce, donc un export de 512 px semblera flou à cette taille.

PNG ou SVG pour l'impression ?

SVG dès que l'imprimeur ou le graphiste l'accepte — il s'étend à l'infini sans aucun flou. Le PNG à 1024 px pour les cartes et dépliants, ou 2048 px pour les affiches, est le repli pour l'impression de bureau et les applications qui n'acceptent pas le SVG.

Puis-je corriger un code imprimé flou sans réimprimer ?

Non. Le flou est cuit dans l'image imprimée. Réimprimez depuis un export en plus haute résolution (ou SVG). Modifier un code dynamique n'aidera pas — le motif sur papier est ce qu'il est, même si un code dynamique permet de changer la destination derrière un nouveau tirage.

Pourquoi le même export semble-t-il net à l'écran mais flou à l'impression ?

Un écran montre le code petit, donc ses pixels semblent serrés. Le papier montre le code à sa vraie taille, donc le même nombre de pixels étalé sur des centimètres révèle le flou. Vérifiez l'export par rapport à la taille d'impression avant d'envoyer à l'impression.

Un agrandissement ou un filtre d'accentuation corrigera-t-il un code flou ?

Non. L'agrandissement interpole entre les pixels que vous avez déjà, donc les bords restent flous, seulement plus grands. Un filtre d'accentuation peut ajouter des halos qui perturbent un appareil photo, et convertir un JPEG en PNG n'annule pas les dégâts du JPEG. La seule réparation fiable est un nouvel export depuis les données d'origine en plus haute résolution, ou en SVG.
