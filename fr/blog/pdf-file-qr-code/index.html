Notes de terrain

Un QR code PDF n'est bon que le fichier derrière lui

Un QR code sur une affiche, un panneau de menu, un document distribué ou un encart produit peut ouvrir un PDF complet en un scan : un menu, un catalogue, une liste de prix, un manuel ou une brochure. Le scan lui-même est la partie facile. La partie difficile est tout ce qui se trouve derrière : où vit le fichier, quelle est sa taille, s'il s'ouvre proprement sur un téléphone, et ce qui se passe quand le document a besoin d'un nouveau prix, d'une page corrigée ou d'une mise à jour saisonnière. Prenez ces quatre décisions correctement et le code reste utile pendant tout un tirage. Prenez-les mal et vous avez imprimé un raccourci vers un fichier lent, cassé ou obsolète.

Commencez par demander à quoi sert le PDF, car cette réponse décide de presque tout le reste. Un menu de restaurant doit s'ouvrir vite, bien se lire sur un petit écran, et changer quand les plats ou les prix changent. Un manuel de produit doit rester exact pendant toute la vie du produit, et un lecteur peut y revenir des mois après l'achat. Une liste de prix a besoin d'une seule version digne de confiance, pour que personne ne commande aux prix de la saison dernière. Un document de conférence n'a peut-être besoin de vivre qu'un week-end, mais il doit quand même s'ouvrir sans mur de connexion ni étape de téléchargement déroutante. Écrivez cet objectif en une phrase avant de générer le code, et testez le résultat final par rapport à lui : ce scan donne-t-il au lecteur le bon document, rapidement, sur un téléphone, aujourd'hui et après la prochaine mise à jour ?

Le premier choix pratique est entre encoder le PDF lui-même et renvoyer vers un PDF hébergé. Un QR code ne peut pas contenir confortablement un fichier PDF entier. Les codes sont conçus pour de courtes charges comme les liens et les fiches de contact, et une longue charge rend le motif dense, lent à scanner et fragile à la taille d'impression. L'approche standard est donc un code de lien : le code contient une courte adresse web, et cette adresse ouvre le PDF. C'est aussi ce qui rend le code maintenable, car l'adresse peut rester la même tandis que le fichier derrière change, à condition d'utiliser un code dynamique. Un code statique fige l'adresse exacte avec laquelle il a été imprimé, donc déplacer le fichier vers une nouvelle adresse casse chaque exemplaire imprimé. Un code dynamique pointe vers une destination que vous pouvez mettre à jour, ce qui fait la différence entre corriger une liste de prix dans un après-midi et réimprimer tout un lot d'affiches. Pour la comparaison plus large, voir codes statiques contre dynamiques, et pour le processus de modification, voir comment modifier un QR code après impression.

Où héberger le PDF

Hébergez le PDF à une adresse stable et publique que vous contrôlez, et gardez l'adresse courte. Votre propre site web, une page de destination dédiée, ou un hébergeur de fichiers que vous gérez sont tous viables, à condition que le lien ait peu de chances de bouger, d'expirer ou d'acquérir une exigence de connexion plus tard. Évitez les adresses qui dépendent d'un lien de partage temporaire, d'un dossier de drive personnel aux permissions changeantes, ou d'un raccourcisseur que vous ne contrôlez pas, car n'importe lequel peut casser le code imprimé sans avertissement. Utilisez un nom de fichier propre et un dossier stable, par exemple un dossier documents ou menus sur votre propre domaine, et évitez les espaces, les caractères spéciaux et les numéros de version dans l'adresse publique si vous prévoyez de remplacer le fichier sur place. Un numéro de version dans l'adresse impose une nouvelle adresse à chaque mise à jour, ce qui annule l'intérêt d'un code stable.

Vérifiez comment le PDF s'ouvre, pas seulement si le lien fonctionne. Sur la plupart des téléphones, un lien PDF s'ouvre dans le navigateur ou dans un lecteur, et le lecteur doit voir la première page sans étape de téléchargement supplémentaire, sans invite de connexion, ni avertissement de fichier dangereux. Testez le lien sur les deux grandes plateformes de téléphones, sur une connexion mobile plutôt que seulement sur le Wi-Fi du bureau, et depuis le code imprimé plutôt que seulement depuis une adresse tapée. Si l'hébergeur impose un téléchargement au lieu d'un aperçu, un lecteur sur une connexion lente peut abandonner le scan avant la fin du fichier. Si l'hébergeur ajoute du suivi, de la publicité ou une page interstitielle, le scan semble moins digne de confiance et le lecteur peut ne jamais atteindre le document. L'hébergeur fait partie de l'expérience utilisateur, pas seulement un choix de stockage.

Gardez une seule version canonique du document. Quand un menu, un catalogue ou une liste de prix existe à plusieurs endroits, lecteurs et personnel perdent vite de vue quelle copie est actuelle. Nommez le fichier clairement dans vos propres archives, gardez l'adresse publique inchangée quand vous remplacez le fichier, et notez la date d'effet dans le PDF lui-même, sur la première page ou en pied de page, pour qu'un lecteur qui l'imprime ou le transfère puisse dire s'il est actuel. Si une ancienne version doit rester disponible, donnez-lui une adresse différente et renvoyez vers elle depuis le nouveau document, plutôt que de laisser deux versions concurrentes partager le même code. Pour les menus en particulier, un PDF court et ciblé qui s'ouvre sur le menu actuel servira mieux les lecteurs qu'une grande brochure générale qui enterre le menu plusieurs pages plus loin.

Taille du fichier : rendez-le rapide avant de le rendre beau

La taille du fichier est la raison la plus fréquente de déception d'un code PDF. Un PDF construit à partir de photographies haute résolution, de scans non compressés ou d'une mise en page complète d'impression peut facilement atteindre plusieurs mégaoctets, et cela compte sur un téléphone. Les gros fichiers mettent plus de temps à télécharger, consomment plus de données mobiles, et peuvent se bloquer sur un signal faible dans un restaurant, une salle ou un magasin. La compression existe précisément pour cet arbitrage : elle réduit le fichier tout en essayant de préserver la qualité visuelle, et le bon réglage dépend du document. Les documents riches en texte se compressent généralement bien sans perte visible, tandis que les documents riches en images imposent un choix entre un fichier plus petit et des photographies plus nettes. Les conseils mobiles d'Adobe le décrivent directement, offrant des compressions haute, moyenne et basse, la compression basse préservant le mieux la qualité et la compression haute donnant le fichier le plus petit au prix d'une certaine qualité.

Avant de compresser, réduisez le fichier à la source. Supprimez les pages dont le lecteur n'a pas besoin, recadrez les photographies à la taille à laquelle elles seront réellement affichées, et évitez d'intégrer plusieurs fois la même grande image. Un menu n'a pas besoin de photographies en résolution d'impression sur chaque page quand il sera lu sur un écran de téléphone, et une liste de prix n'a pas besoin d'images scannées de pages qui pourraient être du vrai texte. Le vrai texte a un second avantage au-delà de la taille : il peut être recherché, sélectionné et lu par des outils d'accessibilité, tandis qu'une image scannée de texte ne le peut pas, sauf si le scan a été traité pour reconnaître le texte. Après compression, ouvrez le résultat sur un téléphone et vérifiez les pages qui comptent le plus, surtout les petits caractères, les prix et les tableaux. Si un prix, une note d'allergène ou une note de bas de page devient difficile à lire, la compression est allée trop loin, et un fichier légèrement plus grand est le meilleur choix.

Fixez une discipline de taille pratique pour votre propre équipe, même si vous ne publiez pas de chiffre aux lecteurs. En règle de travail, visez un fichier qui s'ouvre rapidement sur une connexion mobile et semble instantané en Wi-Fi, et testez-le sur un vrai téléphone plutôt que de juger par la seule taille du fichier. Certains services d'e-mail et de téléversement imposent leurs propres limites, ce qui rappelle utilement que les gros fichiers créent des frictions partout : un guide de compression mobile note que Gmail plafonne les pièces jointes à 25 mégaoctets, tandis que beaucoup de portails d'emploi limitent les téléversements à 5 mégaoctets et que certains formulaires exigent des fichiers de moins de 2 mégaoctets. Ce sont les limites d'autres services, pas une règle pour votre PDF, mais elles illustrent le point qu'un fichier difficile à envoyer est aussi difficile à ouvrir depuis un scan. Si votre PDF reste gros après compression, divisez-le : un menu court et un catalogue détaillé séparé, liés l'un à l'autre, s'ouvriront tous deux plus vite qu'un seul fichier combiné.

Remplacez le fichier sans réimprimer le code

Remplacer un PDF derrière un code dynamique est un petit processus, mais il exige une checklist pour ne pas créer d'erreur silencieuse. D'abord, préparez le nouveau fichier et vérifiez-le sur un téléphone, y compris les pages qui ont changé et celles qui n'ont pas changé. Ensuite, remplacez le fichier à la même adresse publique, ou mettez à jour la destination dynamique vers la nouvelle adresse, et gardez l'ancienne adresse active jusqu'à ce que vous soyez sûr que la nouvelle est correcte. Troisièmement, scannez un exemplaire imprimé du code, pas seulement un aperçu à l'écran, et confirmez qu'il ouvre la nouvelle version. Quatrièmement, vérifiez la date d'effet dans le document et toute référence imprimée à l'ancienne version, comme un pied de page indiquant que les prix s'appliquent jusqu'à une certaine date. Enfin, dites aux gens qui distribuent ou affichent le code, comme le personnel de salle, que le document a changé, pour que personne ne continue à diriger les lecteurs vers une copie en cache ou imprimée de l'ancien fichier.

Attention à la mise en cache. Le téléphone ou le navigateur d'un lecteur peut conserver une ancienne copie du PDF pendant un moment après son remplacement, et le téléphone d'un membre du personnel peut faire de même. C'est normal, mais cela signifie que votre test doit inclure un nouveau scan après avoir vidé le cache, ou un scan sur un téléphone qui n'a jamais ouvert l'ancien fichier. Si vous remplacez un fichier fréquemment, comme un menu hebdomadaire, envisagez d'ajouter la date d'effet sur la première page en gros caractères, pour qu'un lecteur qui voit une copie en cache puisse repérer qu'elle est ancienne. Si un changement est urgent, comme une correction de prix ou une note de sécurité, ne comptez pas sur le seul code : mettez à jour toute copie imprimée, tout panneau ou tout script du personnel qui répète la même information, et confirmez la correction avec les personnes les plus susceptibles d'agir dessus.

Il y a des limites à ce qu'un code dynamique peut corriger. Il peut changer la destination, mais il ne peut pas corriger un PDF jamais conçu pour un téléphone, un fichier trop gros pour s'ouvrir sur un signal faible, ou un document qui enterre l'information clé à la page douze. Il ne peut pas non plus corriger un hébergeur cassé, un lien de partage expiré, ou un changement de permissions qui bloque les lecteurs. Ce sont des problèmes d'hébergement et de document, et ils doivent être résolus à la source. Une bonne routine est de rescanner vos codes PDF imprimés selon un rythme qui correspond à la fréquence de changement du document : chaque semaine pour un menu changeant, chaque mois pour une liste de prix, et avant chaque événement pour un document de conférence. Un code qui fonctionnait au moment de l'impression n'est pas garanti de fonctionner pour toujours, et une courte vérification régulière coûte bien moins cher que de découvrir un code cassé par un client.

Concevez le PDF pour le téléphone qui l'ouvrira

Un PDF fait pour l'impression ne se lit pas automatiquement bien sur un téléphone. Les tableaux larges, les minuscules notes de bas de page et les mises en page denses en plusieurs colonnes obligent le lecteur à pincer, zoomer et défiler latéralement, ce qui est une mauvaise expérience après un scan rapide. Si le PDF sera surtout lu sur des téléphones, fixez des tailles de caractères généreuses, gardez les tableaux étroits, et mettez les informations les plus importantes en premier. Un menu doit commencer par les plats et les prix, pas par une page d'histoire. Une liste de prix doit commencer par les prix actuels et la date à partir de laquelle ils s'appliquent. Un manuel doit commencer par les notes de sécurité et les étapes de démarrage rapide, avec le matériel de référence détaillé plus loin. Un PDF court et adapté au téléphone sera scanné, lu et suivi plus souvent qu'un PDF long et parfait pour l'impression que personne ne finit.

Gardez le code lui-même lisible, car un code PDF est souvent imprimé avec d'autres informations. Utilisez un lien court derrière le code pour que le motif reste clairsemé et les modules grands, gardez la zone de silence dégagée, et imprimez le code à une taille adaptée à la distance de scan, en suivant le guide des tailles d'impression. Si le code se trouve sur un panneau de menu, une affiche ou un document distribué, ajoutez une étiquette qui dit ce que le scan ouvre, comme « Scannez pour le menu complet (PDF) » ou « Scannez pour la liste de prix. » Les lecteurs sont plus susceptibles de scanner quand ils savent le résultat, et moins susceptibles d'être agacés quand un PDF s'ouvre s'ils s'y attendaient. Si le PDF est long, envisagez de renvoyer d'abord vers une courte page de destination qui nomme le document, sa date et sa taille, avec un bouton clair pour ouvrir le PDF, plutôt que d'ouvrir un gros fichier sans avertissement.

Enfin, prévoyez la fin de vie du document. Un menu change avec les saisons, une liste de prix expire, et un document d'événement devient inutile après l'événement. Décidez à l'avance ce que le code doit faire quand le document n'est plus actuel : pointez-le vers la nouvelle version, pointez-le vers une page qui dit que le document a été remplacé, ou retirez le matériel imprimé. Laisser un code qui ouvre une liste de prix obsolète ou un programme d'événement passé est pire que de n'avoir aucun code, car cela apprend aux lecteurs que vos codes ne sont pas dignes de confiance. Un code PDF mérite sa place en restant actuel, en s'ouvrant vite, et en donnant au lecteur exactement le document attendu, sous une forme qu'il peut réellement lire sur le téléphone qu'il a en main.

Bon à savoir

Un QR code peut-il contenir un fichier PDF entier ?

Pas en pratique. Les codes sont conçus pour de courtes charges comme les liens, et une longue charge rend le motif dense et difficile à scanner à la taille d'impression. Utilisez plutôt un code de lien qui ouvre un PDF hébergé.

Dois-je utiliser un code statique ou dynamique pour un PDF ?

Utilisez un code dynamique pour tout document qui peut changer. Une destination dynamique peut être mise à jour sans réimpression, tandis qu'un code statique fige l'adresse exacte imprimée dessus, donc déplacer le fichier casse chaque exemplaire imprimé.

Où dois-je héberger le PDF ?

À une adresse stable et publique que vous contrôlez, comme votre propre site web, avec un nom de fichier propre et aucune exigence de connexion. Évitez les liens de partage temporaires ou les dossiers personnels dont les permissions peuvent changer, car l'un ou l'autre peut casser le code imprimé sans avertissement.

Quelle taille le PDF doit-il faire ?

Aussi petit que vous pouvez le faire sans nuire à la lisibilité. Compressez d'abord les images, supprimez les pages inutiles, privilégiez le vrai texte aux images scannées, et testez le résultat sur un téléphone sur une connexion mobile. Si les prix ou les petits caractères deviennent difficiles à lire, la compression est allée trop loin.

Comment remplacer le PDF sans réimprimer ?

Préparez et vérifiez le nouveau fichier sur un téléphone, remplacez-le à la même adresse publique ou mettez à jour la destination dynamique, puis scannez un exemplaire imprimé pour confirmer la nouvelle version et sa date. Dites au personnel que le document a changé, et testez sur un téléphone qui n'a pas mis l'ancien fichier en cache.

Pourquoi le PDF s'ouvre-t-il lentement depuis un scan ?

Les causes habituelles sont un gros fichier, des pages riches en images, un hébergeur lent, ou un signal mobile faible. Compressez le fichier, réduisez la taille des images, divisez un long document, et testez sur données mobiles plutôt que seulement sur le Wi-Fi du bureau.

Le scan doit-il ouvrir le PDF directement ou d'abord une page de destination ?

Ouvrez le PDF directement quand il est court et que l'étiquette dit que c'est un PDF. Utilisez d'abord une courte page de destination quand le fichier est gros, quand les lecteurs ont besoin de la date et du contexte avant le téléchargement, ou quand vous voulez qu'une page propose plusieurs documents connexes.

Que se passe-t-il quand le PDF devient obsolète ?

Pointez le code dynamique vers la nouvelle version, ou vers une page qui dit que le document a été remplacé, et retirez le matériel imprimé qui pointe toujours vers l'ancienne version. Laisser une liste de prix obsolète ou un programme en direct enseigne aux lecteurs à ne pas faire confiance à vos codes.
