Ce que les statistiques du QR code dynamique vous disent

Un code dynamique signale chaque scan. Voici ce que FreeQrly compte, comment le lire, et ce qu’il ne collecte jamais.

16 octobre 2026 · Dernière mise à jour : 3 novembre 2026 · 15 min de lecture

Un code statique est silencieux : il ne rapporte jamais rien, donc personne — vous y compris — ne sait combien de fois il a été scanné. Un code dynamique rapporte chaque scan à votre tableau de bord. Voici ce que FreeQrly compte, comment le lire, ce qu'il ne collecte délibérément jamais, et comment utiliser vos propres chiffres pour décider — plus les seuls chiffres externes que cet article cite, chacun avec sa source d'origine, pour que vous puissiez les vérifier vous-même.

La réponse courte d'abord : les statistiques de scan répondent à trois questions, et seulement trois. Quel emplacement a attiré l'attention ? Quand l'a-t-il attirée ? Et sur quel type d'appareil et depuis à peu près où ? Tout le reste — si un scan est devenu un client, si l'affiche était bonne — est une interprétation que vous ajoutez par-dessus, et la plupart des mauvaises lectures viennent de traiter une interprétation comme si c'était une mesure.

Ce que FreeQrly compte

Ouvrez un code dynamique dans votre tableau de bord et vous voyez le même ensemble de chiffres pour chaque code. Les définitions comptent, parce que deux des lectures erronées les plus fréquentes viennent de confondre « total » et « unique » et « aujourd'hui » et « depuis toujours ».

Chaque répartition s'accompagne de comptes et de pourcentages. Les pourcentages sont des parts des scans de ce code, pas des parts de quoi que ce soit de plus grand — un code avec surtout des scans iOS ne veut pas dire que la plupart de vos clients utilisent des iPhones. Cela veut dire que la plupart des gens qui ont scanné ce code l'ont fait sur un iPhone.

Deux chiffres externes, avec leurs sources jointes

Cet article cite délibérément très peu de chiffres externes, et la raison vaut d'être dite clairement : une statistique QR empruntée à un recueil arrive généralement sans les trois faits qui rendent un chiffre utilisable — quoi a été mesuré, sur qui, et quand. Les deux chiffres ci-dessous arrivent avec les trois, depuis leurs éditeurs d'origine.

La norme QR elle-même : combien de dégâts un code peut survivre

Les statistiques de scan ne sont que la moitié d'une décision d'impression ; l'autre moitié est de savoir si le code survit à la manipulation. La norme QR, ISO/IEC 18004:2024, définit quatre niveaux de correction d'erreur, chacun indiquant quelle part des mots de code du symbole peut être récupérée en cas de dégâts :

NiveauMots de code récupérablesUsage typique
L7 %Affichage numérique propre
M15 %Impression intérieure quotidienne
Q25 %Tirage manipulé ou vivant en extérieur
H30 %Codes portant un logo central, ou manipulation rude

Source : ISO/IEC 18004:2024, la spécification de la symbologie des codes-barres QR, via la page de la norme ISO (iso.org/standard/83389.html). Lisez les pourcentages attentivement : ils décrivent des mots de code, pas une surface imprimée. Un code au niveau H ne survit pas à tous les trous possibles de 30 % dans le tirage, et un niveau plus élevé achète de la résilience en dépensant davantage du code en redondance. Pour les statistiques, le point pratique : un code imprimé à un niveau bas sur une surface manipulée sous-déclarera son vrai public — des gens ont essayé de scanner, le code a échoué, et aucun scan n'a été enregistré.

Qui porte un téléphone avec appareil photo : l'enquête américaine de Pew

Quand vous lisez une répartition par appareil, il aide de connaître le plafond : combien de personnes dans le public pourraient scanner du tout. La fiche mobile 2026 du Pew Research Center rapporte que 91 % des adultes américains ont dit posséder un smartphone, et 98 % ont dit posséder un téléphone portable quelconque, contre 35 % de possession de smartphone dans la première enquête du Center en 2011. Source : Pew Research Center, « Americans' Use of Mobile Devices in 2026 » (pewresearch.org/internet/fact-sheet/mobile/), basé sur une enquête auprès de 5 511 adultes américains menée du 30 janvier au 18 juin 2026, avec une marge d'erreur globale de plus ou moins 1,8 point de pourcentage.

Trois mises en garde voyagent avec ce chiffre, et elles s'appliquent à tout chiffre externe rencontré. D'abord, la population : ce sont des adultes américains, pas le monde, et pas la liste d'invités de votre événement. Ensuite, la mesure : la possession auto-déclarée, pas le comportement de scan. Enfin, la date : une enquête de 2026 décrit 2026. Un chiffre utilisé hors de sa population, de sa mesure, ou de sa date cesse d'être une preuve et devient de la décoration.

Comment lire vos propres chiffres : cinq questions

Les chiffres de votre tableau de bord n'ont besoin d'aucun repère externe pour être utiles. Passez chaque lecture par ces cinq questions avant d'agir dessus :

  1. Comparé à quoi ? Le total d'un code veut dire peu tout seul. Comparez des codes qui ont tourné dans la même période, dans des emplacements similaires, pour la même offre. Un code de dépliant et un code d'affiche de la même semaine peuvent être comparés ; un code de dépliant du printemps dernier et un code d'affiche de cette semaine ne le peuvent pas, parce que la saison, l'offre et le public ont tous changé entre-temps.
  2. Sur quelle période ? Le graphique sur 7 jours existe pour empêcher les lectures d'un seul jour. Un code qui semble mort un lundi peut être un code du soir, un code de week-end, ou un code de trajet de banlieue. Lisez la forme de la semaine avant de juger la hauteur d'un jour.
  3. Total ou unique ? Si le total dépasse de loin l'unique, les mêmes personnes reviennent — ce qui est bon pour un menu ou un horaire, et un signal d'alerte pour une offre unique. Si l'unique est proche du total, chaque scan est une personne différente, et le code touche largement plutôt que profondément.
  4. Que s'est-il passé d'autre ce jour-là ? Les pics ont besoin de contexte. Une rafale de scans juste après la publication d'un post, c'est le post, pas l'affiche. Une rafale un jour où vous avez changé la destination, c'est la nouvelle destination, pas l'ancien emplacement. Notez les événements externes — un post, une mention, un changement de prix — à côté du graphique, sinon le graphique vous induira en erreur avec une parfaite assurance.
  5. À quoi le scan a-t-il mené ? Un scan est un coup d'œil, pas une conversion. Jumelez les statistiques de scan avec ce que la destination elle-même mesure — envois de formulaires, commandes, inscriptions — et jugez le code par le résultat de la destination, pas par le nombre de scans seul.

Lire une vraie semaine : des schémas, pas seulement des totaux

Les mêmes répartitions, lues comme des comportements plutôt que des chiffres :

  • Scans du soir seulement. Un code qui s'éveille après les heures de travail est probablement sur un trajet de banlieue ou dans un lieu du soir — des visiteurs du soir, pas des visiteurs de bureau.
  • Une nouvelle ville soudaine. Des scans qui s'étendent à une ville où vous n'avez jamais imprimé veulent généralement dire que quelqu'un a partagé le code dans une conversation ou une publication — le code a voyagé sans vous. Vérifiez où le code pointe : un code partagé envoie des inconnus vers votre destination, donc la destination devrait avoir du sens pour un inconnu.
  • Scans uniquement en semaine. Un code qui se tait le week-end est probablement sur une affiche de bureau ou dans un lieu de semaine, pas un lieu de week-end.
  • Scans majoritairement sur ordinateur. Une affiche qui reçoit des scans sur ordinateur est probablement scannée depuis une capture d'écran ou une image transférée, pas depuis le mur. La version mur peut aller bien ; la version capture fait le travail, et la destination devrait être vérifiée sur un écran d'ordinateur aussi bien que sur un téléphone.
  • Zéro est une donnée. Un code sans scan pendant une semaine vous dit que l'emplacement est mauvais, pas le code. Les codes n'échouent pas silencieusement très souvent — un code imprimé scanne ou ne scanne pas, et un test rapide avec votre propre téléphone règle cela en quelques secondes. S'il scanne et que personne ne le scanne, le problème est la position, la taille, le contraste, ou l'absence de raison de scanner, dans cet ordre.

Un exemple travaillé, avec l'arithmétique montrée

Exemple illustratif — les chiffres ci-dessous sont hypothétiques, utilisés seulement pour montrer l'arithmétique, pas des mesures d'une vraie campagne. Supposez que deux codes pointent vers la même page pendant les mêmes deux semaines. Le code A, sur un panneau de comptoir, enregistre 120 scans totaux et 90 scans uniques. Le code B, sur une affiche de vitrine, enregistre 60 scans totaux et 55 scans uniques. Trois lectures suivent, chacune avec une action différente :

  • Portée : Le code A a atteint plus de personnes distinctes (90 contre 55), donc le panneau de comptoir est l'emplacement le plus large.
  • Usage répété : Le total du code A dépasse son compte unique de 30 scans, tandis que celui du code B ne le dépasse que de 5, donc les visiteurs du comptoir scannent à répétition tandis que les visiteurs de l'affiche scannent pour la plupart une seule fois. Cela correspond à un panneau de comptoir vu par des habitués et une affiche vue par des passants — et cela suggère que la destination du code de comptoir devrait récompenser une deuxième visite, tandis que la destination du code d'affiche devrait convaincre en une visite.
  • Prochain test : N'échangez rien pour l'instant. Déplacez l'affiche du code B au comptoir pendant une semaine et le panneau du code A à la vitrine, puis comparez à nouveau. Si le schéma suit l'emplacement, l'emplacement était la cause. Si le schéma suit le code, la destination ou le design était la cause. Un échange bat un mois de débat sur quel panneau est meilleur.

La discipline de cet exemple est le point, pas les chiffres : même période, même destination, un seul changement à la fois, et une règle de décision écrite avant que le test ne tourne.

Mettre en place une comparaison en laquelle avoir confiance

  1. Donnez à chaque emplacement son propre code dynamique. Un code par emplacement — comptoir, vitrine, dépliant, reçu — tous pointant vers la même destination. Les codes partagés ne peuvent pas distinguer les emplacements, et une comparaison construite sur un code partagé est une devinette avec un graphique.
  2. Gardez la destination identique. Si deux codes pointent vers des pages différentes, vous testez des pages, pas des emplacements. Testez une variable à la fois.
  3. Faites-les tourner pendant la même période. Commencez et terminez ensemble, avec les mêmes jours de semaine et week-ends. Un code qui a tourné pendant un week-end de vacances n'est pas comparable à un code qui a tourné pendant une semaine ordinaire.
  4. Notez ce qui s'est passé d'autre. Tenez un journal d'une ligne à côté du graphique : post publié, prix changé, lieu fermé. Les pics sans notes deviennent des mystères.
  5. Décidez de l'action avant de regarder. Écrivez ce que vous ferez si A dépasse B — déplacer B, réimprimer B, retirer B — avant d'ouvrir les statistiques.
  6. Agissez sur le résultat, puis remesurez. Déplacez le code faible, changez la destination du code fort, ou retirez le code silencieux — et regardez le graphique des 7 jours suivants pour le changement. Une statistique qui ne change jamais une décision était un divertissement, pas une mesure.

Ce que FreeQrly ne collecte jamais

Les statistiques sont des agrégats — il n'y a aucune fiche par visiteur à consulter. Un « scan unique » est un hachage à sens unique de l'adresse IP de la personne qui scanne, du navigateur, et de la date : suffisant pour compter les personnes distinctes ayant scanné par jour, impossible à inverser en une personne. Pas de noms, pas d'e-mails, pas de lieux exacts, pas de suivi d'individus entre codes. Et les codes statiques ne suivent rien du tout — ils ne touchent jamais un serveur, il n'y a donc rien à compter.

Cette limite façonne ce que vous devriez demander aux statistiques. Vous pouvez demander quel emplacement a gagné, quand il a gagné, et sur quels appareils. Vous ne pouvez pas demander qui a scanné : un scan ne porte aucune identité, et toute identité qui y est attachée vient d'ailleurs. Si votre décision exige vraiment de savoir qui a répondu, mettez un formulaire derrière le code et laissez les gens s'identifier là, volontairement.

Ce que les statistiques de scan ne peuvent pas vous dire

  • Les scans ne sont pas des clients. Un scan est un coup d'œil. Quelqu'un peut scanner par curiosité, par accident, ou pour montrer à un ami, et aucun de ces cas n'est une vente. Jugez le résultat de la destination, pas le nombre de scans.
  • Les scans ne sont pas la satisfaction. Un code très scanné sur un formulaire de plainte n'est pas une réussite. Lisez le contenu de la destination à côté des comptes.
  • Les moyennes cachent la forme. Deux codes avec le même total hebdomadaire peuvent avoir des schémas opposés — l'un stable, l'autre en pics — et le stable est généralement l'emplacement le plus sain. Lisez toujours le graphique sur 7 jours, pas seulement le total.
  • Le silence est ambigu. Zéro scan peut vouloir dire un mauvais emplacement, un tirage abîmé, une destination changée, ou un code imprimé là où personne ne regarde. Testez le tirage avec votre propre téléphone avant de conclure quoi que ce soit sur le public.
  • Les repères externes induisent plus en erreur qu'ils n'aident. Un chiffre cité sans sa population, sa mesure et sa date ne peut pas être comparé à vos codes, parce que vous ne savez pas ce qu'il a compté. Les chiffres publiés par les fournisseurs méritent une vérification supplémentaire : lisez-les comme le propre récit du fournisseur sur ses propres utilisateurs, et cherchez la page de méthodologie qui indique qui a été interrogé et comment. Un chiffre dont la page d'origine indique la méthode peut être utilisé, avec sa portée jointe ; un chiffre rapporté de seconde main, dépouillé de sa méthode, devrait être exclu entièrement de votre décision. C'est pourquoi cet article s'appuie sur votre propre tableau de bord et sur deux sources de niveau normatif plutôt que sur un recueil de pourcentages empruntés.

Une routine hebdomadaire qui prend dix minutes

  • Ouvrez chaque code en direct et lisez d'abord la forme du graphique sur 7 jours, les totaux ensuite.
  • Comparez les emplacements qui ont tourné côte à côte, même période, même destination.
  • Déplacez, redirigez, ou retirez l'emplacement le plus faible — un seul changement, pas cinq.
  • Vérifiez la destination sur l'appareil que la plupart des personnes qui ont scanné ont utilisé cette semaine.
  • Notez tout événement externe à côté du graphique, pour que le pic de la semaine prochaine ait une explication prête.

Faites cela chaque semaine pendant un mois et les statistiques deviennent une habitude qui déplace les panneaux et retire les emplacements morts.

Bon à savoir

Qu’est-ce qui compte comme un scan unique ?

Un scanner, une fois par jour. FreeQrly compte les scanners distincts avec un hachage à sens unique de l’adresse IP, du navigateur et de la date — la même personne qui scanne deux fois dans la journée ne compte qu’une fois.

Les QR codes statiques suivent-ils les scans ?

Non. Les codes statiques ne touchent jamais un serveur — la destination vit dans le motif — il n'y a donc rien à compter. Seuls les codes dynamiques rapportent des scans.

Les données des visiteurs sont-elles privées ?

Oui. Les statistiques sont uniquement des agrégats : des chiffres par jour, pays, ville, appareil et système d’exploitation. Pas de noms, pas d’e-mails, pas de positions exactes, pas d’enregistrements par visiteur. Les scans uniques utilisent un hachage irréversible.

Puis-je voir qui a scanné mon QR code ?

Non — et c'est voulu. FreeQrly compte les scans ; il n'identifie pas les personnes qui scannent. Un scan ne porte aucune identité, donc si une décision exige de savoir qui a répondu, mettez un formulaire derrière le code et laissez les gens s'identifier là volontairement.

Pourquoi un code affiche-t-il bien plus de scans totaux que de scans uniques ?

Parce que les mêmes personnes scannent à répétition. Un total bien devant le compte unique correspond à un code vu par des habitués, comme un panneau de comptoir ou un menu ; un total proche du compte unique correspond à un code vu surtout par des passants. Comparez les deux chiffres ensemble — le total seul cache l'usage répété.

Mon code affiche zéro scan — est-il cassé ?

Pas forcément. Testez d'abord le tirage avec votre propre téléphone : s'il scanne, le problème est l'emplacement, la taille, le contraste, ou l'absence de raison de scanner, dans cet ordre. Zéro scan pendant une semaine est une donnée sur l'emplacement, pas une preuve que le code a échoué. S'il ne scanne pas, vérifiez les dégâts, le contraste et la taille avant de conclure quoi que ce soit sur le public.

Comment comparer deux emplacements équitablement ?

Donnez à chaque emplacement son propre code dynamique pointant vers la même destination, faites-les tourner pendant la même période avec les mêmes jours de semaine et week-ends, et décidez de l'action avant de regarder — ce que vous ferez si l'un dépasse l'autre. Notez tout ce qui s'est passé d'autre cette semaine, comme la publication d'un post, à côté du graphique.

Pourquoi cet article cite-t-il si peu de statistiques externes ?

Parce qu'un chiffre externe n'est utilisable qu'avec sa mesure, sa population et sa date jointes. Cet article cite deux chiffres qui arrivent avec les trois depuis leurs éditeurs d'origine — les niveaux de correction d'erreur QR de l'ISO et l'enquête américaine sur les smartphones de Pew — et s'appuie sur votre propre tableau de bord pour le reste. Un chiffre rapporté de seconde main, dépouillé de sa méthode, est exclu des décisions ici.
