Statische vs. dynamische QR-Codes

Einer ist für immer kostenlos. Der andere ist ein Abo. So erkennst du, welchen du wirklich brauchst.

13. Oktober 2026 · 4 Min. Lesezeit

Jeder QR-Code-Generator will dasselbe Gespräch mit dir führen: Hast du schon mal über dynamisch nachgedacht? Bevor du antwortest, hilft es zu wissen, was die beiden Sorten wirklich sind — und warum die Branche eine davon so stark pusht.

Der Unterschied, ohne Verkaufsgespräch

Ein statischer QR-Code enthält dein Ziel direkt. Scann ihn und dein Handy liest das WLAN-Passwort, die vCard oder die URL direkt aus dem Muster. Kein Mittelsmann, kein Server, kein Konto.

Ein dynamischer QR-Code enthält einen kurzen Link auf dem Server des Anbieters. Scann ihn, dein Handy besucht ihren Server, und ihr Server leitet dich zum echten Ziel weiter. Weil das Ziel auf ihrem Server lebt, kann der Anbieter es später ändern — und jeden Scan zählen.

Das ist der ganze Unterschied. Alles andere sind Konsequenzen.

Wann dynamisch wirklich Sinn macht

  • Du machst Kampagnen. Ein Poster geht nächste Woche in den Druck, aber die Landingpage ist nicht final. Dynamisch lässt dich jetzt irgendwohin zeigen und es später korrigieren.
  • Du brauchst Scan-Analysen. Wie viele Leute gescannt haben, von wo, auf was. Statische Codes sind stumm; dynamische Codes melden nach Hause.
  • Du testest Ziele A/B. Den Link hinter einem gedruckten Code austauschen, ohne neu zu drucken.

Wann statisch gewinnt

  • Das Ziel ändert sich nicht. WLAN-Passwörter, Visitenkarten, App-Download-Links, Restaurantmenüs, Museumsetiketten. Die meisten QR-Codes da draußen sind so.
  • Du willst kein Abo. Dynamisch heißt für immer zahlen — aufhören, und die Codes sterben. Statisch ist eine einmalige Handlung.
  • Privatsphäre zählt. Jeder dynamische Scan pingt den Server des Anbieters. Statische Scans berühren nichts außer dem Ziel.
Hier kommt der unangenehme Teil: Die meisten Generatoren pushen dynamisch, weil es wiederkehrende Einnahmen sind, nicht weil du es brauchst. Wenn der „kostenlose“ Code von jemandem ein Konto erfordert, schaust du auf einen dynamischen Code mit Testphasen-Timer.

Eine schnelle Entscheidungshilfe

  • WLAN für Gäste? Statisch.
  • Kontaktdaten auf einer Visitenkarte? Statisch.
  • Menü, das sich saisonal ändert? Statisch — zeig auf deine Menü-Seite und aktualisiere die Seite, nicht den Code.
  • Billboard für einen Produktlaunch mit nicht finalen URLs? Dynamisch — dafür ist es da.
  • Musst du einem Kunden Scan-Zählungen berichten? Dynamisch.

Gut zu wissen

Was ist der Unterschied zwischen statischen und dynamischen QR-Codes?

Ein statischer QR-Code kodiert das Ziel direkt im Muster — für immer kostenlos, nicht änderbar. Ein dynamischer QR-Code kodiert eine Weiterleitung auf dem Server des Anbieters, sodass das Ziel später geändert und Scans getrackt werden können — aber er erfordert ein laufendes Abo.

Brauche ich einen dynamischen QR-Code?

Wahrscheinlich nicht. Wenn sich dein Ziel nicht ändern wird — WLAN, Visitenkarten, feste Links — ist statisch die richtige Wahl. Dynamisch brauchst du nur für änderbare Ziele oder Scan-Analysen, typischerweise in Marketingkampagnen.

Warum pushen kostenlose QR-Code-Generatoren dynamische Codes?

Weil dynamische Codes ihren Server erfordern, was ein Abo rechtfertigt. Viele „kostenlose“ Generatoren erstellen dynamische Codes, die an eine Testphase gebunden sind — der Code hört auf zu funktionieren, wenn die Testphase endet.
