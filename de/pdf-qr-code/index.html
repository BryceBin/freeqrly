Wo dein PDF liegen sollte

Ein QR-Code enthält einen Link, keine Datei. Der Code, den du druckst, zeigt auf den Ort, an dem dein PDF schon liegt. Deshalb ist die erste Entscheidung: Wo soll die Datei liegen? Drei Möglichkeiten decken fast alles ab.

Egal welche du nimmst: Stell die Freigabe auf „Alle, die den Link haben“. Ein PDF, das nur für bestimmte Personen freigegeben ist, verlangt von allen, die scannen, eine Anmeldung – und die meisten werden das nicht tun.

Warum ein Drive-Link manchmal eine Warnung zeigt

Zwei Dinge sorgen für Verwirrung, und keins davon ist ein Problem des Codes.

Das erste ist die Dateigröße. Google prüft Drive-Downloads auf Viren und überspringt diese Prüfung ab 100 MB. Statt eines Downloads bekommst du eine Seite mit dem Hinweis, dass Google die Datei nicht prüfen konnte, und einem Button zum Fortfahren. Das PDF öffnet sich trotzdem, wirkt auf einem Restauranttisch aber verdächtig. Halte Speisekarten und Broschüren unter 100 MB, dann erscheint die Warnung nie.

Das zweite ist die Berechtigung. Ist die Datei noch privat, landet, wer scannt, auf einer Google-Anmeldeseite. Öffne die Freigabeeinstellungen der Datei und stell sie auf „Alle, die den Link haben, können ansehen“.

Wenn beides nicht praktikabel ist – ein 300-MB-Portfolio oder ein Kunde, der auf einem privaten Ordner besteht –, stelle das PDF auf deiner eigenen Domain bereit. Dort bestimmst du die Berechtigungen, und es gibt keine Zwischenseite.

Wie groß du drucken musst

Ein Code, der auf dem Monitor funktioniert, kann an einer Wand versagen. Die Faustregel: Der gedruckte Code sollte etwa ein Zehntel der Entfernung messen, aus der gescannt wird. Aus 3 Metern Entfernung druckst du einen 30-cm-Code.

Lass einen Rand stehen. Die weiße Fläche um das Muster – die Ruhezone – gehört dazu, damit Scanner den Code finden. Sie wegzuschneiden, um Platz zu sparen, ist der häufigste Grund, warum ein gedruckter Code nicht mehr funktioniert.

Wenn du das PDF aktualisierst

Der Code zeigt auf einen Link. Ob du das PDF ohne Neudruck ändern kannst, hängt allein davon ab, ob der Link gleich bleibt.

Ersetzt du die Datei am selben Ort, bleibt der Link erhalten. Öffne in Drive die vorhandene Datei und lade eine neue Version hoch, statt eine neue Datei anzulegen; in Dropbox überschreibst du die Datei unter demselben Pfad. Die URL ändert sich nicht, also funktionieren alle gedruckten Codes weiter.

Lädst du eine neue Datei hoch, bekommst du einen neuen Link. Der alte Code öffnet dann eine gelöschte Datei oder eine 404. Du musst neu drucken – was gut zu wissen ist, bevor du 500 Tischkarten bestellst.

Noch ein Fall: Liegt das PDF auf deiner eigenen Domain und der Dateiname bleibt gleich, merkt niemand, der scannt, dass du die Datei ausgetauscht hast. Das ist die fehlertoleranteste Variante und die, die wir für alles in großer Auflage empfehlen würden.

Teste, bevor du druckst

Scanne den Code vom Bildschirm mit zwei verschiedenen Handys – einem iPhone und einem Android-Gerät –, bevor irgendetwas in den Druck geht. Bildschirm und Papier versagen unterschiedlich: Spiegelungen, verlaufende Tinte und eine zu knappe Ruhezone zeigen sich erst auf dem Ausdruck.

Scanne dann den Probedruck aus der Entfernung, aus der später gescannt wird. Braucht er länger als eine Sekunde, ist der Code für diese Stelle zu klein – nicht schlecht gemacht.

Gut zu wissen

Kann ich hier direkt ein PDF hochladen?

FreeQrly hostet keine Dateien — dein PDF liegt auf Drive, Dropbox oder deiner Website, und der QR-Code öffnet einfach seinen Link. Das heißt auch: Du kannst die Datei später austauschen, ohne neu zu drucken, solange der Link gleich bleibt.

Does the scanner download the PDF or preview it?

It depends on the file and the phone. iOS and Android both preview most PDFs in the browser before saving; a large file may download instead. Keep the PDF under a few megabytes if you want it to open quickly at the table.

Was, wenn das PDF groß ist?

Für den Code spielt die Größe keine Rolle — er codiert nur den Link. Halt das PDF selbst vernünftig klein, damit es auf Handys schnell öffnet.
