Zuletzt

Statische Codes werden komplett in deinem Browser erzeugt.

Ein statischer Code enthält einen Link

Das lassen die meisten App-Store-QR-Seiten weg, deshalb hier ganz offen: Ein QR-Code speichert Text, und dieser Text ist eine URL. Ein Code, ein Ziel. Im Muster steckt keine Logik, die das Handy erkennt und den passenden Store wählt.

Das ist wichtig, weil deine iOS- und Android-Einträge zwei verschiedene URLs sind. Ein einzelner statischer Code kann nur auf eine davon zeigen. Kodierst du den App-Store-Link, landen Android-Nutzer auf einer Seite für eine App, die sie nicht installieren können – umgekehrt ist es genauso schlecht.

Es gibt drei Wege, beide Plattformen abzudecken. Die Tabelle unten vergleicht sie.

Zwei Codes sind die ehrliche Variante ohne Aufwand. Eine Router-Seite ist das, was die meisten Apps machen, sobald sie eine Marketing-Website haben. Smart Banners funktionieren nur, wenn die Leute zuerst auf deiner Website landen – das ist eine andere Aufgabe als ein gedruckter Code.

So bekommst du deine Store-Links

Beide Stores geben dir eine saubere, dauerhafte URL, und beide sind leicht zu finden, wenn du weißt, wo.

Für iOS: Öffne deine App in App Store Connect, geh zu App-Informationen und kopiere die App-Store-URL. Sie sieht aus wie apps.apple.com/app/id1234567890. Du kannst ein Länderkürzel ergänzen – apps.apple.com/gb/app/id… –, wenn der Code einen bestimmten Storefront öffnen soll; die einfache Version leitet aber in die Region des Besuchers weiter, und das willst du meistens.

Für Android: Öffne den Eintrag in der Play Console und kopiere den Link aus der Adressleiste. Er sieht aus wie play.google.com/store/apps/details?id=com.yourcompany.yourapp. Die id ist dein Paketname, und sie ändert sich nie, auch wenn der App-Name wechselt.

Lass alles nach der ID weg. Marketing-Tools hängen oft Tracking-Parameter an, etwa ?mt=8 oder &referrer=…. Sie schaden nicht, machen das QR-Muster aber dichter ohne Nutzen – und ein dichteres Muster lässt sich schlechter klein drucken.

Eine Router-Seite bauen, die funktioniert

Entscheidest du dich für einen Code, braucht er ein Ziel. Eine Router-Seite ist eine kleine Seite auf deiner Domain, die den User-Agent liest und weiterleitet.

Die Logik ist kurz: Meldet der Browser ein iPhone oder iPad, geht es zum App Store; meldet er Android, zu Play; sonst zeigst du beide Buttons. Bau einen Fallback für Desktop ein, denn ein relevanter Teil der Scans kommt von Leuten, die am Laptop testen.

Zwei Dinge machen diese Seiten in der Praxis kaputt. Die In-App-Browser von Apple und manche Social-Apps kürzen den User-Agent auf etwas Generisches, dann rät die Erkennung falsch. Und eine Weiterleitung, die ausgelöst wird, bevor die Seite gerendert ist, wirkt wie ein kaputter Link. Beide Buttons zu zeigen und den erkannten hervorzuheben, ist nachsichtiger als sofort weiterzuleiten.

Soll das Ziel später änderbar sein, nimm einen dynamischen Code, der auf die Router-Seite zeigt. Ändere die Seite, und alle gedruckten Codes folgen – ohne Neudruck.

Wenn du zwei Codes druckst, beschrifte sie. Zwei identisch aussehende Quadrate ohne „iPhone“ und „Android“ sind schlechter als ein Code, weil die Leute den falschen scannen und in einem Store landen, der ihnen nichts nützt.

Gut zu wissen

Kann ein statischer Code beide Stores öffnen?

Nein. Ein statischer Code speichert eine einzige URL, und deine beiden Store-Einträge sind zwei URLs. Kodierst du den App-Store-Link, landen Android-Besucher bei einer App, die sie nicht installieren können. Druck zwei beschriftete Codes – oder lass einen Code auf eine Seite deiner eigenen Domain zeigen, die das Handy erkennt und an den richtigen Store weiterleitet.

Was, wenn ich beide Felder ausfülle?

Kodiert wird nur der App-Store-Link — das Play-Feld greift, wenn das App-Store-Feld leer ist. Um beide Plattformen abzudecken, erstellst du zwei Codes, einen pro Feld.

Was, wenn es nur eine Plattform gibt?

Füll das Feld aus und druck einen Code. Mehr brauchst du nicht.

Erkennt er das Handy und leitet automatisch weiter?

Nicht von allein — ein gedrucktes Muster kann keine Logik ausführen. Für die Geräteerkennung braucht es eine Seite dazwischen: Hoste eine kleine Router-Seite und lass einen dynamischen Code darauf zeigen, dann kannst du das Ziel später ändern, ohne neu zu drucken.

Zählt er Installationen?

Nein. Statische Codes enthalten nur den Link und senden keine Daten. App Store Connect und die Play Console melden die Installationen ohnehin.
