QR Codes for Event Organizers: The Complete Checklist (Before, During, and After)

A QR code only works if someone can scan it, in the right place, at the right moment. This checklist covers everything an event organizer needs to plan, print, test, run, and reuse QR codes — before the doors open, on the day, and after the last guest leaves.

November 19, 2026 · 17 min read

Most event QR codes fail for simple reasons: the code links to a moved page, the print is too small to scan from two meters, Wi-Fi drops at check-in, or nobody tested the code on a phone.

Before the Event: Plan, Create, Print, Test

Everything in this phase happens while you still have time to fix mistakes: a QR code printed on 500 badges cannot be reprinted the morning of the event, but its destination can still be changed — if you chose the right kind of code.

1. Decide which codes are static and which must be dynamic

  • Static codes encode their destination permanently. Once printed, the destination cannot change. They are genuinely free, need no sign-up, carry no watermark, never expire, and are generated entirely in the browser — nothing is uploaded and nothing is tracked.
  • Dynamic codes point to a short link you control. The printed code never changes, but you can edit where it leads at any time — even after it is printed, posted, and handed out. If in doubt, choose dynamic. The cost of an unneeded dynamic code is zero; the cost of a static code whose destination moved is a reprint.

2. Create the ticketing and registration codes

Your ticketing QR code is usually the first code an attendee scans, and it appears on posters, social posts, emails, and partner websites.

  • Link it to the live ticket page, not a homepage. Every extra tap risks losing a buyer.
  • Use a dynamic code so you can switch the destination between ticket phases (early bird → regular → final release) without reprinting or reposting anything.
  • Put the same code on every channel — poster, email signature, social bio link, partner page — and its scan statistics show the total across all of them. To compare channels, give each channel its own code instead.
  • Add a short printed URL underneath the code. If the code ever fails to scan, the URL is the backup.
  • If you run several ticket types (general, VIP, student, speaker), create one code per type. Batch generation can create up to 50 static codes at once, which is useful for per-type or per-channel variants, but batch is static-only — dynamic codes are created one at a time.

3. Create the check-in codes

Check-in is where a bad QR code causes a visible queue. Plan it as a process, not as a poster.

  • Decide what the guest scans: a code on their ticket confirmation email, a code on a printed badge, or a code posted at the entrance that opens the check-in page.
  • Decide what staff see: a check-in dashboard, a searchable attendee list, or a simple "confirmed" page. Test this on the exact device staff will hold — a phone, a tablet, or a laptop.
  • If each attendee gets a unique code (one per ticket), generate them in a batch: up to 50 static codes per batch, so a 200-person event needs four batches.
  • Print a few spare generic check-in codes for walk-ins, press, and last-minute additions.

4. Create the venue, schedule, speaker, and sponsor codes

These are the codes guests scan once they are inside. Each one answers a question a guest would otherwise ask a volunteer.

  • Venue directions and parking: a code linking to a map pin or directions page. Print it on the invitation, the confirmation email, and a sign at the car park entrance. Static is fine — the venue does not move.
  • Schedule and program: a code linking to the live schedule. Use dynamic: sessions get cancelled, rooms change, and start times slip. Put this code on the back of every badge, on the lobby wall, and at every room door.
  • Speaker links: one code per speaker, or one code linking to a speakers page with everyone's bio, slides, and social links. Dynamic, because slides arrive late.
  • Sponsor links: one code per sponsor, printed on their booth sign and in the program. Dynamic, so the sponsor can change the landing page after the event without asking you to reprint. Tell sponsors the code is dynamic and editable — it is a selling point for the booth package.
  • Wi-Fi: a Wi-Fi QR code that joins the network in one scan. Print it large at the entrance and in every session room. Static is fine, and guests will thank you for it.

Placement rules that prevent the most common failures:

  • Never place a code where glare hits it. Glossy paper under a spotlight, a code behind glass, or a screen facing a window will not scan. Matte paper and shaded placement prevent most of these failures.
  • Keep a quiet zone around every code. The blank margin around a QR code is part of the code. Do not let text, logos, or borders crowd it. A logo in the center is fine — the center is designed for that — but keep the edges clear.
  • One code per sign, one job per code. A poster with five codes is a poster nobody scans. If a sign needs several destinations, link to one landing page and list them there.
  • Print the short URL under every important code. It is the fallback when a camera cannot read the code.

6. Test-scan everything

This is the step most organizers skip, and the one that saves the event.

  • Scan every printed code with at least two different phones — one iPhone and one Android if possible — from the distance a guest will stand at.
  • Scan in the actual venue lighting if you can, or at least under bright light and in dim light.
  • Scan the codes on screen as well as on paper: a code that looks fine in a design file can be too small once it is on a badge.
  • Click through to the final destination every time. A code that scans but lands on a 404 page is worse than a code that does not scan, because nobody reports it — they just leave.
  • Test the check-in flow end to end with a real ticket: scan, confirm, enter. If it takes more than a few seconds per guest, the queue will grow.
  • Re-test after any change to a destination. Dynamic codes make changes easy — and untested changes easy too. Change, then scan, then trust.

A ten-minute test log — code, phone tested on, distance, pass or fail — catches the one code that would have failed in front of a hundred people.

On the Day: Run the Flow, Handle the Failures

On the day, your job is not to create codes. Watch the flow, fix what breaks, and update what changes — without reprinting anything.

7. Run the check-in flow

What the guest sees:

  1. They open their ticket email or hold up their badge.
  2. They scan the check-in code (or staff scan their ticket code).
  3. A confirmation page appears — their name, ticket type, and a clear "You're checked in" message.
  4. They walk in. No app to download, no account to create.
  • What staff see:
  1. The check-in page or attendee list, with the guest's name marked as arrived.
  2. A count of checked-in vs. expected guests, so you know at a glance whether the room is filling as planned.
  3. A search box for names, for the guest whose phone died or whose email never arrived.

Brief staff five minutes before doors open: show every staff member the check-in page on their own phone; agree that a failed scan never turns a guest away — search the name manually instead; keep one charged spare phone or tablet at the desk, and keep the paper attendee list within reach.

8. Change a link after printing — why dynamic codes matter

This is when dynamic codes prove their value. A session moves rooms. A speaker cancels. The ticketing page moves to a new platform. With static codes, each of these means reprinting. With dynamic codes, each one means opening the dashboard, editing the destination, and scanning the printed code once to confirm the new destination loads. Tell staff what changed, so nobody gives guests the old information from memory.

The pattern is clear: anything that can change on the day should have been dynamic from the start. Wi-Fi is the exception: set the password before printing and do not change it mid-event.

9. Have a failure plan

Something will go wrong. The plan decides whether it is a two-minute fix or a visible problem.

If a code won't scan: check the light first — move the sign out of direct glare or tilt it slightly. Wipe the guest's camera lens; it sounds minor, but it fixes many failures. Try another phone: if it scans on a second phone, the problem is the guest's device, not your code. Read the short printed URL aloud or type it in — that is why it is printed under the code. If the code itself is damaged (torn, wet, faded), replace the sign with a spare print. Always bring spares of the entrance and check-in signs.

If the Wi-Fi drops: check-in must not depend on Wi-Fi. Keep the paper attendee list at the desk and a downloaded copy of the list on a staff phone. Have staff tell guests the network name and password verbally until the network returns, and know the venue's backup network or mobile hotspot credentials before doors open.

If the ticketing page moves: if the ticketing code is dynamic, edit the destination and re-scan to confirm — this takes minutes. If it is static, you cannot fix the printed code: post the new link on your event's social accounts, email registered attendees, and put a staff member at the entrance with the new link ready to share. This is the failure that persuades organizers to use dynamic codes from then on.

If the schedule changes mid-event: edit the dynamic schedule destination once. Every printed schedule code in the building now shows the new schedule — badges, lobby wall, room doors — with no reprinting. Announce the change on the main screen and by voice as well, since not every guest will re-scan the code, and put a staff member at the old room door for the first ten minutes directing guests to the new room.

10. Use live updates and photo sharing

QR codes are not only for entry. During the event they are the fastest way to send updated information to a whole room.

  • Live schedule changes: one dynamic schedule code, updated once, reaches every guest who scans it. Announce "scan the code on your badge for the updated schedule" from the stage.
  • Room changes: update the destination, then put a staff member at the old room door for the first ten minutes directing guests to the new room.
  • Photo sharing: put a photo-sharing code on the stage backdrop, the lobby wall, and the tables. Guests scan it to upload photos to a shared album or to find the event hashtag. Use a dynamic code: the album link usually does not exist until the event is running.
  • Social links: one code linking to a page with all your social profiles and the event hashtag. Put it where people take photos — the backdrop, the photo wall, the sponsor area — because that is when they want to post.

After the Event: Follow Up and Reuse

The event ends, but the codes keep working — and the same printed materials can serve the next event.

11. Share the photo album

  • Update the dynamic photo-sharing code's destination to the finished album once photos are collected and curated. Every poster, badge, and table card that carried the photo code now points to the album — guests who scan a badge they kept at home land on the photos.
  • Email attendees with the album link as well. Not everyone keeps the badge, and email reaches people the code cannot.

12. Collect feedback while the memory is fresh

  • Update the dynamic feedback code's destination to the final survey, then email it and post it on social channels within 24 hours. Response rates fall sharply after the first day.
  • Keep the survey short: three to five questions, plus one open text box. A long survey attached to a QR code gets opened and abandoned.
  • Put the feedback code on the exit wall and the tables, not only in the email. Guests leaving the venue are the ones with the freshest opinions.
  • Read the feedback code's scan statistics: if many people opened the survey but few completed it, the survey is too long.

13. Send thank-you messages and sponsor follow-up

  • Update the thank-you code (or the main event code) to a thank-you page with the photo album, the feedback link, and the date of the next event.
  • Send sponsors their scan statistics: how many times their booth code was scanned, and when. Sponsors renew booths when they can see the numbers. Scan statistics are available on dynamic codes; static codes record nothing, which is another reason sponsor codes should be dynamic.
  • Share the headline results with speakers too — scans on their session code, feedback mentions — because speakers who feel valued come back.

14. Reuse the printed materials for the next event

This is the lasting benefit of choosing dynamic codes. The banners, badges, table cards, and signs you printed for this event do not need reprinting for the next one:

  1. Keep the printed materials that carry dynamic codes.
  2. Before the next event, edit each code's destination to the new event's pages: new ticketing link, new schedule, new photo album, new feedback form.
  3. Scan every reused code and confirm it lands on the new event's pages. A code pointing at last year's schedule is worse than no code.
  4. Reprint only the materials whose codes are static and whose destinations changed — usually just the date and venue details.

For a recurring event — a monthly meetup, an annual conference, a seasonal fair — this turns printing from a per-event cost into a one-time cost. The checklist for the next event starts at step 6 (test-scan everything) instead of step 1.

Good to know

Should event QR codes be static or dynamic?

Dynamic for anything that might change after printing: ticketing, schedule, speakers, sponsors, photo albums, feedback, and thank-you pages. Static for things that will never change: the venue address, the Wi-Fi login, and the event's permanent homepage. If you are unsure, choose dynamic — the free tier allows 20 dynamic codes, which covers most single events.

Can I change a QR code's destination after printing it?

Yes, if it is a dynamic code. Edit the destination in the code's settings and the printed code immediately leads to the new page. Static codes cannot be changed after printing; the destination is encoded in the code itself.

What size should a printed QR code be?

There is no universal size, because the right size depends on scanning distance: a badge code scanned at arm's length can be small, while a stage-backdrop code scanned from eight meters away must be very large. The reliable method is to print, then test-scan from the distance a guest will actually stand at, on two different phones.

Can I reuse the same printed QR codes for my next event?

Yes, for dynamic codes. Edit each code's destination to the new event's pages and re-test every code by scanning the actual printed material. Static codes can only be reused if their destination is still correct for the next event.

Is there a limit on how many times an event QR code can be scanned?

No. Scans are unlimited on both static and dynamic codes, so a popular code at a large event will not stop working partway through the day.
