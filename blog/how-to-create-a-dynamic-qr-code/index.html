How to create a dynamic QR code

A dynamic QR code lets you change the destination after printing — and see how many people scanned. Here's how to make one, free, in about a minute.

Dynamic or static? Decide before you print

The decision cannot be reversed for a code that is already printed. A static code holds the destination inside the pattern, so it can never be repointed. A dynamic code holds a short link that redirects to the destination, so the destination can be changed later. A printed static code with a wrong link needs a reprint; a printed dynamic code needs only an edit in the Dashboard.

How a dynamic code actually works

A dynamic code does not hold your link directly. It holds a short FreeQrly link, in the form freeqrly.com/q/XXXXXXX, and the pattern encodes that short link. When someone scans the code, their phone opens the short link, FreeQrly's server looks up the destination you currently have set, and the scanner is redirected there. The scanner ends up on your page; the short link is only the junction in the middle.

That junction explains every feature and limit:

  • Editing works because the pattern never changes. The pattern holds only the short link. Editing changes the record behind it, so every printed copy serves the new destination at the next scan.
  • Counting works because every scan passes through the junction. The server sees the scan on its way to the destination and adds it to the statistics. A static code never touches a server, so there is nothing to count.
  • An account is required because the junction must belong to someone. Only the creating account may change where its short link points. Without an owner, anyone could repoint anyone else's printed code.
  • Deleting is permanent because the junction is removed. Delete a code and its short link stops redirecting, so printed copies stop working. There is no undo, and the freed slot can be used for a new code.

Scanners do not see any of this — they point, tap the preview, and land on your page. One thing they can notice is a redirect that shows an advertisement or a vendor-branded page first, so when comparing generators, scan a sample code and watch what appears before your destination loads.

Choosing the type

The type decides what the scanner sees and does. A Website code opens a page. A WiFi code offers to join a network. A contact code offers to save a person. An event code offers to save a date. The right type removes a step, and that is usually worth more than a cleverer design. A restaurant should use a Website code pointing at its menu page, not a text code containing the menu: the page can be updated, the text code cannot. A guest WiFi code should be a WiFi code, because the phone can join from the scan itself — see how to share WiFi with a QR code.

Point at a page you control, not a file hosted somewhere you do not control: a deleted file leaves a working code pointing at nothing. And note that long text makes a denser pattern, which needs a larger print size to scan at the same distance; see the QR code print size guide.

Styling without breaking the scan

Dynamic codes support the same styling as static codes: dot shapes, colors, a logo in the centre, and a frame with text. Three rules keep a styled code scannable. First, keep contrast high and the background light; scanners read dark modules against light ones. Second, keep the logo modest and centred, and never cover a finder square. Error correction rebuilds modules hidden behind a small central logo — at the High level in ISO/IEC 18004, up to about 30% of codewords can be restored — but that budget covers all damage combined, including print wear and dirt, not the logo alone. Third, keep the quiet zone: the blank margin around the code, at least 4 modules wide on all four sides under ISO/IEC 18004, is part of the code, not decoration. More on logos is in how to add a logo to a QR code.

For print, test a real printed proof, not just the screen preview: one copy at the intended size, on the intended material, scanned on two different phones — one iPhone and one Android if you can — in the lighting where it will actually be used. Glossy lamination under bright light and a code wrapped around a bottle fail in ways a screen preview never shows. If the proof scans slowly, print larger; size is the cheapest fix available.

Reading the statistics honestly

Every dynamic code reports to your Dashboard: total scans, scans today, unique scans, and a seven-day chart, with breakdowns by country, city, device, and operating system. The full guide is in what dynamic QR code statistics tell you. Three habits matter most. Compare codes against each other, not against an imagined benchmark: a shop-window code and a delivery-box code live in different worlds. Treat zero as data: a code with no scans for a week usually means the placement is wrong, the call to action is missing, or the code is too small. And give a spike context: a burst of scans right after a post goes out is the post, not the poster.

FreeQrly's stats are aggregates only — counts by day, country, city, device, and operating system — with no per-visitor record and no way to identify an individual scanner. A unique scan is counted with a one-way hash, not a name or an address.

Scenarios where dynamic earns its keep

A restaurant menu that changes with the season

Print one code on the table tents and point it at the menu page. When the season changes, update the page or repoint the code — the tents stay. See QR codes for restaurants.

An event poster printed before the details are final

Posters go to print weeks before a venue, ticket link, or schedule is locked. A dynamic code lets the poster ship pointing at a holding page, then move to the ticket page when sales open, and to a recap page after the event. See QR codes for events.

A product or package that outlives its first campaign

Packaging is printed in bulk and sold over months or years. A dynamic code on the pack can start at a launch offer, move to a manual or warranty page, and later to a successor product — without a reprint. Keep a list of where each code lives: a code you cannot find in the Dashboard is a code you cannot fix.

One code per placement, or the numbers lie

Give each placement its own code. Sharing one code across a flyer, a business card, and a market stall merges their statistics into one number that explains nothing. A code by the till that opens a review page works the same way; see how to get Google reviews with a QR code.

Dynamic is for living material that someone still looks after; static is for material that must look after itself.

Mistakes that waste a print run

  • Printing static when the link was not final. If the destination might change, the code should have been dynamic before printing; a printed static code cannot be rescued by an edit.
  • Sharing one dynamic code across placements. One code, one placement, one statistics record — otherwise the numbers cannot say which placement worked.
  • Deleting a code to “tidy up”. Deleting is permanent and printed copies stop at once. Repoint a retiring code to a closing page first, and delete only when no printed copy remains in circulation.
  • Skipping the printed proof. A screen preview proves the design; only a printed proof at the real size, material, and light proves the scan. See why your QR code is not working.
  • Forgetting the call to action. A bare code asks scanners to guess. A frame saying what they get — menu, tickets, WiFi, discount — turns a decoration into a doorway.
