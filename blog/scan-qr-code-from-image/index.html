Scan a QR code from a picture

The code is in a photo, not in front of your camera. Here's how to decode it on iPhone, Android, and desktop — no app required.

October 14, 2026 · Last updated: November 3, 2026 · 15 min read

The short answer: you do not need a second phone, and you do not need to point a camera at your own screen. A QR code that arrives as a photo, a screenshot, a message attachment, or a picture on a web page can be read from the image itself. On an iPhone, open the image in Photos and press and hold the code. On Android, open it in Google Photos and tap the Lens button. On a computer, upload the image to a decoder that reads it in your browser, such as FreeQrly's scanner. The rest of this guide is about choosing the right one of those paths for where your image actually lives, cleaning up a stubborn image before you give up on it, and keeping private images private while you do it.

The core distinction is simple. A live camera reads a pattern in front of it. An image reader reads a pattern already stored as pixels. The two jobs look similar, but they use different tools, and reaching for the live camera when the code is already a file is the most common reason people conclude a code "cannot be scanned" when it can. If the code is in your hand as a file, start with an image reader, not with a camera.

The basic steps, whichever device you use

  1. Get the image into a form a reader can open. Save an attachment, take a screenshot of a code shown on screen, or download the picture from the page. A reader needs a file or an open image, not a thumbnail in a chat list.
  2. Open the image full-screen. Readers work on what they can see. A code shrunk to a thumbnail in a message thread is a much smaller target than the same code opened full-screen, and opening it full-screen costs nothing.
  3. Use your phone's built-in image reader first. On iPhone, Photos; on Android, Google Photos with Lens; on Samsung, Gallery. These readers run on the device and need no upload, which matters for the privacy section below.
  4. Read the preview before you open anything. The same rule as live scanning applies, with one extra reason: an image forwarded to you has passed through someone else's hands, and the preview is your check that the code leads where the sender said it does.
  5. If the first reader finds nothing, clean the image and try again — crop, brighten, and retry — before you conclude the code is unreadable. The cleaning steps below rescue more images than any change of reader.

On iPhone: Photos, press and hold

Open the photo or screenshot in the Photos app and press and hold the QR code itself. The phone detects the code in the image and offers the link or action, which you tap after reading the preview. That is the whole method, and it covers the most common cases: a screenshot a friend sent you, a photo of a poster you took yesterday, a boarding pass saved to your camera roll, a code inside an email that you screenshotted rather than saved. If pressing and holding does nothing, check two things before anything else: that you are pressing on the code itself rather than on empty space near it, and that the code is fully visible in the image rather than cut off at an edge. A code cropped by the screenshot's edge is the image equivalent of a code cropped by the camera's frame, and no reader can reconstruct the missing corner.

When the code is not a saved photo at all — it is showing in a message, an email, or a web page on the same phone — take a screenshot first, then open the screenshot in Photos and press and hold the code. This two-step dance feels clumsy the first time and becomes automatic quickly, and it is the answer to the question that confuses the most people: you cannot point your own camera at your own screen, so you capture the screen and read the capture instead. Live codes in front of you are covered in the phone scanning guide and the general scanning guide.

On Android: Google Photos and Lens

Open the image in Google Photos and tap the Lens button. Lens analyses the image, finds the code, and shows the decoded link or action, which you tap after reading the preview. Lens reads pixels, not sources, so it works for a saved photo, a screenshot, or a downloaded image alike. If you do not see a Lens button, look for it in the image's options or share menu. You can also reach Lens from the Google app by tapping its Lens icon and choosing the image.

On a Samsung Galaxy, there is an additional built-in path. Open the image in the Samsung Gallery app and tap the Bixby Vision button; the phone reads the image and offers to open the link or copy it. Samsung's support guide, updated in October 2026, describes the same path through the Quick Settings scanner: open Quick Settings, tap Scan QR code, tap the gallery image icon at the bottom, choose the photo, and confirm. Either door leads to the same result, so use whichever you find first. If your phone is neither a Samsung nor a phone with Google Photos, the fallback is the same as on a computer: save the image and upload it to a browser decoder, which is covered next.

On a computer: upload to a browser decoder

A computer has no built-in image reader for QR codes in the way a phone does, so this is where a browser decoder earns its keep. Save the image — or take a screenshot of the code on the web page, in the document, or in the presentation — and upload it to a decoder. FreeQrly's scanner decodes the image in your browser, so the image never leaves the page; that detail matters most exactly when the screenshot contains something private, which is often, and the privacy section below explains why. The decoder returns the raw decoded content, with a link button for links and a copy button for everything else. Read the decoded link before you open it, just as you would read a phone's preview.

Images other people send you

A code sent to you in a chat, an email, or a social post deserves one extra habit: save it before you scan it. Reading inside a chat bubble means reading a small, possibly compressed version of the image, inside an app that may not offer a reader at all. Saving the image gives you the full file, opens it in Photos or Google Photos where the reader lives, and lets you crop and brighten it if the first attempt fails. It also gives you a moment to think: a code arriving from a sender you do not know, with an urgent story attached, is the image version of the unexpected message the safety guides warn about. Save it, read the preview, and only then decide.

Cleaning up a stubborn image

Most unreadable images are not unreadable codes; they are readable codes buried in a bad picture. Work through these fixes in order, and retest after each one, because the first fix that works saves you the rest.

  • Crop tight around the code. Cut away the chat window, the surrounding text, the table, and the background. Keep the quiet zone — the blank margin around the code — inside the crop.
  • Straighten and flatten. A code photographed at an angle, on a curved surface, or in perspective is stretched in the image. If your photo app offers a straightening tool, use it lightly; otherwise retake the photo straight-on.
  • Brighten, do not sharpen blindly. Raising brightness or contrast can rescue a code shot in dim light. Heavy sharpening can invent edges that are not there, so brighten first and sharpen only a little.
  • Try the original file. If you have been working from a compressed chat copy, go back to the original photo, the original download, or a fresh screenshot. Editing cannot restore detail that compression removed.
  • Try a different reader. If Photos finds nothing, try Lens; if Lens finds nothing, try a browser decoder; if a browser decoder finds nothing, try the other phone in the house. A code on the edge of readability sometimes passes one reader and not another. A code that no reader can read from the original file should be replaced by the sender.

Special cases: video stills, multiple codes, and tiny codes

A code inside a video is a screenshot problem in disguise: pause on a frame where the code is sharp, fully visible, and not in motion, screenshot that frame, and read the screenshot. Multiple codes in one image — a poster, a page of tickets — should be read one at a time: crop to a single code, read it, and repeat, since a reader shown several codes will typically pick one, and it may not be the one you wanted. A tiny code in a large image may simply be too few pixels to resolve; crop to it, and if the modules still blur together when you zoom in, the image does not contain enough detail — ask for a closer photo, a higher-resolution download, or a fresh code.

Privacy: what your screenshot contains besides the code

Screenshots and photos almost always contain more than the QR code. A screenshot of a chat contains the conversation around the code. A photo of a ticket contains the name, the booking reference, and the barcode next to the code. A screenshot of a payment page contains amounts and account details. Before you upload any such image to a decoder, look at what else is in the frame, and crop it out. Cropping is not just a readability fix; it is a privacy fix, and it costs the same few seconds either way.

The deeper question is where the image goes. Many online decoders upload your image to their server to read it, which means a stranger's server receives your screenshot — chat, ticket, and all — just to read one code. A decoder that reads the image in your browser, like FreeQrly's scanner, never sends the image anywhere; the reading happens on your device, in the page, and the image stays with you. Prefer a local decoder for any image you would not email to a stranger, and crop before you upload even then.

The honest comparison: built-in readers, browser decoders, and scanner apps

For a code in an image, three kinds of tool compete, and the honest ranking depends on the image, not on the tool's marketing. Built-in readers — Photos on iPhone, Lens on Android, Gallery on Samsung — are the best first choice for a saved image on your own phone: they are already installed, they run on the device, and they need no upload. Browser decoders are the best choice on a computer, and the best backup on a phone when the built-in reader fails, provided the decoder reads locally in the browser rather than uploading your image. Scanner apps are the weakest default for this job: they add an install, a permission screen, and often ads or an account, in exchange for a capability your phone already has.

One more honest note: no reader rescues a code whose detail is gone. A heavily compressed forward, a blurred video frame, a code cut off at the edge of a screenshot — these are missing-data problems, not reader problems, and switching readers five times will not restore what was never captured. The fix for missing data is a better original, and asking the sender for one is faster and more honest than trying every decoder on the internet. Readers are good at finding codes in images; they are not good at inventing codes that are not there.

When the image reads but the destination fails

Sometimes the image reads perfectly and the result still disappoints: a dead link, a moved page, a form that no longer exists, a ticket that has already been used. That is not a scanning failure; it is a destination failure, and the fix belongs to whoever issued the code. A static code holds its destination directly, so if the destination is gone, the code has nothing to say — and if the destination moved, only the issuer can point the code somewhere new, which is exactly what a dynamic code is for: it stays editable after printing, with scan statistics, under a free account. For codes that will not read at all, see why your QR code won't scan and why your QR code is blurry. If the link is dead, ask the sender for a fresh code rather than rescanning.

Make a code worth sending as an image

The other side of this guide is worth a paragraph, because the codes people struggle to read from images are often codes that were made badly in the first place. If you are the one sending a code as an image, send the original file, not a screenshot of a screenshot; keep the code large in the frame, with its quiet zone intact and dark modules on a light background; and test it by reading it back from the image yourself before you send it.
