How to Generate 100 QR Codes at Once: From Spreadsheet to Printed Codes

yes — 100 codes means two batches of 50. FreeQrly's batch mode makes up to 50 QR codes at a time, so a hundred codes is two runs through the same tool: build one table of 100 rows, generate the first 50, then the second 50, download two ZIP files, test-scan, and print.

November 19, 2026 · 17 min read

It is free, needs no sign-up, and the codes carry no watermark. The rest covers the table, the input method, the checks before printing, and what to do when something looks off.

This guide covers static codes only, because batch mode makes only static codes. A static code holds its destination inside the pattern: it never expires, needs no account, and is generated entirely in your browser — nothing uploaded, nothing tracked. The trade-off: a static code cannot be edited after printing. If a link changes, regenerate that code and reprint it. If you need codes you can edit after printing, with scan statistics, use dynamic codes — made one at a time, not in batches.

Step 1: Build your table

Everything that can go wrong with a hundred codes goes wrong in the table, not the generator — a typo in row 37 becomes a wrong code in row 37. Give the table ten careful minutes first.

The one rule: one row, one code

Every row of your table becomes exactly one QR code, in the same order. Row 1 becomes qr-1.png, row 2 becomes qr-2.png, and so on. That order is the only mapping between a code and its destination, so keep the table file next to the downloaded ZIPs and do not reorder the rows.

A worked example: 100 product pages

Suppose a small shop wants one code per product page, for shelf labels. The table needs only two columns for a link code: something that identifies the row, and the link itself. All values below are SAMPLE DATA.

If your destinations are already in a spreadsheet — an inventory export, a product list, a guest list — copy the destination column into a fresh sheet instead of uploading the whole export.

Columns per type

Batch mode supports 16 types: url, text, email, sms, phone, geo, wifi, vcard, event, bitcoin, coupon, appstore, review, mp3, google-form, and menu. Single-field types need one column. The field orders above match what the batch generator reads — the format hint under the textarea shows the same order. First, the pipe is the separator, so it cannot appear inside a field: a WiFi password containing | will split into the wrong fields. Second, field order is fixed. For WiFi it is network name, password, security type — MyWiFi | password | WPA, exactly as shown. A reversed order still generates a code, but the phone will read the fields in the wrong places. Third, keep destinations short where you can. A short link makes a roomier pattern with larger modules, which scans more reliably at small print sizes. Shorten long links before they go in the table — and test the shortened links first.

Cleaning the table before you generate

Run through this checklist once, on all 100 rows, before you open the generator:

  1. No blank rows. A blank line in a pasted list is skipped, but the generator may still read a blank row in a spreadsheet as an empty item, so delete empty rows.
  2. No header row in the paste. Leave the header out of pasted text. (A CSV header row is auto-detected and skipped — see Step 2 — but pasted text gets no help.)
  3. No trailing spaces. A space at the end of a link becomes part of the code's content. In a spreadsheet, select the column and trim it.
  4. Every link opens. Spot-check the first, last, and a few middle links. A link that 404s in the browser 404s when scanned.
  5. One type per batch. A CSV upload uses a single type: the type selected in the generator. Do not mix WiFi rows and link rows in one batch; split mixed jobs by type, or use the Excel upload described next.

Step 2: Paste or upload — pick your input method

Batch mode offers two ways in; the right one depends on where your list already lives.

For 100 codes, upload is usually better: the file keeps your table intact, the generator handles the header row, and you can re-upload the same file if you spot a mistake. Paste is faster for a short list, or one that comes from somewhere other than a spreadsheet.

The Excel shortcut: one sheet per type

Only the Excel upload can carry several types in one file. Each sheet is one type, and the sheet name picks the type — url, website, or link for links; text; email; sms; phone; geo; wifi; vcard or contact for contacts; event. A sheet whose name is not recognized defaults to url, so check the names before uploading. Types beyond those nine sheet names are not picked by sheet name; for those, use the CSV upload or paste with the type selected.

Step 3: Use the template file

If you are starting from a blank sheet, not an existing export, do not build the columns from memory. FreeQrly provides a downloadable template, freeqrly-batch-template.xlsx, with one sheet per type, headers, and filled-in example rows. Download it, replace the example rows with your own, delete the examples you do not need, and upload the result. The template is the fastest way to get the field order right: for multi-field types like WiFi and vCard, the example row shows it. The vCard sheet has 8 columns — name, phone, email, company, title, website, address, note — and batch mode reads all eight, in template order, the same as the single-code contact form, so company and title also appear in the saved contact.

There is also a CSV template for the selected type only. For a mixed-type job, the Excel template is the right one.

Keep two copies of your finished file — the working file you upload, and an untouched original saved with the downloaded ZIPs, so the row numbers still answer "which code is which product" in three months.

Step 4: Generate and check the codes

Generation is the shortest step. Select the type, add your list — by pasting or uploading — and generate. Every item becomes its own code, previewed in a grid on the page. Then, before anything is downloaded or printed, check the grid:

  • Count the codes. Each batch should show 50. If the count is short, a row was skipped — usually a blank line. Go back to the table.
  • Read the first and last codes. Scan the first code, then the last. If both open the right destination, the setup is right; the middle codes use the same settings. Still, spot-check any row you typed by hand.
  • Spot-check one multi-field code. If your batch is WiFi or vCard, scan one and confirm the phone joins the network or saves the contact. A code that scans but fills the wrong field is a silent failure.

Test on screen first: screen testing is free and instant. But a code that scans on a bright screen can still fail on paper, which is why the print test in Step 6 matters.

Step 5: Download — one by one, or the whole ZIP

Each code can be downloaded individually as a 1024 px PNG — useful for one replacement code, or when you are placing codes one at a time into a design. For a hundred codes, the ZIP is the practical choice: one click downloads freeqrly-batch.zip containing qr-1.png through qr-50.png, each a 1024 px PNG. There is no SVG option in batch mode.

Two things to get right at download time. First, keep the two ZIPs apart: both arrive with the same file name, freeqrly-batch.zip, so the second will overwrite the first in the same folder. Rename the first to batch-1-rows-1-50.zip before downloading the second, or download each into its own folder. Second, keep the mapping: the file names inside the ZIP are row numbers, not product names. If you rename the PNGs, rename them from the table — qr-37.png becomes SKU-037-mug.png, for example — and work from a copy, keeping the original ZIP untouched.

No login is required: batch codes are static and generated in the browser, so there is no account to create, no watermark, and no expiry.

Step 6: Print — size, contrast, and the quiet zone

Three things decide whether a code that scans on screen also scans on paper, where it will actually live: a shelf label under shop lights, a parcel label in a warehouse, a table card in a dim restaurant.

Size

FreeQrly's print-size guide covers sizes by use case — cards, flyers, posters. As a floor, a plain code should be printed at least 2 × 2 cm, as shown on the page. Denser codes need more room: at the same print size, a code with a longer destination needs more room than one with a short destination, and codes scanned from a distance need to be larger in proportion to the distance. When in doubt, print one test label and scan it from the distance your customers will stand at.

Contrast and the quiet zone

Contrast never changes: dark modules on a light background, with strong contrast. A code in pale grey on white, or in a brand color too light, will fail on phones you cannot test — older cameras, dim rooms, glare. Keep the modules dark and the background light and plain.

Around every code sits the quiet zone: the blank margin that lets a camera find the code's edges. Do not let text, a border, a fold, or a neighbouring label eat into it. Give the code its own clear patch of light background, quiet zone clear on all four sides.

Paper, ink, and the print test

Matte paper works better than gloss under bright lights, because gloss reflects glare. If the labels must be glossy, test-scan under the lights they will sit under. Always run a print test before the full run: print one sheet and scan the first, last, and one random middle code on the paper, with two phones if you can — one iPhone and one Android. If all three scan on the first try, print the hundred. If one hesitates, print larger, raise the contrast, or shorten the destination.

When batch is the wrong tool

Batch mode is the right tool when the destinations are settled and the quantity is the problem. It is the wrong tool in three cases. First, you need to edit codes after printing: a menu link that changes monthly needs a dynamic code, made one at a time and editable from the Dashboard. The free tier allows 20 dynamic codes; Pro is $9/month or $90/year, and its only difference from the free tier is unlimited dynamic codes. During the current limited-time offer, free dynamic codes are unlimited; after the offer ends, the free plan includes 20 dynamic codes. Second, every code needs different styling: batch mode makes the set in one consistent style, so use the main generator one at a time instead. Third, you need scan statistics per code: static codes record no scans, so use dynamic codes instead — and dynamic codes do not come in a batch of 50.

The workflow, in one paragraph

Build a table, one row per code, columns to match the type. Clean it: no blank rows, no header in the paste, every link checked. Upload or paste it in two halves of 50, using the template if you are starting from scratch. Count the grid, scan the first and last codes, download the ZIPs into separate folders with the table beside them. Print one sheet, scan it on paper, then print the hundred. A hundred codes is not a hundred small jobs. It is one table, two batches, and a test print.

Good to know

How many QR codes can I generate at once?

Up to 50 per batch, whether you paste or upload — so 100 codes means two batches: rows 1–50, then rows 51–100. Keep the row order identical in both halves so the file names map back to the table.

Do I need an account to generate QR codes in bulk?

No. Batch codes are static and generated entirely in your browser, so no sign-up is needed, nothing uploaded, and the codes never expire and carry no watermark.

Can batch codes be dynamic or editable after printing?

No. Batch mode is static only. If a destination changes after printing, regenerate that code and reprint it. For codes you need to edit after printing, create dynamic codes one at a time instead.

What file types can I upload?

A CSV file (.csv) or an Excel file (.xlsx / .xls). A CSV carries one type per file, and the generator handles quoted fields, so commas inside a field are safe. An Excel file can carry one type per sheet, the sheet name picking the type.

How do I format WiFi and contact details in the file?

Multi-field types use the pipe character | between fields, in a fixed order. WiFi is network name, password, security type — for example, MyWiFi | password | WPA (SAMPLE DATA). A vCard is name, phone, email, company, title, website, address, note — for example, Ada Lovelace | +1 555 010 2040 | ada@example.com | Alder Design Studio | Designer | https://example.com | 123 Main St | Friend (SAMPLE DATA). The template, freeqrly-batch-template.xlsx, shows the field order for each type, with headers and example rows.

What do I get when I download?

Each code can be downloaded individually as a 1024 px PNG. The ZIP is freeqrly-batch.zip with qr-1.png through qr-50.png, each a 1024 px PNG. No SVG option in batch mode.

How do I know which PNG belongs to which product?

By row number: qr-1.png is row 1, qr-37.png is row 37. Keep the table with the ZIPs; rename copies from the table for meaningful file names.

What size should I print the codes?

At least 2 × 2 cm for a plain code, as shown on the page; larger for dense codes or codes scanned from a distance. FreeQrly's print-size guide covers sizes by use case — whatever size you choose, print one sheet first and scan it on paper.

Why do some of my codes fail to scan after printing?

The usual causes, in order: the print is too small for how dense the code is; the contrast is too low; or something — text, a border, a fold — has eaten into the quiet zone. Print larger, darken the modules, clear the margin, and test again on paper.
