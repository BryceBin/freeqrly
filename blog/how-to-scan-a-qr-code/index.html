How to scan a QR code

No app required. Every modern iPhone and Android phone scans QR codes with the camera it already has. Here's how — plus what to do when nothing happens.

2026-10-14 · Last updated: November 3, 2026 · 15 min read

The short answer: point your phone's camera at the code, wait for the preview, read it, and tap it. No app to install, no account to create, no photo to take. Every modern iPhone and Android phone reads QR codes with the camera it already has, and the whole job takes a few seconds once you know the rhythm: frame the whole code, hold still, read the preview, tap. This guide covers what each kind of code does, what your phone asks along the way, the safety habit that matters most, and a fault chain for the moment nothing happens.

Start by recognising what you are looking at. A QR code is the square pattern with three large corner squares; those corners are the reader's landmarks, and a pattern without them is not a QR code at all — it may be an ordinary barcode, a proprietary mark, or a decorative pattern, and no QR reader will read it. A genuine QR code can hold several kinds of content, and knowing which kind you have scanned changes what you should expect next. A link opens a page, a Wi-Fi code offers a network, a contact code offers a person to save, a text code shows words, an event code offers a calendar entry, and a payment or ticket code opens an app or checkout. Your phone's preview tells you which kind it is before anything happens.

The steps, from code to destination

  1. Frame the whole code. Open the built-in Camera app and hold the phone so the entire square, including the blank margin around it, sits inside the frame. You do not need to press the shutter button. If part of the code is cut off, pull back until all four corners are visible.
  2. Hold still and let the camera focus. Give the camera a second to settle; a moving phone produces a blurred pattern.
  3. Read the preview. A link, a network name, or an action appears on screen. Read it fully before you tap — the domain, not just the first words. This step is the safety habit, and it is covered in detail below.
  4. Tap to open, and answer the confirmation. Tapping opens the destination; read any confirmation the same way, as a second preview.
  5. If nothing appears, work the fault chain. Do not keep pointing and hoping. The ordered checks below separate a phone problem from a light problem from a code problem in about a minute.
  6. If the code is already on your own screen, read the image instead. Screenshot the code, or save the image, and read it from the image (Photos on iPhone, Google Photos with Lens on Android). The full version is the guide to scanning a QR code from a picture.

Before you tap: permissions and confirmations

Scanning asks very little of you, and that is part of its appeal — but the few things it does ask deserve attention. A browser-based scanner may ask for camera permission the first time; allow it while using the page, and revoke it afterwards. It does not need your photos, contacts, or location, and any such request is a reason to stop.

After the preview, confirmations follow the code type. A Wi-Fi code asks you to join a network — check the name against the sign before you join, since a rogue network with a plausible name is a real trick, and joining the wrong network is worse than failing to join the right one. A contact code asks you to save a person, and an app code asks you to open an app — check both against what you expected. A download should make you pause: a file is a larger commitment than a page. And a login form reached from a public code deserves a second look before any password goes near it.

Scenarios: the same rhythm, different stakes

Menus, posters, and timetables are the lowest-stakes scans, and the rhythm is at its simplest: frame, preview, tap. Failures here are usually physical: tilt for glare, step closer for size, add light for darkness. Tickets and check-ins are higher-stakes because they are time-sensitive and often single-use. Have the code ready before you reach the queue, and scan promptly if it refreshes.

The safety habit, in full

A QR code hides its destination by design. You cannot read a URL from looking at the pattern, which is exactly why a code is such an effective vehicle for a link you would never tap if you could see it. The defence is not to avoid codes — it is to read the preview, every time, and to treat the preview as a decision, not a formality. The United States Federal Trade Commission warned about this pattern in a consumer alert dated December 6, 2023: scammers cover genuine codes with their own stickers — on parking meters, for example — or send codes in unexpected messages, and a scanned code can lead to a spoofed site that looks real, where anything entered can be stolen, or to malware. The FTC's advice in that alert is the same habit this guide recommends: inspect the URL before opening it, look for misspellings or a switched letter in a familiar name, and do not scan a code in an unexpected message, especially one urging immediate action.

Turn that advice into three checks: the domain, letter for letter, matches the business or sign in front of you; the code shows no tampering, such as a sticker pasted over another code; and the context fits — you expected this code, in this place, for this purpose. Failing any one of those checks is enough to stop. A preview showing only a shortened link hides the final destination just as thoroughly as the code itself did; if you do not recognise the sender, that is a reason to stop, not to tap and find out.

When nothing happens: the fault chain, in order

Work through this chain in order. Each step takes seconds, and the order matters: it moves from the cheapest fixes to the most conclusive test, so you stop as soon as you find the fault instead of trying everything at random. The phone-specific versions of these steps — the exact toggles and shortcuts on iPhone, Pixel, and Samsung — are in the phone scanning guide; this chain is the logic that sits underneath them.

  1. Frame. Is the whole code, including its quiet margin, inside the frame? Pull back until all four corners are visible. A code cropped by the frame's edge is the most common cause of silence.
  2. Mode. Use the normal photo view, not portrait or video, or use your phone's dedicated scanner shortcut.
  3. Setting. A toggle switched off by an update looks exactly like a broken code; check your camera settings first.
  4. Focus and steadiness. Hold steady and move slowly closer or farther until the pattern sharpens.
  5. Light. Add light in a dark room, remove glare in a bright one, and tilt slightly for a code behind glass.
  6. Lens. Is the lens clean? Wipe it with a soft cloth. A smudged lens blurs every code equally, which is why a dirty lens is so often mistaken for a bad print.
  7. Code integrity. Are the corner squares intact, the contrast dark-on-light, and the code free of damage, fading, or a distorting curve?
  8. Size and distance. Is the code large enough for the distance? Per the print size guide, a code should be at least one-tenth as wide as the scanning distance and at least 2 × 2 cm in print; move closer if it is too small for its distance.
  9. Second phone test. If another phone reads it, the problem is your phone; if none does, it is the code.

Going deeper: blur, damage, and the quiet zone

Three code-side failures deserve more than a line in a chain, because they are the ones people misdiagnose most often. Blur is the first. A code can be blurred at creation — a low-resolution export stretched to poster size — or at capture — a moving phone, a shaky hand, a code photographed in poor light. Capture blur is fixed by holding still, adding light, and retaking; creation blur is fixed only by a better original. The full treatment is in why your QR code is blurry.

Damage is the second. Under ISO/IEC 18004, four error-correction levels — L, M, Q, H — let a reader reconstruct a damaged pattern: roughly 7% of codewords at L, 15% at M, 25% at Q, and 30% at H. So a scuffed code often still reads, and a code with a central logo reads because the correction absorbs the missing middle. The limit is the corner squares: damage one badly and the reader cannot orient the pattern at all, however good the error correction is elsewhere. That is why a torn corner fails while a scuffed middle succeeds.

The quiet zone is the third, and the most often designed away. The blank margin around a code, at least four modules wide on every side under the standard, is what lets the reader find the code's edges. A design that crowds the code with text, borders, or graphics up to its edge is not being stylish; it is removing the margin the reader needs to find the pattern. Crowding, pale colours on white, and a logo covering a corner square are the design choices that most often turn a working code into a decoration; see why your QR code won't scan.

The honest comparison: built-in scanning, browser scanners, and scanner apps

Three kinds of scanner compete for the same job, and the honest ranking is short. The built-in camera is the best default: already installed, already updated with the phone, and it reads standard codes with the same preview as any other reader, without an account or an ad between you and a menu. A browser scanner is the best backup: it needs no install, it works on a phone or a computer, and — when it decodes in your browser rather than uploading your image — it is the right tool for a code in a saved image or on a computer screen. Scanner apps are the weakest default for everyday scanning: they add an install, a permission screen, and often ads or an account, in exchange for a capability your phone already has.

The exceptions are real but narrow. A phone old enough to lack a built-in reader needs an app or a browser scanner. A person who scans codes all day for work — inventory, tickets, asset tags — may want a history, bulk reading, or exports, and a dedicated tool can justify itself there. And a code in a saved image on a phone whose gallery tools do not offer a reader may need a browser decoder, which is a better answer than an app for a single code. For everyone else, the case against an app is concrete: many scanner apps show ads, and some ask for permissions far beyond the camera — contacts, location, or an account that ties your scanning history to an identity. A scanner that knows every menu, ticket, and poster you have ever pointed it at knows a great deal about your movements, and that knowledge is the product being sold when the app itself costs nothing. The built-in camera reads the code and moves on; it does not keep a diary of your scans.

When the scan works but the destination does not

Sometimes everything above goes right and the result still disappoints: a dead link, a moved page, a form that no longer exists, a ticket that has already been used. That is not a scanning failure; it is a destination failure, and the fix belongs to whoever issued the code. A static code holds its destination directly, so if the destination is gone, the code has nothing to say. If the destination moved, only the issuer can point the code somewhere new — which is exactly what a dynamic code is for: it stays editable after printing, with scan statistics, under a free account. If you are the scanner and the link is dead, do not keep rescanning; ask the sender for a fresh code.

Testing your own codes before anyone else scans them

If you print codes for other people — a menu, a poster, a ticket, a business card — test them the way your audience will scan them, not the way you made them. Scan the printed proof, not just the screen version, because print changes size, contrast, and sharpness. Scan it on two phones if you can, one iPhone and one Android, because a code that reads on one and not the other has a real problem hiding in its size, contrast, or quiet zone. Scan it in the light and from the distance where it will actually be used. Thirty seconds of testing per code saves a reprint, a queue of confused customers, and a poster that is decoration rather than a door.

Good to know

Do I need an app to scan QR codes?

No. iPhones and virtually all Android phones scan QR codes with the built-in camera. Third-party scanner apps are unnecessary for standard codes, and are a reasonable answer only for a phone with no built-in reader or for work that needs a history or bulk reading.

What happens after I scan a QR code?

It depends on what the code holds: a link opens a web page, a Wi-Fi code offers to join a network, a contact code offers to save a person, a text code shows words, and an event code offers a calendar entry. Your phone's preview tells you which kind it is before anything opens.

How do I scan a QR code that is on my own phone's screen?

Screenshot the code or save the image, then read it from the image: on iPhone, open it in Photos and press and hold the code; on Android, open it in Google Photos and tap Lens. A camera cannot point at its own screen.

Why won't my camera scan the QR code?

Work the fault chain in order: whole code in frame, normal photo view, scanning switched on, steady focus, good light without glare, clean lens, intact corner squares and contrast, and size for the distance. Finish with a second-phone test: if another phone reads it, the problem is your phone; if none does, it is the code.

What is the difference between a QR code and a barcode?

A QR code is the square pattern with three large corner squares, which are the reader's landmarks. A pattern without those corner squares is not a QR code, and no QR reader will read it.

My QR code scans, but the link doesn't work. Is the code broken?

No. The code did its job; the destination is the problem — the page moved, the site is down, or the form no longer exists. Contact the sender for a fresh code, or, if you issued it, use a code whose destination you control or a dynamic code that stays editable.

Is it safe to scan a QR code I find in public?

Read the preview before you tap: the domain should match the sign in front of you, the code should show no tampering such as a sticker pasted over another code, and you should have expected this code in this place. Failing any one of those checks is enough to stop.

How do I test a QR code I printed before other people scan it?

Scan the printed proof, not just the screen version, on two phones if you can — one iPhone and one Android — in the light and from the distance where it will actually be used. A code that reads in all of those conditions has its size, contrast, and quiet zone right.
