QR codes for events, done right

Check-in lines, ticket chaos, 'where are the photos?' — a few well-placed QR codes solve the recurring event headaches. Here's the playbook.

October 14, 2026 · Last updated: November 3, 2026 · 4 min read

Check-in lines, ticket chaos, “where are the photos?” — a few well-placed QR codes solve the recurring event headaches. The trick is not the code itself; it is matching each code to one moment in the guest's journey, and choosing static or dynamic for each moment deliberately. A code on the invitation does a different job from a code on the exit sign, and printing the wrong kind in the wrong place is how events end up with a wall of codes nobody scans.

Start from the guest, not from the technology. A guest meets your event in roughly five moments: they hear about it, they commit, they arrive, they take part, and they leave. Each moment has one question — when is it, am I in, where do I go, what is happening, what did I think — and each question has a code that answers it in one scan.

The pattern in that table is the whole strategy: anything that might change after printing goes dynamic, and anything fixed goes static. A static code never expires — right for a keepsake invitation, wrong for an agenda that will be edited the morning of the event.

Before the event: invitations, calendar, and RSVP

The invitation is where most event codes fail, because organizers print a code that leads to a homepage and expect guests to find the RSVP form themselves. Link the code to the form, not to the site. Build your RSVP form first — a simple form tool works fine — then generate the code, print it on the invitation suite, and guests scan, tap, and respond. No stamps, no lost reply cards, no deciphering handwriting. After the responses roll in, the form tallies them automatically, meal choices included; export to a sheet, share it with the caterer, and the admin is done.

Pair the RSVP code with an add-to-calendar code, the most underused event code there is. One scan drops the event — title, start and end time, location — straight into the guest's calendar on both iPhone and Android. Print it on the invitation, and one less step sits between the invite and the calendar, which may mean fewer no-shows. A wedding invitation suite is the classic case: the RSVP code goes on the details card, the calendar code beside it, and the photo album code waits for the table cards. The same invitation trick works for holiday parties — see the Christmas QR code generator.

Word the invitation code the way you would word an instruction to a stranger. Print exactly what to do next to the code: “Scan to RSVP by June 1st.” Older guests may need the nudge, and the truly scan-averse still need a phone number on the invitation. Every code should sit beside a short printed alternative — a link or a phone number — so a guest with a dead battery, no signal, or no camera phone is not locked out.

Tickets: one code per ticket, and what that really means

For ticketed events, link each ticket to its own validation page rather than printing one shared code on every ticket. A shared code cannot tell one ticket from another, so it cannot catch a ticket scanned twice — and a screenshot of a shared code is a free ticket for anyone who receives it.

Batch generation turns a list of ticket links into a set of codes in one download. Name the files by ticket or guest and test-scan a sample before sending. At the door, the check-in team needs one thing above all: a fallback. Phones die, screens crack, and screenshots arrive too dim to read. Keep a printed guest list at the entrance, and train the door team to check a name when a code will not read.

At the door: check-in without the clipboard queue

Put a code on the confirmation email linking to a check-in form, or to a simple “I'm here” page. Guests scan at the door instead of spelling their names for a volunteer with a clipboard. For a small event, that form can be as simple as a name field and a submit button.

Three details make door check-in work. First, print the entrance code large and at chest height, where a guest holding a phone naturally points it — not on a table where people queue behind it, and not on a swinging door. Second, give the door team a second way in: a printed link and the guest list on paper. Third, decide before doors open what happens when a code has already been used. A ticket scanned twice is either a returning guest or a screenshot doing the rounds; the door team needs a rule, not a debate in front of a queue.

During the event: agenda, speakers, WiFi, and the photo wall

Agenda and speaker bios

A code on the program — or in the footer of each session slide — linking to the live agenda page saves you from reprinting the program every time a session moves rooms. This is the strongest case for dynamic codes at an event: the printed pattern stays the same while the destination changes from your Dashboard. Speaker bios work the same way.

Venue WiFi

Attendees will ask for WiFi. A WiFi QR code on signage connects them in one scan — no password spelling over loud music, no queue at the help desk. Put it where people first look for it: the entrance, the registration desk, and the tables, not only on a slide that disappears after thirty seconds. One honest trade-off: anyone who photographs the printed code can join the network, so treat a venue WiFi code like a guest key.

The shared photo album

Every event has the same problem: the photos scatter across fifty phones, and the organizer spends the next week begging for them. A code linking to a shared album on table cards fixes it — guests upload their shots in one tap, all night, into one place. Print it on the table cards, on a photo wall sign, and on the closing slide, where guests see it when they take a photo. Check the album's sharing settings before the event: anyone with the link can usually add to a shared album. If the album is meant for guests only, keep the code inside the room rather than on a public event page.

After the event: feedback while it is still fresh

A code linking to a short feedback form on the exit signage or the closing slide catches guests while the event is still fresh, instead of competing with a follow-up email days later that most guests will ignore. Keep the form to two questions: one rating and one open box for what to change. A ten-question survey at the exit gets abandoned; a two-question form gets answered on the walk to the car. The thank-you email the next day can carry the same code again, plus the photo album link, for guests who left too quickly.

After the event is also when the static-versus-dynamic choice pays off a second time. A dynamic code on a reusable sign can be repointed at the next event's feedback form, so the sign never needs reprinting. A static code on a keepsake keeps working for years as a memento. Decide which kind of afterlife each sign should have before you print it.

A practical rule: use dynamic codes for everything the event team controls on the day — agenda, check-in, feedback — and static codes for everything the guest keeps — invitations, calendar entries, photo albums that should outlive the event. If anyone might need to change where a code points after it is printed, make it dynamic.

Printing and testing: the unglamorous part that decides everything

Event codes get scanned in chaotic lighting by hurried people. Print for that reality, not for a design mockup:

  • Go bigger than you think. The 1:10 distance rule of thumb is a good starting point: a code scanned from a metre away needs to be roughly ten times larger than one scanned from ten centimetres. Size each one for its actual distance.
  • Keep contrast high and the margin clear. Dark ink on a light background, with a clear quiet margin around the code. A code printed over a busy photo, or in brand colours with low contrast, is the most common reason an otherwise fine code fails at an event.
  • Print for damage. Tickets get folded, table cards get spilled on, outdoor signs get rained on. The QR standard, ISO/IEC 18004:2024, defines four error-correction levels — L, M, Q, and H — recovering 7%, 15%, 25%, and 30% of the symbol's codewords respectively, so a code with a higher level keeps scanning after more of it is damaged. Use a higher level for anything guests will handle, and keep logos small and centred so they do not eat into that margin.
  • Test on both iPhone and Android before printing a hundred of anything. The built-in camera on modern phones reads codes with no app needed — Apple's support page describes opening Camera or the Control Center scanner, holding the phone so the code appears in frame, and tapping the link that appears — but camera behaviour varies between models, and a code that scans on one phone in bright light may fail on another in a dim hall. Test the actual print, at the actual size, in lighting like the venue's.
  • One code per sign, with a label. Two codes side by side make guests hesitate and cameras pick the wrong one. Label every code with what it does — “Scan for WiFi,” “Scan for photos” — because a bare code at an event is a code guests walk past.

One more number worth knowing before you plan around phones: in Pew Research Center's 2026 survey of United States adults, 91% said they owned a smartphone, up from 35% in the Center's first such survey in 2011. That is a United States figure, from a survey of 5,511 adults conducted from January 30 to June 18, 2026 — not a global rate, and not a promise about your particular guest list. Its practical meaning is modest: for most audiences, planning around phone cameras is planning around the device nearly everyone already carries, while still keeping a printed alternative for the rest.

What can go wrong — and the fix for each

  • A code leads to a page that moved. Fix: dynamic codes for anything the team might move, and a final link check the morning of the event, from a phone, on the venue's network.
  • Guests cannot connect because the WiFi code is on one slide. Fix: WiFi codes on permanent signage at the entrance and the tables, not only on a slide.
  • The photo album fills with uploads from strangers. Fix: keep the album code inside the room, check the sharing settings before doors open, and change the album link after the event if the link escaped.
  • A ticket screenshot does the rounds. Fix: one code per ticket, a rule for second scans at the door, and the paper guest list as backup.
  • Older guests or guests without smartphones are stranded. Fix: a phone number on the invitation, a paper list at the door, and a printed agenda beside the code. The code is an additional route, never the only one.

Event code checklist

  • Check-in: a code on the confirmation email, scanned at the door.
  • Add-to-calendar: on the invitation, so guests keep the date.
  • RSVP: on the details card, linking to the form.
  • Tickets: one code per ticket, batch-generated, test-scanned before sending.
  • Agenda and speakers: on the program and slide footers, dynamic.
  • Photo album: on table cards, so shots land in one shared album.
  • Venue WiFi: on signage, so nobody spells the password over loud music.
  • Feedback: on exit signage and the closing slide, while the event is still fresh.

Put together: one code per guest question, dynamic where things change, static where things should last, each code labelled, tested, and backed by a printed alternative. Good to know

How do I make a QR code for event check-in?

Link the code to your check-in form or registration page, print it for the entrance, and guests scan on arrival instead of queueing at a desk. Keep a printed guest list beside the scanner as a fallback for phones that die or screens that will not read.

Can a QR code add an event to my calendar?

Yes — calendar (VEVENT) QR codes open an 'add to calendar' prompt on iPhones and Androids. FreeQrly generates them free with its event type: title, start and end time, and location in one scan.

What QR codes do I need for an event?

At minimum: check-in/registration, a shared photo album, and venue WiFi. Add-to-calendar codes on invitations are the high-value extra. For conferences, add agenda and speaker codes; for ticketed events, add one code per ticket.

Should event ticket codes be static or dynamic?

One code per ticket, and dynamic when a ticket can be transferred or cancelled or when the validation page might change — a dynamic code can be repointed without reprinting the ticket. A simple, non-transferable ticket with a final validation page can use a static code. Never print one shared code on every ticket: it cannot tell one ticket from another.

What if a guest's ticket code will not scan at the door?

Check the name against the printed guest list instead of turning the guest away. Phones die, screens crack, and screenshots arrive too dim to read. Decide before doors open what the door team does when a code has already been used — a returning guest or a screenshot doing the rounds needs a rule, not a debate in front of a queue.

Can I reuse event signage for the next event?

Yes, if the codes on it are dynamic. A dynamic code on a reusable sign can be repointed at the next event's feedback form or agenda, so the sign never needs reprinting. Static codes are better for keepsakes — invitations and printed programs that should keep working for years.

How big should event QR codes be printed?

Size each code for its actual scanning distance, using the 1:10 distance rule of thumb from the print size guide: a code scanned from a metre away needs to be roughly ten times larger than one scanned from ten centimetres. Keep contrast high, leave a clear quiet margin, and test the actual print on both iPhone and Android in lighting like the venue's before printing a full run.
