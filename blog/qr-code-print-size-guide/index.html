How big should a printed QR code be?

The short answer: at least 2x2 cm, at 300 dpi, with a clear margin. The longer answer — with the distance rule of thumb printers actually use — is below.

October 14, 2026 · Last updated: November 3, 2026 · 15 min read

The short answer: at least 2 × 2 cm, at 300 dpi, with a clear margin. The longer answer — the one that keeps a poster scannable from across a room and a business card scannable from a handshake — is two rules of thumb plus a table. Rule one: never print a code smaller than 2 × 2 cm (0.8 × 0.8 in). Rule two: the code's width should be at least one-tenth of the scanning distance. A code scanned from 50 cm needs a 5 cm code; a poster scanned from 5 meters needs a 50 cm code. Everything below works those two rules out for every surface you are likely to print on, plus the format, margin, and proofing details that decide whether the size actually works.

The two rules that matter

Rule of thumb 1 — minimum size: 2 × 2 cm (0.8 × 0.8 in). Below that, phone cameras cannot resolve the modules reliably, especially codes holding a lot of data like vCards. This is a practical minimum for close, hand-held scanning, not a guarantee: a dense code at 2 cm is far more fragile than a short-URL code at the same size, and older phones need more room than new ones.

Rule of thumb 2 — the 1:10 distance ratio: the code's width should be at least one-tenth of the scanning distance. Scanning from 50 cm (a table card)? 5 cm code. From 5 meters (a poster)? 50 cm code. Printers and signage folks use this ratio as a rule of thumb — it is a planning guideline, not part of the QR standard itself — and the safe habit is to round up rather than down, because distance, lighting, and glare all eat into the margin of safety.

Those two rules interact. The 1:10 ratio can demand less than the 2 cm minimum — a code scanned from 15 cm would only need 1.5 cm by the ratio — and in that case the minimum wins: print 2 cm anyway.

The distance rule, worked out

To work out a size, divide the distance people will scan from by ten, then round up — and never below the 2 cm minimum. A few worked examples make the habit automatic:

The distance to use is the distance people will actually stand at, not the distance you wish they would. A poster in a corridor is scanned from the corridor's width; a sign across a car park is scanned from where people walk, not from the far fence.

Why data density changes the answer

Not all QR codes have the same number of modules. The more data you put in, the more modules the code needs: the smallest code (Version 1) is 21 × 21 modules, and each version up adds four modules per side, to a maximum of 177 × 177. Printed at the same size, a denser code has smaller modules, and smaller modules are harder for a camera to separate — especially in poor light.

Error correction adds the same trade-off. Higher levels are more robust, which is useful for codes with a logo or on surfaces that may get scuffed, but they also add modules. As a rough example, a 40-character web address fits in a 29 × 29 code at level M, but needs 37 × 37 at level H; on a 2 cm code, that shrinks each module from about 0.69 mm to about 0.54 mm. The practical takeaway: keep the content short. Use a short, clean URL instead of a long tracking link, include only the vCard fields you actually need, and if a small printed item must hold a lot, make the code bigger. A dynamic code helps differently: its destination is editable after printing, so you can print a short redirect once and change where it points later, instead of encoding a long URL that forces a dense grid — and it carries scan statistics, so you can see whether the size you chose is actually getting scanned.

Resolution: export big

Print needs 300 dpi. A 2 cm code at 300 dpi is only about 240 px — but always export larger and let the designer scale down: PNG at 1024 or 2048 px, or SVG, which is infinitely scalable and the best choice for professional print. FreeQrly exports both, free. The pixel math is simple: divide a PNG's pixel width by 300 to get its maximum print width in inches, and multiply by 2.54 for centimeters. A 600 px image gives 2 inches, about 5 cm, at 300 dpi — fine for a table card, far too small for a poster. A 2048 px image gives about 17 cm at 300 dpi, which covers flyers, menus, and small posters, but not a shop window; for that, use SVG.

For very large formats viewed from a distance, printers commonly accept lower effective resolutions — around 150 dpi is a workable benchmark for large posters — because the eye cannot resolve fine detail from meters away. Two format rules do not bend with size. Avoid JPG for QR codes: its compression blurs the sharp module edges a scanner depends on. If you must enlarge a PNG, use nearest-neighbor scaling (sometimes called "hard edges" or "no smoothing") by a whole number such as 2×, 3×, or 4×, which keeps every module a crisp block instead of a soft blur. Better still, import the SVG and re-export at the required resolution rather than stretching a small PNG.

Don't forget the quiet zone

Leave a blank margin around the code at least 4 modules wide on every side, as specified in ISO/IEC 18004. Crowding it with text or graphics is one of the top reasons codes fail — more in why your code won't scan. A module is one small square of the grid, so the physical margin depends on the code: count the squares across your code, work out how wide one module is, and leave four of those widths clear on every side. For a 2 cm code with 29 modules across, one module is about 0.7 mm, so you need about 2.8 mm of clear space all round — and that margin must be the same light color as the code's background, not a frame, a crop mark, or a fold.

The quiet zone is also where layout software quietly sabotages you. A design tool that crops an image to its visible pattern, a printer's bleed that trims the margin, or a frame drawn tight around the code can each eat the margin after you set it correctly. Check the margin on the final artwork, not just in the generator, and remember the margin is part of the footprint — a 2 cm code with its quiet zone needs more than 2 cm of clear space on the card.

On screens: pixels instead of centimeters

Print sizes do not translate directly to screens, because a screen's physical size varies. The working rule of thumb for screen display is not to go below about 200 × 200 pixels, with more being better — people usually hold their phones at arm's length when scanning, and a small on-screen code competes with glare and room light. For slides and projected displays, the distance rule takes over: estimate how far the furthest viewer sits, divide by ten, and make the projected code at least that wide. A code that looks generous on your laptop can be tiny on a hall wall,.

Materials and surfaces: where good sizes go wrong

Size is only one part of a reliable printed code, and the surface can undo a perfect size. Glossy laminates cause glare; a matte finish is usually safer for signs and menus, and a table code under a restaurant spotlight should be tested under that spotlight, not office lighting. Curved surfaces distort the grid — a code wrapped around a small bottle reads worse than the same code flat, so use a flat panel or print larger. Textured card and thermal receipt paper blur fine detail, which is why receipts need short URLs and a test on the actual printer. On dark stock, print the code on a white patch. Outdoors, print larger and use a higher error-correction level.

Common print mistakes

  • Printed too small. The code looks fine in the design file and fails in the hand, because each module is a fraction of a millimeter wide. Size up or shorten the content.
  • Stretched or squashed. Dragging one corner without locking proportions distorts the finder patterns — the three large corner squares scanners use to locate the code.
  • Upscaled from a small, blurry PNG. Normal smoothing turns crisp edges into grey blur. Use SVG, or nearest-neighbor scaling.
  • Cropped quiet zone. Text, borders, or a tight crop running into the margin stops the scanner finding the code's edges.
  • Low contrast. Brand colors that look elegant on screen can fail in print, where ink and paper shift the tones. Dark code on a light background, always — and check the printed proof.
  • Logo too big for the print size. A logo code needs a 3 × 3 cm minimum in print, not 2 × 2 cm, and the logo should stay under about 30% of the code area. The logo guide covers the trade-off.
  • Never proofed. The most expensive mistake, because it turns every item above from a fixable detail into a reprint.

Preflight checklist before you send the file

  1. Format: SVG for professional print and anything large; PNG at 1024 or 2048 px if the printer needs raster, never JPG.
  2. Size: the larger of the 2 cm minimum and distance ÷ 10, rounded up, checked against the real scanning distance.
  3. Density: short URL, only the needed fields, and a larger print if the grid looks dense.
  4. Quiet zone: at least four modules of clear, light margin on all four sides, confirmed on the final artwork.
  5. Contrast: dark modules on a light background, verified on the printed proof, not just the screen.
  6. Finish and surface: matte where glare is a risk, flat panels on curved objects, a white patch on dark stock.
  7. Proof: one copy at final size, on the final material, scanned with more than one phone in the lighting where it will be used, plus a check that the destination opens on mobile data.

The honest comparison: print versus screen, static versus dynamic

Print and screen reward opposite habits. On screen, a code can be regenerated in seconds and tested instantly, so a small or experimental code costs nothing to fix. In print, every fix is a reprint, which is why print demands the conservative choices: SVG over PNG, the larger size, the full quiet zone, the proof scan. Treating a print file like a screen file — export small, crop tight, skip the proof — is how good designs become dead squares on a finished run.

The static-versus-dynamic choice matters in print for a different reason: what happens after the run. A static code encodes its destination directly, needs no sign-up, carries no watermark, and never expires — ideal for a fixed destination such as a homepage or a product manual. A dynamic code encodes a redirect, so its destination can be edited after printing and it carries scan statistics; that is the right choice when the destination may change, or when you need to know whether the size and placement you chose are working. What a dynamic code cannot do is rescue a badly sized print: editing the destination does not fix modules too small to read. Size the print correctly first.

One more comparison is worth making plainly, because it decides budgets: a bigger code is nearly free, and a reprint is not. Going from 2 cm to 3 cm on a business card costs nothing in print; reprinting a thousand cards costs the whole run. When the size decision is close, the larger size is almost always the cheaper choice — and a code with unlimited scans behind it stays useful however popular it becomes.

Good to know

What is the minimum size for a printed QR code?

As a rule of thumb, 2 × 2 cm (0.8 × 0.8 in). Smaller codes fail on many phones, especially for data-heavy codes like vCards.

How big should a QR code be on a poster?

Use the 1:10 rule of thumb: the code width should be at least one-tenth of the expected scanning distance. A poster scanned from 5 meters needs a 50 cm code.

PNG or SVG for print?

SVG is best — it scales infinitely with no quality loss. If your printer needs raster, export PNG at 2048 px. Never use JPG: its compression blurs the module edges a scanner depends on.

How much margin does a QR code need?

A quiet zone at least 4 modules wide on every side, in the same light color as the code background, as specified in ISO/IEC 18004. For a 2 cm code with 29 modules across, that is about 2.8 mm all round.

How do I work out the size for a scanning distance?

Divide the distance by ten and round up, never below the 2 cm minimum. A code scanned from 2 meters needs at least 20 cm; from 10 meters, at least 1 meter.

Does a longer URL need a bigger print?

Yes. More data means more modules, and more modules at the same print size means smaller modules that are harder to read. Use a short, clean URL, or a dynamic code whose short redirect destination you can edit after printing.

What size should a QR code be on a screen?

As a rule of thumb, not below about 200 × 200 pixels. For slides and projected displays, apply the 1:10 ratio to the projected width and the furthest viewer's distance.

Why does my printed code fail when the screen version scans?

Common causes are a cropped quiet zone, glare on gloss laminate, ink spread on textured stock, a stretched grid, or a PNG upscaled with smoothing. Proof one copy at final size, on the final material, and scan it with more than one phone before the full run.
