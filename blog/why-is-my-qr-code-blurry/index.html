Why is my QR code blurry?

A blurry QR code is almost always a resolution problem: too few pixels stretched across too much space. The fix is to export bigger — or as SVG.

October 17, 2026 · Last updated: November 3, 2026 · 15 min read

A blurry QR code is almost always a resolution problem: too few pixels stretched across too much space. The fix is to export bigger — or as SVG. If the code looked sharp on screen and turned to mush on paper, the image did not have enough pixels for the size it was printed at. A QR code is a grid of tiny squares called modules; when there are not enough pixels, their edges smear into each other, phones cannot find the grid, and scans fail. Start with the export, not a new design: regenerate at higher resolution or as a vector file, reprint one copy at the real size, and scan it at the real viewing distance before printing the batch.

That answer covers most cases, but blur has more than one cause, each with a different fix: a small export, JPEG compression, stretching, printer or paper, or a copy of a copy. The sections below separate those causes, give you a numbers table for the printer, walk through the fix in order, and cover codes that look sharp yet still will not scan — those belong to why your QR code will not scan.

What blur actually does to a code

A phone camera does not read a QR code the way a person reads a picture. It looks for the three large square finder patterns in the corners, works out the grid from them, and then decides, module by module, whether each small square is dark or light. Blur attacks exactly that decision: when neighbouring modules bleed into each other, the camera sees grey where it needs black or white, and it starts guessing. A little guessing is survivable, because QR codes carry built-in error correction — extra data that lets a reader rebuild codewords that come back wrong or unreadable. That protection is measured in codewords, not visible area: the four levels in ISO/IEC 18004 restore approximately 7% of codewords at level L, 15% at M, 25% at Q, and 30% at H. A smudge over a finder pattern, or blur spread across the whole symbol, can defeat a reader long before any neat percentage suggests it should survive. Treat error correction as a safety net, never as permission to print a soft code.

Density makes blur worse. A short link produces a roomy grid with large modules; a long link, a full contact card, or a Wi-Fi code with a long password produces a denser grid with smaller modules, and smaller modules blur sooner. That is why the same export can look fine for a short URL and fail for a data-heavy code at the same print size. If a code is both dense and printed small, shorten the destination where you can, print larger, or both. A dynamic code helps differently: the printed pattern encodes a short link you can redirect later, so the grid stays roomy even if the final destination is long. For a destination that will never change, a static code is simpler: free, no account, no watermark, and it does not expire.

The numbers: print size, pixels, and format

Printers talk about resolution in dots or pixels per inch. For close-viewed print, 300 pixels per inch at the final print size is the widely used professional baseline for sharp output. The table below turns that baseline into pixel counts: print width in inches multiplied by 300. A 2 cm code is about 0.8 inches wide, so it needs roughly 240 pixels at 300 pixels per inch — and that is the bare minimum, not a comfortable margin. Always export larger than the minimum and let the designer scale down, because scaling down preserves sharpness while scaling up only enlarges the blur.

Two rules of thumb sit behind that table. First, the print size in centimetres, multiplied by roughly 100, gives a quick pixel target — a 5 cm code wants around 500 pixels at minimum, a 10 cm code around 1,000. Second, the 1:10 distance rule of thumb from the print size guide: the code width should be at least one-tenth of the scanning distance, so a code scanned from 50 cm should be at least 5 cm wide, and a poster scanned from 5 metres needs a 50 cm code. A poster code viewed from metres away can tolerate a lower effective resolution than a card held in the hand, but it still needs enough pixels for its size — and only a vector file gives you that without a ceiling.

The 5 usual causes, in detail

1. Low-resolution export

This is the most common cause, and the most forgiving to fix. A 512 px PNG looks fine at 2 cm wide; blown up to a 20 cm poster, each module becomes a smudge, because the same 512 pixels now cover ten times the area. The screen hides the problem — a display shows the code small, so the pixels look tight — while paper shows it at true size. The fix is at the source: re-export at 1024 px for cards and flyers, 2048 px for posters, or SVG whenever the printer accepts it. Enlarging the small file in an editor does not add detail; it only makes the existing blur bigger. If the original export is gone, regenerate from the same destination rather than stretching the file you have.

2. JPEG compression

JPEG is built for photographs, and it works by discarding detail the eye is least likely to notice in a photo. That trade is poor for a QR code, which is nothing but sharp edges and flat areas — exactly the features JPEG smears. A code saved as a low-quality JPEG can fail even at small sizes, and the damage worsens every time the file is re-saved as JPEG. PNG uses lossless compression, preserving every pixel exactly, and SVG has no pixels to lose. The rule is simple: PNG or SVG only. If a designer, chat app, or social platform hands you back a JPEG version, treat it as a preview, not print artwork, and replace it with the original PNG or SVG before printing.

3. Stretching

Dragging one corner distorts the grid: squares become rectangles, module spacing changes unevenly, and scanners give up. This happens most often in slide decks, word processors, and page-layout tools, where an image is dragged to fill a gap. Always resize proportionally — hold Shift, or use the lock icon, so width and height change together and the squares stay square. A code stretched and then stretched back is not automatically square again, because rounding in the layout tool can leave it slightly off. When in doubt, delete the placed image and place a fresh export at the intended size.

4. Bad print: printer, ink, and paper

Low-resolution printers, ink bleed on rough or absorbent paper, and glossy glare all soften edges. An inkjet on uncoated, absorbent stock lets ink spread into the fibres, so thin white gaps between modules fill in and the code looks bold and muddy. A laser printer on smooth or coated stock holds edges far better, which is why matte paper and a laser printer beat an inkjet on a napkin. Glossy lamination is different: the paper can stay sharp yet throw reflections back at the camera — tilt the print under the light to tell glare apart from blur. For fabric, embroidery, engraving, or very rough surfaces, expect edges to soften regardless, and compensate with a larger code, higher error correction, and a physical test first.

5. Copy of a copy

Screenshotting a code from a message, then screenshotting that screenshot, loses resolution each time. Messaging apps also recompress and downscale images, so a code forwarded through chat can arrive far smaller and softer than the original export. Photographing a printed code to reuse it adds perspective distortion, uneven light, and lens softness on top of the original print. Always go back to the original export, or regenerate from the same destination. If the destination is a dynamic code, generate a fresh code for the same short link — no old file needed.

How to fix it, step by step

  1. Find the original file. If you only have a JPEG, a screenshot, or a forwarded chat image, stop and regenerate — no edit restores detail compression already threw away.
  2. Export at the right size. PNG at 1024 px for cards and flyers, 2048 px for posters, SVG whenever the printer or designer accepts it. Above about 20 cm, SVG is the only format that keeps edges exact without an enormous file.
  3. Use PNG or SVG, never JPEG. PNG for screens and office printing, SVG for professional print. If a tool insists on JPEG, use its highest quality setting for a screen preview only, never as the print master.
  4. Keep proportions when resizing. Hold Shift or the lock icon so the squares stay square. Place the image at the final size, rather than placing it small and stretching it later.
  5. Keep the code dark on light, with a clear margin. Blur and low contrast compound each other: a grey code on a pale background that is also soft fails sooner than either fault alone. Keep a blank margin at least 4 modules wide on every side, as specified in ISO/IEC 18004, and keep text, logos, and decorative borders out of it.
  6. Match paper and printer to the job. Smooth or coated stock and a laser printer for small codes; matte finish where glare is a risk; larger size and higher error correction for rough or textured surfaces.
  7. Test-scan the real print. Print one copy at final size, step back to the real viewing distance, and scan it in the real lighting. A first-try scan means the batch is safe. If it hesitates, fix the export or the size now — a run of soft codes cannot be rescued afterwards.

Scenarios: where blur bites hardest

Flyers, menus, and table tents

These are scanned at arm's length, often in dim rooms, so they need both sharpness and size: at least 3 cm on a flyer or menu, 4–5 cm on a table tent as a rule of thumb. Menus add lamination risk: gloss under overhead lights can glare, while matte laminate keeps the code readable and wipes clean. For a menu that changes, link to a page you control rather than a screenshot, so the print never goes stale — and a dynamic code lets you change that destination after printing, with scan stats to show which tables actually scan.

Posters and signage

Posters fail differently: the export is usually the problem, not the printer. A 512 px file that looked fine on screen becomes visibly soft at 20 cm or 50 cm, and no printer can invent the missing pixels. Use SVG, apply the 1:10 distance rule of thumb, and proof the code panel at full size before the run. Outdoors, allow for fading too: a code that starts sharp but fades in sun drifts towards failure over weeks, so a higher error-correction level and a sheltered position matter more than a marginally sharper first print.

Packaging and labels

Small labels combine small size, dense data, and curved or textured surfaces. Keep the code at 2 cm or larger as a rule of thumb, avoid wrapping it around a tight curve where edge modules stretch, and test on the actual container — a code that scans flat can fail on a bottle. If the material is rough or printing coarse, print larger and simpler: a short link keeps the grid roomy, including a short link behind a dynamic code.

Honest comparison: what fixes blur, and what does not

Not every sharpening trick works, and some popular advice wastes a print run. Upscaling a small file — in an editor, with an enlarger tool, or by exporting the same small image larger — does not add detail; it interpolates between the pixels you already have, so edges stay soft, only bigger. A sharpening filter can make edges look crisper to the eye while adding halos that confuse a camera, so a filtered code can scan worse. Converting a JPEG to PNG does not undo JPEG damage either: the format changes, but the smeared pixels stay smeared. The only reliable repair is a fresh export from the original data at higher resolution, or as SVG.

Format choice has its own trade-offs. SVG is the best choice for print, but some office tools, older apps, and social platforms do not accept it — in those cases a high-resolution PNG is the right fallback, not a reason to fall back to JPEG. PDF can be a good carrier for print because it can hold the vector code, but only if the code inside the PDF is actually vector; a PDF with a small JPEG pasted inside it is just a JPEG with a fancier wrapper, so check what is inside before trusting the file extension.

Finally, sharpness is necessary but not sufficient. A perfectly sharp code can still fail if it is too small for its distance, if contrast is weak, if the quiet zone is crowded, if a logo covers too much of the centre, or if the destination itself is dead. Those are diagnosis questions, covered in order in the full troubleshooting guide. Good to know

Why does my QR code look blurry but still scan?

Phones are forgiving — error correction rebuilds codewords that come back wrong or unreadable. But a code that scans in a bright office may fail in dim light or at arm's length. Sharp is safe; barely scanning is not.

What resolution do I need for a poster?

SVG is the best choice, because it scales without limit. If the printer needs a raster file, use PNG at 2048 px; a poster at 20 cm needs roughly 2,360 px at 300 pixels per inch, so a 512 px export will look soft at that size.

PNG or SVG for print?

SVG whenever the printer or designer accepts it — it scales infinitely with zero blur. PNG at 1024 px for cards and flyers, or 2048 px for posters, is the fallback for office printing and apps that do not take SVG.

Can I fix a blurry printed code without reprinting?

No. The blur is baked into the printed image. Reprint from a higher-resolution export (or SVG). Editing a dynamic code will not help — the pattern on paper is what it is, even though a dynamic code lets you change the destination behind a fresh print.

Why does the same export look fine on screen but soft in print?

A screen shows the code small, so its pixels look tight. Paper shows the code at its true size, so the same pixel count spread over centimetres reveals the blur. Check the export against the print size before sending it to print.

Will upscaling or a sharpening filter fix a blurry code?

No. Upscaling interpolates between the pixels you already have, so edges stay soft, only bigger. A sharpening filter can add halos that confuse a camera, and converting a JPEG to PNG does not undo JPEG damage. The only reliable repair is a fresh export from the original data at higher resolution, or as SVG.
