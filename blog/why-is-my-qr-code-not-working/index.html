Why won’t this thing scan?

A QR code that won't scan is almost never a mystery. Run through these seven checks — in order — and you'll find the culprit in about two minutes.

October 14, 2026 · Last updated: November 3, 2026 · 15 min read

A QR code that will not scan is almost never a mystery. Run through these checks — in order — and you will find the culprit in about two minutes. Before you change anything, split the problem three ways: the phone, the printed or displayed code, and the destination. Scan with a second phone. If it reads the code, the first phone, its camera, or its lighting is the problem. If no phone reads it, the code itself — size, contrast, margin, damage, or logo — is the problem. If phones read it but the link goes nowhere, the code is doing its job and the destination is the problem. That three-way split saves most people a pointless reprint, because each branch has a different fix.

The two standards that explain most failures

Two ideas from ISO/IEC 18004, the QR code symbology specification, explain a surprising share of scan failures. The first is the quiet zone: a blank margin at least 4 modules wide on every side, where a module is one small square of the grid. Scanners use that border to find where the symbol begins and ends, so text, graphics, or a crop invading it can make a perfect code invisible to a camera. The second is error correction: extra data that lets a reader rebuild codewords that come back wrong or unreadable, at four levels — L approximately 7%, M approximately 15%, Q approximately 25%, H approximately 30%. Those percentages describe codewords, not visible area: a torn finder pattern can kill a code well inside its level, while scattered minor damage elsewhere may survive. Higher levels are not free either: more recovery data means a denser grid, so raising the level on an already-small code can make it harder to read. Raise it for a reason — a logo, rough handling, outdoor use — then re-check size and test-scan.

Step 1: rule out the phone

Wipe the lens. A smudged lens is behind an embarrassing number of supposedly broken codes, because a thin film of grease softens the whole image just enough to blur module edges. Then test on a second phone: if phone B reads it, the code was never the problem. The whole square must be in frame, with a little room around it — a code cropped by the viewfinder edge will not read. Hold still once the code fills about half the viewfinder, and move to better light in dim conditions. A code that shows a preview but goes nowhere when tapped has a destination problem (Step 9), not a scanning problem.

Step 2: size and distance

The classic failure is a code squeezed into a business card corner at 1 cm wide. As a rule of thumb, printed codes need at least 2 x 2 cm (about 0.8 inches), and bigger is always safer. Size and distance follow the 1:10 distance rule of thumb: code width at least one-tenth of scanning distance — 5 cm for a table card scanned from 50 cm, 50 cm for a poster scanned from 5 metres. Below that rule for its distance, no cleaning, re-angling, or re-exporting will reliably fix it — reprint larger, or move the code closer to where people stand. The full breakdown by use case is in the print size guide. Density tightens the rule: a short link gives a roomy grid, while a long link, full contact card, or long Wi-Fi password gives a denser grid with smaller modules, needing a larger print. A dynamic code shortens the printed pattern without shortening the final destination, because it encodes a short link you control and can redirect later, with scan stats showing performance.

Step 3: contrast

QR readers look for dark modules on a light background. Light grey on white, brand pastels, a dark code on dark, or a code over a busy photo will fail — especially in dim light. Judge it in the light where the code will actually be scanned: if you squint to tell modules from background, a phone camera will struggle too. The fix is black on white, which always works, with the quiet zone in the same light background colour. Inverted codes — light modules on dark — are a special case: some readers handle them and many do not, so do not rely on inversion for public codes. If brand colours matter, keep them in the surrounding design and a small central logo, not in the modules, and test the coloured version in dim light first.

Step 4: the quiet zone

The blank margin around the code is not decoration — scanners need it to find the edges. Keep a clear border at least 4 modules wide on all four sides, as specified in ISO/IEC 18004, and keep text, rules, decorative borders, and nearby images out of it. This failure is common in designed layouts, where a headline, a rule, or a photo edge creeps into the margin, and at a page edge, where a code too close to the trim loses its margin. Check all four sides: a margin generous on three sides and zero on the fourth still fails. The fix is layout, not re-export — give the code room, or place it on a plain light panel that guarantees the margin inside a busy layout.

Step 5: damage, fading, and wear

Creased flyers, sun-faded posters, scratched stickers, rain-spotted labels: error correction can survive some damage, but location matters more than size. Damage to the three large corner finder patterns is the most serious, because without them the reader cannot find or orient the grid — a torn finder pattern is often fatal even when the rest looks intact. Scattered scuffs across the data area are far more forgiving, because that is what error correction is built to rebuild. Fading is slower damage: as dark modules lighten towards the background, contrast falls until the reader can no longer separate modules, even though the pattern is still there. Judge a worn code corners first, then contrast, then surface. The fix for a damaged print is a reprint; for a code that will live a hard life — outdoors, on packaging, on a vehicle — be preventive: higher error correction, a larger print, lamination or a sheltered position.

Step 6: logo obstruction

A logo in the centre eats into the pattern, consuming part of the error-correction budget by design — which is why it can work, and why it can fail. Judge it by how much of the grid the logo covers and whether it touches a finder pattern: a small logo cleanly centred, clear of the three corners, is safe; a large logo, one spreading towards the corners, or one with busy detail mimicking modules is risky. As a rule of thumb, keep the logo under about 30% of the code area, print logo codes at 3 x 3 cm or larger, and use error correction Q or H. Test the logo version specifically: a plain code that scans tells you nothing about its logo sibling. If a logo code fails, shrink the logo first, then enlarge the print, then raise the level, testing after each change. See how to add a logo to a QR code and the logo code generator.

Step 7: glare, curve, and angle

Glossy lamination under bright light, a code wrapped around a bottle, or a photo taken at a steep angle all distort what the camera sees. Glare washes modules out in patches; a curve stretches edge modules while compressing middle ones; a steep angle turns squares into trapezoids the reader must un-warp. Tilt the print slowly: if the unreadable patch moves with the reflection, it is glare. Flatten the surface if you can, and shoot straight on. Prefer a flat panel over a tight curve, matte over gloss where lights are strong, and a position people can face squarely. A bottle code that scans when turned to face the camera is a placement problem — move it to the flattest, most front-facing spot, and print it larger.

Step 8: sharpness — when blur is the culprit

If the code is the right size, high contrast, well margined, undamaged, and logo-free, yet still hesitates, look at the module edges: crisp or smeared? Low-resolution exports, JPEG compression, stretching, poor print, and copies of copies all soften edges, and soft edges fail first in dim light and at distance. The full diagnosis is in why your QR code looks blurry. Short version: re-export at 1024 px for cards and flyers or 2048 px for posters, use SVG whenever the printer accepts it, never use JPEG for a code, keep proportions when resizing, and test-scan one real print at the real distance first. Softness and weak contrast compound, so fix both rather than hunting for a single culprit.

Step 9: the destination is dead

Sometimes the code scans fine — but the link is broken, the page moved, the site is down, or a trial-based generator deactivated the code. This is the expired-link trap: nothing useful happens after the tap, so it feels like a scanning failure. Watch the link preview: if a preview appears, the code decoded and the destination is the problem. Check whether the page opens when typed directly into a browser, and whether the link was shortened by a service that has since changed its terms. Static codes never expire on their own — the destination lives inside the pattern, so a static code fails only if the destination itself goes away. Dynamic codes point at a short link you control, so a moved page is fixable without reprinting: sign in, change the destination, and the printed code works again, with scan stats to confirm it. That editability is also the trap to avoid when choosing a generator: a code tied to an ended trial can stop working even though the pattern is perfect — see do QR codes expire? before a large run. For codes already printed: static plus moved page means restore the page or reprint; dynamic means redirect it and test on two phones.

Scenarios: the same checklist, different culprits

A flyer that scans in the office but not at the event

Office light is kind; event light is not. The usual culprits are contrast that only just passes in bright light, a code slightly too small for the distance people stand at, and gloss under venue lights. Fix in order: test in the venue's light, enlarge the code, switch to matte, and return to black on white before reprinting.

A business card that scans for you but not for clients

Your phone knows the code; a stranger's phone meets it cold, in worse light, at a different angle. Check size first — below 2 cm as a rule of thumb fails on many phones — then the quiet zone, which card designs love to crowd, then the stock, which may absorb ink and soften edges.

A code on screen — slides, video, or social images

Screen codes fail on compression, size, and time. A code recompressed by a platform, shown small in a slide corner, or flashed briefly in a video gives the camera little to work with. Keep it large, flat to the camera, and on screen long enough to scan; for a code inside a photo, scanning from an image is the fallback.

Honest comparison: reprint, redirect, or redesign?

Not every failure deserves a reprint. If the destination moved and the code is dynamic, redirecting beats reprinting on cost, waste, and speed — the pattern stays valid and the fix takes minutes. If the code is static and the destination moved, redirecting is not an option: restore the destination or reprint, and choose dynamic next time if the destination may change again. If the pattern itself is at fault — too small, low contrast, crowded margin, heavy logo, soft print — no redirect will help, because the reader cannot decode the pattern; reprint with that parameter changed, one parameter at a time, so you learn which fix worked. Two trade-offs deserve a plain statement. First, higher error correction is not a cure-all: it buys tolerance for damage and logos, but it densifies the grid, so raising the level on an already-small code can make it worse. Second, a coloured or logo code that scans in your office is not proven: it is proven only when it scans first try, in the real light, at the real distance, on two different phones, on the real material.

Test before you print — every time

  1. Scan on two phones — one iPhone, one Android if you can — before printing.
  2. Test at the real distance and in the real light, on the real material.
  3. Check the preview, then the destination: a preview means the code decoded; an opening page means the destination works.
  4. Change one thing at a time when a test fails, so you know which fix actually fixed it.

Good to know

Why does my QR code scan on one phone but not another?

Then the code itself is usually fine — it is the camera, lighting, or angle on the failing phone. Wipe the lens, move to better light, hold the code so it fills about half the viewfinder, and try again.

Can a damaged QR code still work?

Often yes, thanks to error correction — at the High level, approximately 30% of codewords can be restored, as defined in ISO/IEC 18004. But damage to the three corner finder patterns or to the quiet zone is much harder to recover from, and heavy fading will kill a code even when its shape looks intact.

My QR code scans but the link does not work — is the code broken?

No, the code is doing its job. The destination is the problem: the page moved, the site is down, or a trial-based generator deactivated it. If the code is dynamic, sign in and redirect it; if it is static, restore the page or reprint.

How big should a printed QR code be?

As a rule of thumb, at least 2 x 2 cm, and at least one-tenth of the scanning distance: 5 cm for a table card scanned from 50 cm, 50 cm for a poster scanned from 5 metres. Denser codes holding long links or contact cards need to be larger at the same distance.

Why does my logo code fail when the plain version scans?

The logo covers part of the grid and consumes error-correction budget. Keep the logo under about 30% of the code area as a rule of thumb, print logo codes at 3 x 3 cm or larger, use error correction Q or H, and test the logo version itself — a plain code that scans proves nothing about its logo sibling.

How much blank space does a QR code need around it?

A quiet zone at least 4 modules wide on all four sides, as specified in ISO/IEC 18004. Keep text, rules, decorative borders, and nearby images out of it, and check all four sides — a margin generous on three sides and zero on the fourth still fails.

Can I fix a printed QR code without reprinting?

Only if the problem is the destination and the code is dynamic: sign in, change the destination, and the printed pattern works again. If the pattern itself is at fault — too small, low contrast, crowded margin, heavy logo, or soft print — the fix is a reprint with that parameter changed.
