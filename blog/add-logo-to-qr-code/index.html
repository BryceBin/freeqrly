Your logo, in the middle — still scannable

A logo makes a code yours. It also covers up part of the pattern. Here's how to have both: logo dead center, code still scanning on the first try.

October 28, 2026 · Last updated: November 3, 2026 · 4 min read

A logo in the middle of a QR code works when three things are true: the logo stays small, the code's error correction is set high, and nothing important is covered. In practice that means a square logo with a transparent background, centered, kept under about 30% of the code area as a ceiling — and smaller if you want a safety margin — printed dark on light, with a clear margin around the whole code. Do that, test the printed piece on two phones, and the code reads on the first try while still looking unmistakably like your brand.

That short version hides one honest tension, and this guide does not dodge it: 30% is a ceiling, not a target. The highest error-correction level can rebuild about 30% of the data, so a logo approaching that limit leaves almost nothing in reserve for a scuffed print, a dim room, or an older phone. Many design guides therefore advise keeping a centered logo around 20–25% of the code area, so wear and tear still has room to be absorbed. If your logo must be large, the rest of this guide shows what to trade away — shorter content, a bigger print, or a simpler mark — instead of hoping the ceiling will save you.

Why a logo can work at all: error correction

A QR code is not just a picture of your link. It is a grid of dark and light squares, called modules, plus redundant data woven through the grid so a reader can rebuild missing pieces. That redundancy is set by the error-correction level, defined in the QR code standard, ISO/IEC 18004:

LevelRecovers aboutUse it for
L (Low)7%Clean, screen-only codes with no logo
M (Medium)15%Plain printed codes; a good default
Q (Quartile)25%Print exposed to wear, dirt, or scuffing
H (High)30%Any code with a logo, or a rough surface

When you add a logo, the covered middle counts as damage, and the reader reconstructs it from the redundant data spread across the rest of the code. That is why the error-correction level matters more than the logo file itself: on level L or M, a logo eats most of your safety margin before the code ever reaches a printer, while on level H the same logo sits inside a much larger budget. FreeQrly raises error correction automatically when a logo is added, so you do not set the level by hand — but you still have to respect what it buys you. A higher level also adds modules, making the same content denser: a short address that fits in a 29 × 29 grid at level M needs 37 × 37 at level H, so each module gets smaller at the same print size. Keep the destination short, and print logo codes a little larger than plain ones.

Logo size: the ceiling, the safer zone, and the area-versus-width trap

Logo-size advice is easy to misread, because guides quote it two different ways. A logo spanning 30% of the code's width covers only about 9% of its area, while a logo covering 30% of the area spans about 55% of the width. When this guide says "under about 30% of the code area," it means area — the share of the whole square the logo hides — and that is the ceiling the FreeQrly generator uses. Treat anything near that ceiling as a code with no reserve left.

Logo share of code areaWhat it means in practice
Up to about 20%Comfortable. Room left for print variation, glare, and wear.
About 20–25%The range most design guides recommend as a practical maximum for branded codes.
Approaching 30%The ceiling. It can scan in clean conditions, but a scuff or dim light can finish it.
Over 30%Past what error correction can rebuild. Shrink the logo or shorten the content.

Two other placement rules are absolute, not matters of taste. First, the logo goes dead center. The center holds no positioning data, making it the safest place to cover, and centering keeps the mark away from the three large finder patterns in the corners — the squares a camera looks for first to find, orient, and straighten the code. Covering even one finder pattern can stop a scan entirely, no matter the error-correction level. Second, the logo must never touch the quiet zone, the blank margin around the code, which the standard sets at a minimum of four modules wide on every side. A logo edge bleeding into that margin can keep the camera from finding the code's edges at all.

If the logo must be big — a wide wordmark, a detailed crest — you have three honest levers. Shorten the destination, because less data means a roomier pattern with larger modules. Print the code bigger, because larger modules forgive more damage; the print size guide works through the sizes for cards, flyers, and posters. Or simplify the mark: use the compact symbol rather than the full lockup, and save the full version for the packaging around the code.

Preparing the logo file

The file you upload decides how clean the result looks at small sizes. A square PNG with a transparent background sits cleanest in the middle: no white box fighting the pattern, no wasted corners. A rectangular logo stretched into a square distorts the mark; crop a balanced, square version of your symbol instead of forcing the whole horizontal lockup into the center.

  • Simplify before you upload. Fine lettering and tiny details vanish when a mark is reduced to the center of a code. If your logo has a tagline, drop it from the code version.
  • Give the logo a white pad. A small light backing around the mark separates it from the surrounding modules so the camera does not read logo edges as code data.
  • Use the dark version of your mark. A pale logo on a light code confuses cameras. If your brand mark is light, place it on a contrasting white panel.

Color and contrast: the rules that matter more than the logo

A logo code fails on color far more often than on logo size. The rule never changes: dark modules on a light background, with strong contrast. Brand colors are welcome, but only if the dark side stays clearly dark and the light side stays clearly light. Practitioner guides commonly use a contrast ratio of 4.5:1 or higher as a starting point, and the plainer the pairing, the wider the range of phones and lighting it survives.

  • Gradients are a risk. The light end of a gradient often loses contrast, and phones expose colors differently. Check that its lightest part still reads as clearly light, and test the printed piece, not just the screen preview.
  • Inverted codes are a gamble. Light modules on a dark background are permitted by the standard and most current phone cameras read them, but some older scanner apps do not. Unless you can test on the devices your audience actually uses, keep the modules dark.
  • Never recolor the finder patterns into invisibility. You can style the three corner squares — rounded corners and dotted eyes usually scan fine — but filling in the light ring between the outer and inner square, or coloring the eyes lighter than the rest of the code, breaks what the camera searches for first.
  • Busy backgrounds are a second fight. A logo code on a photo forces the camera to separate background, logo, and pattern at once. Give the code a clean, light patch to sit on, with its quiet margin clear.

Shape, frames, and borders

Rounded modules and dot-style patterns are fine, because the grid itself stays regular. What breaks scanning is distortion of the grid: stretching a code so the squares stop being square, warping it to follow a design, or wrapping it around a tight curve such as a small bottle. Scale evenly, keep the code square, and if a curved surface is unavoidable, print larger and test on the actual object.

Frames and borders belong outside the quiet zone, never inside it. A rounded frame, a brand-colored border, or a "Scan me" caption can all work, provided they sit beyond the four-module margin and do not touch the pattern. The same applies to folds and seams on packaging: if a fold runs through the code or its margin, move the code to a flat panel.

Step by step

  1. Make the code. Any type works with a logo: a link, a vCard, a WiFi network, and every other type FreeQrly offers. Shorter destinations make roomier patterns.
  2. Upload a square PNG. Transparency works best. Keep the logo under about 30% of the code area as a ceiling, and nearer 20–25% for a safety margin.
  3. Let error correction adjust. It rises automatically when a logo is added, so the covered middle does not stop the scan. Check that the finder patterns and quiet zone are untouched before you export.
  4. Test-scan before printing. Two phones, one iPhone and one Android, on the print itself — not just the screen. If both read on the first try, ship it. If either hesitates, shrink the logo a notch, raise the contrast, or print larger, and test again.

For print, download PNG up to 2048 px, or SVG for a banner or trade-show wall. The print size guide covers the full sizing table, including why logo codes need a 3 × 3 cm minimum in print rather than the 2 × 2 cm plain codes can use.

How to test a logo code properly

Testing on your own new phone, in good light, on a screen, proves almost nothing. A printed logo code meets worse conditions: ink spread, laminate glare, dim rooms, and older cameras. A useful test method is deliberately unkind:

  • Test the printed piece, at final size, on the final material. A code that scans on screen can fail on gloss laminate or textured card, where glare and ink spread change the contrast.
  • Test two phones at minimum — one iPhone, one Android — and an older phone if you can borrow one. New flagships forgive a lot; the phone your customer owns may not.
  • Test from the real distance and angle, in the real lighting. A table card is scanned from a seat, under restaurant lighting; a poster from meters away, possibly through glass.
  • Test the destination, not just the decode. The code should open the right page and load quickly on mobile data.
  • Treat hesitation as failure. If a scan takes several seconds or needs multiple attempts, the code is marginal. Shrink the logo, raise the contrast, or print larger — then test again.

If a code still refuses to scan, the cause is usually one of the four original mistakes: a logo past the ceiling, low contrast, a crowded background, or a stretched grid. The troubleshooting guide walks through them, and the blurry-code guide covers resolution.

Where logo codes earn their keep

A logo code is worth the extra care wherever the code itself is part of the brand surface, not just a utility. On packaging, putting the mark inside the code makes the whole pack read as one design. On a business card, a logo code turns a forgettable square into a recognizable one, and the card is scanned at close range, where a logo code is most forgiving. At events, a logo code on a badge or poster is recognizable from across a room, which matters when ten exhibitors all have plain black squares. On menus, the logo reassures guests the code belongs to the restaurant.

Batch use is where consistency pays off. A product line with twenty variants should carry the same mark, the same colors, and the same quiet zone on every code — applied once across the batch rather than rebuilt per item. If the destination behind those codes ever needs to change, a dynamic code keeps the printed piece valid: its destination is editable after printing, and it carries scan statistics. Static codes, by contrast, need no sign-up, carry no watermark, and never expire — the right choice when the destination is fixed, such as a homepage or a product manual.

The honest comparison: logo code versus plain code

A plain code is more forgiving than a logo code in every dimension: it tolerates smaller print, lower contrast, denser data, and rougher surfaces, because no part of its pattern is deliberately hidden. A logo code trades some of that forgiveness for recognition. That trade is worth making when the code is a brand surface and the print is controlled — packaging, cards, posters, menus. It is a bad trade in four situations:

  • Tiny print. On a 2 cm code, a logo leaves very little pattern, and each module is already small. Either print larger or drop the logo.
  • Dense data. A long URL or a full vCard already makes a dense grid. Adding a logo on top is two squeezes at once — shorten the content first.
  • Harsh environments. Outdoor signage and workshop labels need their full error-correction budget for survival, not for decoration.
  • Uncontrolled reproduction. If a code will be photocopied, faxed, shrunk by a partner, or reprinted by someone else at a size you did not choose, a plain code survives the journey better.

There is also a brand-consistency argument against over-designing: one simplified mark, one color pairing, one quiet-zone rule, reused across the whole run, reads as a system. A different logo treatment on every code reads as noise, and noise is exactly what a scanner struggles with.

Brand consistency across a whole run

Decide the system once, then repeat it: the same simplified square mark, the same dark-on-light pairing even when the surrounding packaging changes color, the same quiet zone and minimum print size, on every surface. When a code appears on both a card and a poster, the poster version is not a stretched card version; it is the same code generated at the poster's size, with the same logo share. Generate many codes as a batch with the logo applied across all of them, then proof-scan one from each surface type before committing to the run. Good to know

Will my logo break the QR code?

Not if it stays under about 30% of the code area, which is the ceiling the generator uses, and nearer 20–25% if you want a safety margin. Error correction is raised automatically when a logo is added, so the covered middle does not stop the scan.

What logo file works best?

A square PNG with a transparent background. Rectangular logos and white-boxed logos waste space and fight the pattern. Simplify the mark first: fine lettering and taglines vanish at code-center size.

Can I use a logo with any QR code type?

Yes — link, vCard, WiFi, and every other type. The same logo can also be applied across a whole batch.

PNG or SVG for print?

PNG up to 2048 px for most print jobs, or SVG when you need it infinitely scalable, like a banner.

Why must the logo stay in the center?

The center holds no positioning data, so it is the safest place to cover, and centering keeps the mark away from the three finder patterns in the corners. Covering even one finder pattern can stop a scan entirely.

How big should a logo code be in print?

At least 3 × 3 cm, rather than the 2 × 2 cm a plain code can use, and larger if the code holds a lot of data or will be scanned in poor light. The print size guide has the full table.

How should I test a logo code before printing?

Scan the printed piece, at final size and on the final material, with at least two phones — one iPhone, one Android — from the real distance and in the real lighting. Treat hesitation as failure: shrink the logo, raise the contrast, or print larger, and test again.

When should I skip the logo?

On tiny print, on very dense codes, on surfaces that will be scuffed or weathered, or when the code will be reproduced at a size you did not choose. In those cases a plain code is more forgiving.
