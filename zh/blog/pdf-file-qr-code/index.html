实战笔记

PDF 二维码的好坏取决于它背后的文件

海报、菜单板、传单或产品插页上的二维码，一扫就能打开一份完整的 PDF：菜单、目录、价目表、手册或宣传册。扫码本身是最容易的部分。难的是背后的全部事情：文件住在哪里、有多大、在手机上能不能干净地打开，以及文件需要新价格、修正页或季节更新时怎么办。这四个决定做对了，码在整个印刷批次里都管用。做错了，你印出来的就是一条通向缓慢、损坏或过期文件的捷径。

先问这份 PDF 是干什么用的，因为这个答案几乎决定了其他所有事情。餐厅菜单需要打开快、在小屏幕上读得顺，并且菜品或价格变了就能跟着变。产品手册需要在产品的整个生命周期里保持准确，读者可能在购买几个月后还会回来翻它。价目表需要一个唯一可信的版本，这样才不会有人按上个季度的价格下单。会议传单可能只需要活一个周末，但它仍然需要打开时没有登录墙、没有让人困惑的下载步骤。生成码之前先把这个用途用一句话写下来，成品也要拿它来检验：这次扫码是不是今天、以及下次更新之后，都能快速地在手机上给读者正确的那份文件？

第一个实际选择是：把 PDF 本身编进码里，还是链接到托管的 PDF。二维码没法舒舒服服地装下整个 PDF 文件。码是为链接、联系记录这类短负载设计的，长负载会让图案变密、扫起来慢、在印刷尺寸下还很脆弱。所以标准做法是链接码：码里装一个短网址，这个网址打开 PDF。这也是码能维护的原因，因为只要用动态码，地址可以保持不变、背后的文件却可以换。静态码锁死的就是印上去的那个确切地址，所以文件一挪到新地址，所有印好的副本就全断了。动态码指向一个可以更新的目标，这就是一下午改好价目表和重印整批海报之间的区别。更广的对比见静态码与动态码对比，修改流程见打印后如何修改二维码。

PDF 托管在哪里

把 PDF 托管在你自己控制的稳定公开地址上，地址保持简短。自己的网站、专门的落地页，或者你自己管理的文件托管都可以，前提是链接不太可能挪动、过期，或者以后突然要求登录。避开依赖临时分享链接、权限会变的个人网盘文件夹，或者你控制不了的短链接服务的地址，因为其中任何一种都可能在毫无预警的情况下弄断印好的码。文件名要干净，放在自己域名下一个稳定的文件夹里，比如 documents 或 menus 文件夹，并且如果打算原地替换文件，公开地址里要避免空格、特殊字符和版本号。地址里带版本号，每次更新就被迫换一个新地址，这就违背了稳定码的初衷。

检查 PDF 是怎么打开的，而不只检查链接通不通。在大多数手机上，PDF 链接会在浏览器或查看器里打开，读者应该不用多余的下载步骤、登录提示或不安全文件警告就能看到第一页。在两大手机平台上都测一下，用移动网络测而别只用办公室 WiFi，并且从印好的码扫着测而别只从手输的地址测。如果托管方强制下载而不是预览，慢网络下的读者可能在文件下完之前就放弃了。如果托管方加了追踪、广告或插页，扫码体验会显得不那么可信，读者可能根本到不了文件。托管方是用户体验的一部分，而不只是一个存储选择。

只保留一份权威版本。当菜单、目录或价目表存在于好几个地方时，读者和员工很快就搞不清哪份才是最新版。在自己的记录里把文件名起清楚，替换文件时公开地址保持不变，并在 PDF 内部第一页或页脚注明生效日期，这样打印或转发它的读者能判断它是不是最新版。如果旧版必须保留，就给它一个不同的地址，并从新文件里链接过去，而不是让两个相互竞争的版本共用同一个码。尤其是菜单，一份短小聚焦、打开就是当前菜单的 PDF，比一份把菜单埋在好几页之后的大而泛的宣传册对读者更有用。

文件体积：先让它快，再让它好看

文件体积是 PDF 码最常让人失望的原因。用高分辨率照片、未压缩扫描件或完整印刷版式做的 PDF，很容易达到好几 MB，这在手机上很要紧。大文件下载更久、耗更多流量，在餐厅、大厅或商店的弱信号下还可能卡住。压缩正是为这种权衡而存在的：它在尽量保留视觉质量的同时减小文件，合适的设置取决于文件本身。以文字为主的文件通常压缩得很好、看不出损失，而以图片为主的文件则逼你在更小的文件和更清晰的照片之间选一个。Adobe 的移动端指南直接讲了这一点，提供高、中、低三档压缩，低压缩最能保留画质，高压缩文件最小、但画质要付出一些代价。

压缩之前，先从源头上把文件减下来。删掉读者不需要的页面，把照片裁到实际展示的尺寸，别把同一张大图重复嵌入多次。菜单如果是在手机屏幕上读，每页就不需要印刷分辨率的照片；价目表如果可以用真正的文字，也不需要扫描出来的页面图片。真正的文字除了体积小还有第二个好处：可以搜索、选中，还能被无障碍工具读取；而文字的扫描图片就不行，除非扫描件经过了文字识别处理。压缩完后，在手机上打开成品，检查最重要的几页，尤其是小字、价格和表格。如果某个价格、过敏原提示或脚注变得难读，说明压缩过头了，稍微大一点的文件反而是更好的选择。

给自己的团队定一条实际可行的体积纪律，哪怕不向读者公布具体数字。作为一条工作规则，目标是文件在移动网络下能迅速打开、在 WiFi 下感觉是秒开，并且要在真手机上测试，而不是只看文件大小来判断。有些邮件和上传服务有自己的限制，这正好提醒我们大文件到处都会制造摩擦：一份移动端压缩指南提到，Gmail 附件上限是 25 MB，而许多求职门户限制上传 5 MB，有些表单要求文件小于 2 MB。这些是其他服务的限制，不是你的 PDF 的规则，但它们说明了一点：一个发起来别扭的文件，从扫码打开时也同样别扭。如果压缩后 PDF 还是很大，就拆分：一份短菜单加一份单独的详细目录，互相链接，两者都比合在一起的文件打开得快。

文件类型尺寸纪律压缩后检查什么
菜单或价目表保持精简；优先用真正的文字而不是扫描图片价格、小字和表格在手机上仍然清晰可读
目录或宣传册先压缩图片；长目录可以考虑拆分照片仍然能清楚地展示产品
手册或指南保留完整文件，但删掉重复图片图表、警告和页码仍然清晰可读

不重印码也能替换文件

在动态码背后替换 PDF 是个小流程，但需要一份检查清单，不然容易悄悄出错。第一步，准备好新文件并在手机上检查，包括改了的页面和没改的页面。第二步，在同一个公开地址替换文件，或者把动态目标更新到新地址，并且在确认新地址无误之前保持旧地址可用。第三步，扫一份印好的码副本，而不只看屏幕预览，确认它打开的是新版本。第四步，检查文件里的生效日期，以及任何提到旧版的印刷内容，比如页脚写着价格适用到某一天。最后，告诉负责发放或展示码的人，比如前台员工，文件已经变了，这样就没人会继续把读者引向旧文件的缓存副本或印刷副本。

缓存要当心。读者手机或浏览器里可能在你替换文件后还留着旧版 PDF 一段时间，员工手机也一样。这很正常，但这意味着你的测试应该包括清缓存后重新扫一次，或者用一部从没打开过旧文件的手机扫一次。如果你换文件很频繁，比如每周菜单，可以考虑把生效日期用大字写在第一页，这样看到缓存副本的读者能一眼认出它是旧的。如果改动很紧急，比如价格更正或安全提示，别只依赖码：同时更新重复了同样信息的印刷品、招牌或员工话术，并和最可能据此行动的人确认更正。

动态码能修的东西是有限的。它能改目标，但修不好一个从来没为手机设计过的 PDF、一个在弱信号下打不开的大文件，或者把关键信息埋在第 12 页的文件。它也修不好损坏的托管、过期的分享链接，或者把读者锁在外面的权限变更。这些都是托管和文件本身的问题，得从源头解决。一个好习惯是按文件变化的频率定期重扫印好的 PDF 码：经常变的菜单每周一次，价目表每月一次，会议传单每次活动前一次。印的时候能用的码不保证永远能用，而一次简短的定期检查，比从顾客那里发现码坏了要便宜得多。

按会打开它的那部手机来设计 PDF

为印刷做的 PDF 在手机上不一定好读。宽表格、小脚注和密集的多栏版式会逼着读者捏合、放大、横向滑动，扫完码却是这种体验很糟糕。如果 PDF 主要是在手机上读，字号就放宽，表格就收窄，最重要的信息放最前面。菜单应该先上菜品和价格，而不是历史介绍页。价目表应该先上现行价格和生效日期。手册应该先上安全提示和快速上手步骤，详细的参考资料放后面。一份短小、手机友好的 PDF，被扫、被读、被照着做的次数，会比一份长而印刷完美、却没人读完的 PDF 多得多。

码本身要保持可扫，因为 PDF 码经常和其他信息印在一起。码背后用短链接，这样图案稀疏、模块大；静区保持干净；按扫码距离印到合适的尺寸，遵循打印尺寸指南。如果码印在菜单板、海报或传单上，加一句标注说明扫码会打开什么，比如“扫码查看完整菜单（PDF）”或“扫码查看价目表”。读者知道结果时更愿意扫；如果他们预期会打开 PDF，打开时也不太会觉得被打扰。如果 PDF 很长，可以考虑先链接到一个简短的落地页，写明文件名称、日期和大小，并放一个清晰的打开 PDF 按钮，而不是毫无预警地打开一个大文件。

最后，提前规划文件的生命周期终点。菜单随季节变，价目表会过期，活动传单在活动结束后就没用了。提前决定文件不再是最新版时码应该做什么：指向新版本，指向一个说明文件已被替换的页面，或者撤下印刷品。留着一个打开过期价目表或往期活动手册的码，比没有码更糟，因为它会教会读者你的码不可信。一个 PDF 码要配得上它的位置，就得保持最新、打开迅速，并且给读者恰恰是他们期待的那份文件，而且是在手里这部手机上真正能读的形式。

阶段检查如果失败
印刷前在移动网络下，用两部手机扫印刷样张缩短链接、压缩文件，或者放大码
替换文件时扫一份印好的副本，确认新版本和日期修好地址、做清缓存测试，并通知员工
按固定周期重扫会变的文件的码更新目标或撤下印刷品

小提示

二维码里能装下整个 PDF 文件吗？

实际操作中不行。二维码是为链接这类短负载设计的，长负载会让图案变密、在印刷尺寸下难扫。改用打开托管 PDF 的链接码。

PDF 应该用静态码还是动态码？

任何可能变的文件都用动态码。动态目标不用重印就能更新，而静态码锁死的就是印上去的那个确切地址，所以文件一挪位置，所有印好的副本就全断了。

PDF 应该托管在哪里？

放在你自己控制的稳定公开地址上，比如自己的网站，文件名干净、没有登录要求。避开临时分享链接或权限可能变的个人文件夹，因为这两种情况都可能在毫无预警的情况下弄断印好的码。

PDF 应该多大？

在不损害可读性的前提下尽量小。先压缩图片，删掉不需要的页面，优先用真正的文字而不是扫描图片，并在移动网络下的手机上测试结果。如果价格或小字变得难读，说明压缩过头了。

不重印怎么换掉 PDF？

在手机上准备并检查新文件，在同一个公开地址替换它或更新动态目标，然后扫一份印好的副本确认新版本和日期。告诉员工文件已经变了，并且用一部没有缓存旧文件的手机测试。

为什么扫码打开 PDF 这么慢？

常见原因有文件大、图片多的页面、托管方慢，或者移动信号弱。压缩文件、减小图片尺寸、拆分长文件，并且用移动网络测试而别只用办公室 WiFi。

扫码应该直接打开 PDF，还是先到落地页？

文件短、标注也说明了是 PDF 时，就直接打开 PDF。文件大、读者下载前需要知道日期和背景，或者你想用一页提供几份相关文件时，就先到一个简短的落地页。

PDF 过期了会怎么样？

把动态码指向新版本，或者指向一个说明文件已被替换的页面，并撤下仍指向旧版的印刷品。留着过期的价目表或活动手册不撤，会教会读者不要相信你的码。
