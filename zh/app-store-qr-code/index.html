一个静态码只装一个链接

这一点大多数应用商店的二维码页面都跳过，所以我们直说：二维码存的是文本，而这段文本是一个 URL。一个码，一个目的地。图案里没有逻辑，没法看手机型号再挑商店。

你的 iOS 和安卓上架页是两个不同的 URL。一个静态码只能指向其中一个。把 App Store 链接写进码里，安卓用户就会落到一个他们装不了的页面；反过来一样糟。

覆盖双平台有三种做法，下表做个对比。

方案原理要印几个码链接变了还能用吗需要准备
两个码并排一个 App Store，一个 Play2不能，要重印无需
一个码指向路由页页面识别设备，跳转到对应商店1可以，前提是页面是动态的一个你自己控制的页面

两个码是最诚实、也最省事的做法。路由页是大多数 App 有了营销站之后的常见方案。Smart Banner 只对先落到你网站的人才有效，那和印出来的码是两件事。

怎么拿到商店链接

两个商店都会给你一个干净、永久的 URL，知道去哪找就很容易。

iOS：在 App Store Connect 打开你的 App，进“App 信息”，复制 App Store URL。它长这样 apps.apple.com/app/id1234567890。你可以加国家代码——apps.apple.com/gb/app/id…——让码打开指定地区的商店；但默认版本会按访客所在地区跳转，通常这才是你要的。

安卓：在 Play Console 打开商品页，从地址栏复制链接。它长这样 play.google.com/store/apps/details?id=com.yourcompany.yourapp。id 是你的包名，即使 App 改名也不会变。

ID 之后的东西都删掉。营销工具常会加跟踪参数，比如 ?mt=8 或 &referrer=…。它们没有害处，但会让二维码图案变密，一点好处都没有——而图案越密，小尺寸越难印清楚。

做一个能用的路由页

选一个码的话，它得有个去处。路由页是你自己域名下的一张小页面，读 User-Agent 然后跳转。

逻辑很短：浏览器报 iPhone 或 iPad，去 App Store；报 Android，去 Play；其余情况两个按钮都显示。给桌面端留个兜底，因为相当一部分扫码来自在电脑上测试的人。

实际使用中有两种东西会让这类页面失灵。Apple 的应用内浏览器和部分社交 App 会把 User-Agent 削成通用值，识别就猜错了。另外，在页面渲染完成前就触发的跳转，看起来像坏链接。两个按钮都显示、把识别到的那个高亮，比直接跳转更友好。

如果想让目标以后可改，就用动态码指向路由页。改页面，所有印出去的码跟着变，不用重印。

小提示

Can one static code open both stores?

No. A static code stores a single URL, and your two store listings are two URLs. Encode the App Store link and Android visitors land on an app they cannot install. Print two labelled codes, or point one code at a page on your own domain that reads the phone and forwards to the right store.

What if I fill in both fields?

Only the App Store link is encoded — the Play field is used when the App Store field is empty. To cover both platforms, make two codes, one per field.

只有一个平台怎么办？

Fill that field and print one code. Nothing else is needed.

能自动识别手机并跳转吗？

Not on its own — a printed pattern cannot run logic. Device detection needs a page in between: host a small router page, then point a dynamic code at it so you can change the destination later without reprinting.

能统计安装量吗？

No. Static codes carry only the link and never phone home. App Store Connect and the Play Console already report installs.
