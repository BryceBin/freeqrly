Como criar um QR code dinâmico

Um QR code dinâmico permite mudar o destino depois de imprimir — e ver quantas pessoas escanearam. Veja como fazer um, de graça, em cerca de um minuto.

16 de outubro de 2026 · Última atualização: 3 de novembro de 2026 · 14 min de leitura

Sim — dá para criar um QR code dinâmico de graça, em cerca de um minuto, e mudar para onde ele aponta depois de impresso. Escolha o dinâmico quando o destino ainda não está fechado, quando você quer contar os escaneamentos ou quando um mesmo código impresso precisa levar a uma página nova no mês que vem. Escolha o estático quando o destino nunca vai mudar: um link fixo, uma senha de WiFi ou um cartão de visita não precisa de conta nem de redirecionamento. Este guia cobre o processo no FreeQrly, o mecanismo de redirecionamento em linguagem simples e os limites gratuitos logo de cara.

No FreeQrly, os códigos dinâmicos são gratuitos. Entre com e-mail e senha, Google ou GitHub, e você recebe 20 códigos dinâmicos na conta gratuita, atualmente ilimitados durante a promoção por tempo limitado. Não há período de teste nem cartão exigido para começar, e os escaneamentos são ilimitados. Você pode editar um código depois de imprimir, ver as estatísticas de escaneamento, gerar códigos em lote na forma estática e usar a API.

Dinâmico ou estático? Decida antes de imprimir

Essa decisão não tem volta para um código que já foi impresso. Um código estático carrega o destino dentro do próprio padrão, então nunca dá para redirecioná-lo. Um código dinâmico carrega um link curto que redireciona para o destino, então o destino pode ser trocado depois. Um código estático impresso com o link errado exige reimpressão; um código dinâmico impresso só precisa de uma edição no Painel.

Como um código dinâmico funciona na prática

Um código dinâmico não guarda o seu link diretamente. Ele guarda um link curto do FreeQrly, no formato freeqrly.com/q/XXXXXXX, e o padrão codifica esse link curto. Quando alguém escaneia o código, o celular abre o link curto, o servidor do FreeQrly consulta o destino que você definiu no momento, e quem escaneou é redirecionado para lá. Quem escaneia acaba na sua página; o link curto é só a junção no meio do caminho.

Essa junção explica cada recurso e cada limite:

  • Editar funciona porque o padrão nunca muda. O padrão guarda só o link curto. Editar muda o registro por trás dele, então toda cópia impressa passa a servir o novo destino no próximo escaneamento.
  • Contar funciona porque todo escaneamento passa pela junção. O servidor vê o escaneamento a caminho do destino e o soma às estatísticas. Um código estático nunca toca um servidor, então não há nada para contar.
  • É preciso ter conta porque a junção tem que pertencer a alguém. Só a conta que criou o código pode mudar para onde o link curto dele aponta. Sem um dono, qualquer pessoa poderia redirecionar o código impresso de outra pessoa.
  • Excluir é definitivo porque a junção é removida. Exclua um código e o link curto dele para de redirecionar, então as cópias impressas param de funcionar. Não há como desfazer, e a vaga liberada pode ser usada por um código novo.

Quem escaneia não vê nada disso — aponta, toca na prévia e cai na sua página. Uma coisa que dá para notar é um redirecionamento que mostra um anúncio ou uma página com a marca do fornecedor antes: por isso, ao comparar geradores, escaneie um código de exemplo e observe o que aparece antes do seu destino carregar.

Passo a passo: criar um QR code dinâmico

  1. Entre — grátis. Abra a página de login e crie uma conta com e-mail e senha, Google ou GitHub. Códigos estáticos nunca precisam disso; os dinâmicos, sim, porque o código precisa pertencer a alguém que só ele possa editar.
  2. Mude para Dinâmico. No estúdio, vire a chave de Estático para Dinâmico. Tipos, estilo e download funcionam exatamente do mesmo jeito.
  3. Escolha um tipo e preencha. Site, WiFi, contato, evento — os 17 tipos de conteúdo funcionam como códigos dinâmicos. (Lote continua estático: um código dinâmico por geração, porque cada um precisa do próprio link curto e do próprio registro no Painel.)
  4. Estilize se quiser. Pontos, cores, logo, moldura — a prévia atualiza ao vivo, e o estilo fica salvo com o código, então a miniatura do Painel e o download combinam. Mantenha o contraste forte e nunca cubra os três quadrados grandes de localização nos cantos.
  5. Gerar. Clique em Gerar. Você recebe um link curto como freeqrly.com/q/XXXXXXX — é isso que o padrão codifica. Dê ao arquivo baixado um nome que indique onde o código vai ficar, por exemplo cafe-window-menu.png.
  6. Gerencie depois. Seus códigos ficam no Painel: edite, confira as estatísticas ou exclua um para liberar uma vaga. Teste o código impresso com a câmera do seu celular antes de uma tiragem completa, e de novo depois de qualquer edição.

Escolhendo o tipo

O tipo decide o que quem escaneia vê e faz. Um código de Site abre uma página. Um código de WiFi oferece entrar numa rede. Um código de contato oferece salvar uma pessoa. Um código de evento oferece salvar uma data. O tipo certo elimina uma etapa, e isso geralmente vale mais do que um design mais esperto. Um restaurante deve usar um código de Site apontando para a página do cardápio, e não um código de texto com o cardápio dentro: a página pode ser atualizada, o código de texto, não. Um código de WiFi para visitantes deve ser um código de WiFi, porque o celular consegue entrar na rede a partir do próprio escaneamento — veja como compartilhar WiFi com um QR code.

Aponte para uma página que você controla, e não para um arquivo hospedado num lugar que você não controla: um arquivo apagado deixa um código funcionando que aponta para o nada. E note que um texto longo deixa o padrão mais denso, o que exige um tamanho de impressão maior para escanear à mesma distância; veja o guia de tamanho de impressão de QR code.

Estilizar sem quebrar o escaneamento

Códigos dinâmicos aceitam o mesmo estilo que os estáticos: formatos de ponto, cores, um logo no centro e uma moldura com texto. Três regras mantêm um código estilizado escaneável. Primeira: mantenha o contraste alto e o fundo claro; os leitores enxergam módulos escuros sobre módulos claros. Segunda: mantenha o logo discreto e centralizado, e nunca cubra um quadrado de localização. A correção de erros reconstrói os módulos escondidos atrás de um logo central pequeno — no nível Alto da ISO/IEC 18004, cerca de 30% das palavras-código podem ser restauradas — mas esse orçamento cobre todos os danos somados, incluindo desgaste de impressão e sujeira, e não só o logo. Terceira: preserve a zona de silêncio: a margem em branco ao redor do código, com pelo menos 4 módulos de largura nos quatro lados segundo a ISO/IEC 18004, faz parte do código, não é decoração. Mais sobre logos em como adicionar um logo ao QR code.

Para impressão, teste uma prova real impressa, e não só a prévia na tela: uma cópia no tamanho pretendido, no material pretendido, escaneada em dois celulares diferentes — um iPhone e um Android, se possível — na iluminação onde o código de fato vai ser usado. Laminação brilhante sob luz forte e um código enrolado numa garrafa falham de jeitos que uma prévia na tela nunca mostra. Se a prova escanear devagar, imprima maior; tamanho é a correção mais barata que existe.

Lendo as estatísticas com honestidade

Todo código dinâmico informa ao seu Painel: total de escaneamentos, escaneamentos de hoje, escaneamentos únicos e um gráfico de sete dias, com detalhamento por país, cidade, dispositivo e sistema operacional. O guia completo está em o que as estatísticas de QR code dinâmico realmente dizem. Três hábitos são os mais importantes. Compare os códigos entre si, e não com um padrão imaginário: um código de vitrine e um código de caixa de entrega vivem em mundos diferentes. Trate o zero como dado: um código sem nenhum escaneamento por uma semana geralmente significa que o local está errado, que falta um chamado para ação ou que o código é pequeno demais. E dê contexto a um pico: uma enxurrada de escaneamentos logo depois que um post sai no ar é o post, não o cartaz.

As estatísticas do FreeQrly são só agregados — contagens por dia, país, cidade, dispositivo e sistema operacional — sem nenhum registro por visitante e sem como identificar quem escaneou. Um escaneamento único é contado com um hash de mão única, e não com um nome ou um endereço.

Situações em que o dinâmico se paga

Um cardápio de restaurante que muda com a estação

Imprima um código nos porta-cardápios de mesa e aponte para a página do cardápio. Quando a estação mudar, atualize a página ou redirecione o código — os porta-cardápios ficam. Veja QR codes para restaurantes.

Um cartaz de evento impresso antes de os detalhes estarem fechados

Cartazes vão para a gráfica semanas antes de o local, o link de ingressos ou a programação estarem fechados. Um código dinâmico permite que o cartaz saia apontando para uma página provisória, depois mude para a página de ingressos quando as vendas abrirem, e para uma página de retrospectiva depois do evento. Veja QR codes para eventos.

Um produto ou embalagem que sobrevive à primeira campanha

A embalagem é impressa em volume e vendida por meses ou anos. Um código dinâmico na embalagem pode começar numa oferta de lançamento, passar para uma página de manual ou garantia, e mais tarde para um produto sucessor — sem reimpressão. Mantenha uma lista de onde cada código está: um código que você não encontra no Painel é um código que você não consegue corrigir.

Um código por local, ou os números mentem

Dê a cada local o seu próprio código. Compartilhar um código entre um folheto, um cartão de visita e uma banca de feira mistura as estatísticas num único número que não explica nada. Um código junto ao caixa que abre uma página de avaliação funciona do mesmo jeito; veja como conseguir avaliações no Google com um QR code.

A resposta deve ser uma frase para cada caso, na página de preços.

Uma dependência merece ser dita com clareza. Um código dinâmico depende do serviço de redirecionamento do fornecedor enquanto estiver circulando — aqui também é assim. Se esse serviço acabasse, os códigos dinâmicos parariam de redirecionar, enquanto os códigos estáticos, que guardam o destino no padrão, continuariam funcionando. É por isso que o estático é o certo para qualquer coisa que precise funcionar por décadas sem ninguém cuidando, como uma placa permanente. O dinâmico é para material vivo que alguém ainda acompanha; o estático é para material que precisa se virar sozinho.

Erros que desperdiçam uma tiragem

  • Imprimir estático quando o link não estava fechado. Se o destino pode mudar, o código deveria ter sido dinâmico antes de imprimir; um código estático impresso não se salva com uma edição.
  • Compartilhar um código dinâmico entre vários locais. Um código, um local, um registro de estatísticas — senão os números não dizem qual local funcionou.
  • Excluir um código para “organizar”. Excluir é definitivo e as cópias impressas param na hora. Redirecione um código que está se aposentando para uma página de encerramento primeiro, e exclua só quando não restar nenhuma cópia impressa em circulação.
  • Pular a prova impressa. Uma prévia na tela prova o design; só uma prova impressa no tamanho, material e luz reais prova o escaneamento. Veja por que o seu QR code não está funcionando.
  • Esquecer o chamado para ação. Um código pelado faz quem escaneia adivinhar. Uma moldura dizendo o que a pessoa ganha — cardápio, ingressos, WiFi, desconto — transforma uma decoração numa porta de entrada.
