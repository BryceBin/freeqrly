Por que meu QR code está embaçado?

Um QR code embaçado quase sempre é um problema de resolução: poucos pixels esticados em espaço demais. A correção é exportar maior — ou em SVG.

17 de outubro de 2026 · Última atualização: 3 de novembro de 2026 · 15 min de leitura

Um QR code borrado quase sempre é um problema de resolução: poucos pixels demais esticados por espaço demais. A correção é exportar maior — ou em SVG. Se o código parecia nítido na tela e virou uma papa no papel, a imagem não tinha pixels suficientes para o tamanho em que foi impressa. Um QR code é uma grade de quadradinhos chamados módulos; quando não há pixels suficientes, as bordas deles se misturam, os celulares não encontram a grade, e os escaneamentos falham. Comece pela exportação, e não por um design novo: gere de novo em resolução maior ou como arquivo vetorial, reimprima uma cópia no tamanho real, e escaneie na distância real de leitura antes de imprimir o lote.

Essa resposta cobre a maioria dos casos, mas o borrão tem mais de uma causa, cada uma com uma correção diferente: uma exportação pequena, compressão JPEG, distorção, impressora ou papel, ou uma cópia de uma cópia. As seções abaixo separam essas causas, trazem uma tabela de números para a gráfica, passam pela correção em ordem, e cobrem códigos que parecem nítidos e mesmo assim não escaneiam — esses pertencem ao por que o seu QR code não escaneia.

O que o borrão de fato faz com um código

A câmera de um celular não lê um QR code como uma pessoa lê uma foto. Ela procura os três padrões grandes de localização nos cantos, deduz a grade a partir deles, e então decide, módulo por módulo, se cada quadradinho é escuro ou claro. O borrão ataca exatamente essa decisão: quando módulos vizinhos sangram um para dentro do outro, a câmera vê cinza onde precisava de preto ou branco, e começa a adivinhar. Um pouco de adivinhação é suportável, porque os QR codes carregam correção de erros embutida — dados extras que permitem ao leitor reconstruir palavras-código que voltam erradas ou ilegíveis. Essa proteção é medida em palavras-código, e não em área visível: os quatro níveis da ISO/IEC 18004 restauram aproximadamente 7% das palavras-código no nível L, 15% no M, 25% no Q e 30% no H. Uma mancha sobre um padrão de localização, ou um borrão espalhado pelo símbolo inteiro, pode derrotar um leitor muito antes de qualquer porcentagem arrumada sugerir que ele deveria sobreviver. Trate a correção de erros como uma rede de segurança, nunca como permissão para imprimir um código suave.

A densidade piora o borrão. Um link curto produz uma grade espaçosa com módulos grandes; um link longo, um cartão de contato completo ou um código de Wi-Fi com senha longa produz uma grade mais densa com módulos menores, e módulos menores borram antes. É por isso que a mesma exportação pode parecer boa para uma URL curta e falhar para um código carregado de dados no mesmo tamanho de impressão. Se um código é ao mesmo tempo denso e impresso pequeno, encurte o destino onde der, imprima maior, ou os dois. Um código dinâmico ajuda de outro jeito: o padrão impresso codifica um link curto que você pode redirecionar depois, então a grade continua espaçosa mesmo que o destino final seja longo. Para um destino que nunca vai mudar, um código estático é mais simples: gratuito, sem conta, sem marca d'água, e não expira.

Os números: tamanho de impressão, pixels e formato

As gráficas falam de resolução em pontos ou pixels por polegada. Para impressos vistos de perto, 300 pixels por polegada no tamanho final de impressão é a base profissional amplamente usada para uma saída nítida. A tabela abaixo transforma essa base em contagens de pixels: largura de impressão em polegadas multiplicada por 300. Um código de 2 cm tem cerca de 0,8 polegada de largura, então precisa de cerca de 240 pixels a 300 pixels por polegada — e isso é o mínimo absoluto, não uma margem confortável. Exporte sempre maior do que o mínimo e deixe o designer reduzir, porque reduzir preserva a nitidez enquanto ampliar só aumenta o borrão.

Duas regras práticas sustentam essa tabela. Primeira: o tamanho de impressão em centímetros, multiplicado por cerca de 100, dá um alvo rápido de pixels — um código de 5 cm quer cerca de 500 pixels no mínimo, um código de 10 cm cerca de 1.000. Segunda: a regra prática da proporção 1:10 do guia de tamanho de impressão: a largura do código deve ser pelo menos um décimo da distância de escaneamento, então um código escaneado a 50 cm deve ter pelo menos 5 cm de largura, e um cartaz escaneado a 5 metros precisa de um código de 50 cm. Um código de cartaz visto a metros de distância tolera uma resolução efetiva menor do que um cartão segurado na mão, mas ainda precisa de pixels suficientes para o seu tamanho — e só um arquivo vetorial dá isso sem teto.

As 5 causas comuns, em detalhe

1. Exportação em baixa resolução

Essa é a causa mais comum, e a mais generosa de corrigir. Um PNG de 512 px parece bom com 2 cm de largura; ampliado para um cartaz de 20 cm, cada módulo vira uma mancha, porque os mesmos 512 pixels agora cobrem dez vezes a área. A tela esconde o problema — o monitor mostra o código pequeno, então os pixels parecem justos — enquanto o papel mostra no tamanho real. A correção está na fonte: exporte de novo a 1024 px para cartões e folhetos, 2048 px para cartazes, ou SVG sempre que a gráfica aceitar. Ampliar o arquivo pequeno num editor não adiciona detalhe; só deixa o borrão existente maior. Se a exportação original sumiu, gere de novo a partir do mesmo destino em vez de esticar o arquivo que você tem.

2. Compressão JPEG

O JPEG foi feito para fotografias, e funciona descartando detalhes que o olho tem menos chance de notar numa foto. Essa troca é ruim para um QR code, que não é nada além de bordas nítidas e áreas planas — exatamente os recursos que o JPEG borra. Um código salvo como JPEG de baixa qualidade pode falhar mesmo em tamanhos pequenos, e o dano piora cada vez que o arquivo é salvo de novo como JPEG. O PNG usa compressão sem perda, preservando cada pixel exatamente, e o SVG não tem pixels para perder. A regra é simples: só PNG ou SVG. Se um designer, app de chat ou plataforma social devolver uma versão JPEG, trate como prévia, não como arte final, e troque pela PNG ou SVG original antes de imprimir.

3. Distorção

Arrastar um canto distorce a grade: quadrados viram retângulos, o espaçamento dos módulos muda de forma desigual, e os leitores desistem. Isso acontece mais em apresentações de slides, processadores de texto e ferramentas de diagramação, onde uma imagem é arrastada para preencher um espaço. Redimensione sempre proporcionalmente — segure Shift, ou use o ícone de cadeado, para largura e altura mudarem juntas e os quadrados continuarem quadrados. Um código distorcido e depois distorcido de volta não fica quadrado automaticamente, porque o arredondamento na ferramenta de layout pode deixá-lo levemente torto. Na dúvida, apague a imagem colocada e coloque uma exportação nova no tamanho pretendido.

4. Impressão ruim: impressora, tinta e papel

Impressoras de baixa resolução, sangramento de tinta em papel áspero ou absorvente, e reflexo de brilho, tudo suaviza as bordas. Uma impressora a jato de tinta num papel não revestido e absorvente deixa a tinta se espalhar pelas fibras, então os vãos brancos finos entre os módulos se fecham e o código parece pesado e lamacento. Uma impressora a laser num papel liso ou revestido segura as bordas muito melhor, e é por isso que papel fosco e impressora a laser vencem um jato de tinta num guardanapo. Laminação brilhante é diferente: o papel pode continuar nítido e mesmo assim devolver reflexos para a câmera — incline o impresso sob a luz para distinguir reflexo de borrão. Para tecido, bordado, gravação ou superfícies muito ásperas, espere que as bordas suavizem de qualquer jeito, e compense com um código maior, correção de erros mais alta e um teste físico antes.

5. Cópia de uma cópia

Tirar print de um código a partir de uma mensagem, e depois print desse print, perde resolução a cada vez. Apps de mensagem também recomprimem e reduzem as imagens, então um código encaminhado pelo chat pode chegar muito menor e mais suave do que a exportação original. Fotografar um código impresso para reutilizá-lo acrescenta distorção de perspectiva, luz desigual e suavidade de lente por cima da impressão original. Volte sempre à exportação original, ou gere de novo a partir do mesmo destino. Se o destino é um código dinâmico, gere um código novo para o mesmo link curto — nenhum arquivo antigo é necessário.

Como corrigir, passo a passo

  1. Ache o arquivo original. Se você só tem um JPEG, um print ou uma imagem encaminhada de chat, pare e gere de novo — nenhuma edição restaura detalhes que a compressão já jogou fora.
  2. Exporte no tamanho certo. PNG a 1024 px para cartões e folhetos, 2048 px para cartazes, SVG sempre que a gráfica ou o designer aceitar. Acima de cerca de 20 cm, o SVG é o único formato que mantém as bordas exatas sem um arquivo enorme.
  3. Use PNG ou SVG, nunca JPEG. PNG para telas e impressão de escritório, SVG para impressão profissional. Se uma ferramenta insistir em JPEG, use a configuração de qualidade mais alta dela só para uma prévia na tela, nunca como matriz de impressão.
  4. Mantenha as proporções ao redimensionar. Segure Shift ou o ícone de cadeado para os quadrados continuarem quadrados. Coloque a imagem no tamanho final, em vez de colocá-la pequena e esticá-la depois.
  5. Mantenha o código escuro sobre claro, com margem clara. Borrão e baixo contraste se somam: um código cinza sobre fundo pálido que também está suave falha antes do que qualquer uma das falhas sozinha. Mantenha uma margem em branco de pelo menos 4 módulos de largura em todos os lados, conforme especificado na ISO/IEC 18004, e mantenha texto, logos e bordas decorativas fora dela.
  6. Combine papel e impressora com o trabalho. Papel liso ou revestido e impressora a laser para códigos pequenos; acabamento fosco onde o reflexo é um risco; tamanho maior e correção de erros mais alta para superfícies ásperas ou texturizadas.
  7. Escaneie a impressão real para testar. Imprima uma cópia no tamanho final, afaste-se até a distância real de leitura, e escaneie na iluminação real. Um escaneamento de primeira significa que o lote está seguro. Se hesitar, corrija a exportação ou o tamanho agora — uma tiragem de códigos suaves não se salva depois.

Cenários: onde o borrão morde com mais força

Folhetos, cardápios e porta-cardápios de mesa

Eles são escaneados à distância do braço, muitas vezes em salas escuras, então precisam de nitidez e tamanho: pelo menos 3 cm num folheto ou cardápio, 4–5 cm num porta-cardápio de mesa como regra prática. Cardápios acrescentam o risco da laminação: brilho sob luzes de teto pode refletir, enquanto laminação fosca mantém o código legível e limpa fácil. Para um cardápio que muda, aponte para uma página que você controla em vez de um print, para a impressão nunca ficar defasada — e um código dinâmico permite mudar esse destino depois de imprimir, com estatísticas de escaneamento mostrando quais mesas de fato escaneiam.

Cartazes e sinalização

Cartazes falham de outro jeito: a exportação geralmente é o problema, não a impressora. Um arquivo de 512 px que parecia bom na tela fica visivelmente suave a 20 cm ou 50 cm, e nenhuma impressora consegue inventar os pixels faltantes. Use SVG, aplique a regra prática da proporção 1:10, e faça a prova do painel do código em tamanho real antes da tiragem. Ao ar livre, leve o desbotamento em conta também: um código que começa nítido mas desbota no sol caminha para a falha ao longo de semanas, então um nível de correção de erros mais alto e uma posição abrigada importam mais do que uma primeira impressão marginalmente mais nítida.

Embalagens e etiquetas

Etiquetas pequenas combinam tamanho pequeno, dados densos e superfícies curvas ou texturizadas. Mantenha o código com 2 cm ou mais como regra prática, evite enrolá-lo numa curva fechada onde os módulos das bordas esticam, e teste no recipiente real — um código que escaneia plano pode falhar numa garrafa. Se o material é áspero ou a impressão é grosseira, imprima maior e mais simples: um link curto mantém a grade espaçosa, incluindo um link curto por trás de um código dinâmico.

Comparação honesta: o que corrige o borrão, e o que não corrige

Nem todo truque de nitidez funciona, e alguns conselhos populares desperdiçam uma tiragem. Ampliar um arquivo pequeno — num editor, com uma ferramenta de ampliação, ou exportando a mesma imagem pequena maior — não adiciona detalhe; interpola entre os pixels que você já tem, então as bordas continuam suaves, só maiores. Um filtro de nitidez pode deixar as bordas mais nítidas ao olho enquanto acrescenta halos que confundem uma câmera, então um código filtrado pode escanear pior. Converter um JPEG para PNG também não desfaz o dano do JPEG: o formato muda, mas os pixels borrados continuam borrados. A única correção confiável é uma exportação nova a partir dos dados originais em resolução maior, ou em SVG.

A escolha de formato tem seus próprios prós e contras. O SVG é a melhor escolha para impressão, mas algumas ferramentas de escritório, apps mais antigos e plataformas sociais não o aceitam — nesses casos, um PNG em alta resolução é a saída certa, e não um motivo para voltar ao JPEG. O PDF pode ser um bom veículo para impressão porque pode conter o código vetorial, mas só se o código dentro do PDF for de fato vetorial; um PDF com um JPEG pequeno colado dentro é só um JPEG com uma embalagem mais bonita, então confira o que está dentro antes de confiar na extensão do arquivo.

Por fim, nitidez é necessária, mas não suficiente. Um código perfeitamente nítido ainda pode falhar se for pequeno demais para a distância, se o contraste for fraco, se a zona de silêncio estiver lotada, se um logo cobrir demais o centro, ou se o próprio destino estiver morto. Essas são perguntas de diagnóstico, cobertas em ordem no guia completo de solução de problemas. Se a sua reimpressão está nítida e mesmo assim não escaneia, siga o guia de solução de problemas antes de reimprimir de novo — uma segunda reimpressão só ajuda se mudar aquilo que de fato está errado.

Bom saber

Por que meu QR code parece embaçado, mas ainda escaneia?

Os celulares são generosos — a correção de erros reconstrói palavras-código que voltam erradas ou ilegíveis. Mas um código que escaneia num escritório claro pode falhar com pouca luz ou à distância do braço. Nítido é seguro; mal escaneando, não.

De qual resolução preciso para um pôster?

O SVG é a melhor escolha, porque escala sem limite. Se a gráfica precisa de um arquivo raster, use PNG a 2048 px; um cartaz a 20 cm precisa de cerca de 2.360 px a 300 pixels por polegada, então uma exportação de 512 px vai parecer suave nesse tamanho.

PNG ou SVG para impressão?

SVG sempre que a gráfica ou o designer aceitar — ele escala infinitamente com zero borrão. PNG a 1024 px para cartões e folhetos, ou 2048 px para cartazes, é a saída para impressão de escritório e apps que não aceitam SVG.

Dá para corrigir um código impresso embaçado sem reimprimir?

Não. O borrão está grudado na imagem impressa. Reimprima a partir de uma exportação em resolução maior (ou SVG). Editar um código dinâmico não ajuda — o padrão no papel é o que é, mesmo que um código dinâmico permita mudar o destino por trás de uma impressão nova.

Por que a mesma exportação parece boa na tela, mas suave na impressão?

Uma tela mostra o código pequeno, então os pixels dele parecem justos. O papel mostra o código no tamanho real, então a mesma contagem de pixels espalhada por centímetros revela o borrão. Confira a exportação com o tamanho de impressão antes de mandar para a gráfica.

Ampliar ou um filtro de nitidez corrige um código borrado?

Não. Ampliar interpola entre os pixels que você já tem, então as bordas continuam suaves, só maiores. Um filtro de nitidez pode adicionar halos que confundem uma câmera, e converter um JPEG para PNG não desfaz o dano do JPEG. A única correção confiável é uma exportação nova a partir dos dados originais em resolução maior, ou em SVG.
